# Graphs sharing a pair of Things run as parallel lines

Status: accepted
Refines: 0087
Related: 0045, 0086

Where more than one Edge joins the same two Things — from different Graphs, in either direction — each is drawn in its own **lane**: the path a lone Edge would take, moved sideways whole. Both anchors move by one vector along the side of the Thing they sit on, and the curve between them is React Flow's `getBezierPath` over the moved anchors. Because React Flow places its control points relative to the anchors, the result is an exact translate: a straight Edge's lanes are straight lines beside it, and a curved Edge's lanes are the same curve beside it. Lanes are 8 flow units apart.

**The Active Graph's Edges are centred and connect.** It runs from the middle of one anchor to the middle of the other, exactly where a lone Edge would. A Graph holds at most one Edge in each direction between two Things, so where the Active Graph holds both A → B and B → A they split the centre: each runs half a spacing either side of it, the one whose source sorts first above or left, and both connect. The Active Graph's Edges are therefore always centred on the anchors. Every other Graph's Edge takes a lane below it — to its right where the Things are stacked, whichever way the Edge travels — one spacing further out for each, starting one spacing past the outermost of the Active Graph's, and leaves a fifth of its length undrawn at each end. The trim cuts the curve a connecting Edge would draw rather than moving its ends, so the line keeps its shape and a level line stays level, and it is measured along the curve so both ends lose the same length. It is cut in the geometry rather than with `stroke-dasharray`, because React Flow draws an animated Edge with a dash pattern and animates its offset, which would slide a dashed trim along the line. Only the connecting Edge carries an arrowhead: the Edge object's `markerEnd` is set for it alone, which is React Flow's documented path (`url('#…')` handed to the custom Edge and forwarded to `BaseEdge`). The Active Graph is the one that connects; the others are a reading of which Graphs also join the pair. A Graph that is not active stops short even where it is alone in its pair, so the rule reads the same everywhere on the canvas. While no Graph is active nothing stops short, and the first Edge of a pair keeps the centre.

ADR 0087 accepted the opposite as its cost: four Graph-independent anchors put every Graph between one pair on the same curve, with colour and emphasis left to separate them. It deferred separating them as "a decision to take … with the overview in front of you". This is that decision, taken looking at a Diagram overview where two Graphs' Edges between one pair lay on the same line and read as one striped line. `.scratch/multiple-routes/findings.md` bounds how many Graphs colour can separate at about four. Lanes do not raise that bound. They stop coincidence from making two Graphs unreadable well below it.

**Lanes are parallel, not fanned.** ADR 0087 named the alternative as "fanning parallel Edges by curvature" — keeping the anchors and bowing each curve's middle. That was tried first here and rejected on sight: it turns a straight Edge into curves that trace different paths and meet at the ends, which reads as different connections rather than one connection carried by several Graphs. Do not reintroduce a per-lane curvature.

**The lane is decided in the projection, not in the Edge.** Only the projection sees every Edge that shares a pair, so `projectGraphEdges` asks `graphLanes` — given the Edges and the Active Graph — for each Edge's lane offset and whether it connects, and sets a `laneOffset` and an `endTrim` on `RoutedEdgeData` from them: the Active Graph's Edges centred, then the rest in the Space's Graph order. Activating a different Graph therefore moves the lanes — the newly active one to the centre. The offset's sign is the screen's rather than the Edge's, so an Edge and its reverse stack on the same side. `RoutedEdge` reads the offset and moves the anchors it resolves from where the Things are now (ADR 0087), so a drag carries lanes with their Things.

**The Active Graph is painted last.** React Flow draws Edges in the order it is given them, so the projection puts the Active Graph's Edges at the end and its stroke is the one on top wherever it crosses another Graph's Edge. The other Graphs keep receding by opacity (`OTHER_GRAPH_OPACITY`), static, at a narrower stroke.

What this does not touch: nothing is stored, the four anchors and their facing rule are unchanged, and the authoring gesture is unchanged. The additions to the Edge's data are two numbers computed at projection.
