# A commit outcome is named once on both sides of the seam

Status: accepted
Related: 0034, 0057, 0093

What a store decides about a commit — `committed`, `conflict`, `aggregate-refused` — is one type, `CommitOutcome`, declared once in `@project/persistence` and shared by both seams. The stored seam's `RepositoryCommitResult` is that outcome plus `rejected`, the store's refusal of a request it will not judge; the browser's `CommitResult` is that same outcome plus the transport failures only a client can suffer. Neither restates an arm of the other. The status code each outcome crosses HTTP as is written once too, beside the codecs that encode and decode it, and the Fetch application and the browser transport both read that one table.

The three types had been written out separately. `CommitResult` restated the committed, conflict and aggregate-refused arms of `RepositoryCommitResult` word for word, the Hono route mapped the store's arms to status codes in one direction and the browser's transport mapped status codes back in the other, and nothing tied the two tables together. The cost was not the repetition. The route matched three arms with `if` statements and answered everything else as a 400 asking the author to correct their request, so a fourth outcome — one nobody would think to route — would have been served as a malformed request, with whatever prose it carried, and typechecked. An outcome added to the domain is now a compile error at both ends instead: the table is exhaustive over the outcome kinds, and the route matches them in a switch that must return.

The route still pairs each body with its status itself, and the table holds the statuses rather than the encoders. That is Hono's constraint, not a preference: the typed client's per-status response bodies are inferred from the literal types at each `context.json(body, status)` call, so a body and a status arriving there as two separately-typed values collapse every commit response into one union whatever the code that produced them knew.

The identity rule a commit is refused by — no Space named twice, no change disagreeing with its own snapshot about which Space it is — belongs to the commit decision ADR 0095 concentrated, and to nothing else. The wire codec had its own copy, running first over HTTP and answering with the same prose, so the repository's copy never ran there and no test held the two to saying the same thing. The codec now decodes shape only — an object, known fields, a non-empty change set, a UUID, a canonical revision — and the store judges what the request means. So a repository is trusted for the rule every repository already runs and the contract suite already holds all of them to, and the Fetch application no longer knows a rule about commits that it cannot enforce for the store it was handed.

Rejected: deriving one type from the other with `Exclude`, which reads as one seam minus a case rather than as two seams sharing a vocabulary, and leaves the shared arms with no name to be discussed under. Moving the browser's failure classification — timeouts, rate limits, an unreachable host — into the shared table, which no server code has an opinion on and which belongs to the transport that suffers it. Keeping the codec's identity copy and adding a test that the two agree, which pays a test to protect a duplicate with no reason to exist.
