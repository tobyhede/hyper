# A card is a markdown file with frontmatter, and the directory is the inventory

Status: accepted
Refines: 0010
Refined by: 0030, 0051

A card is **one file**: YAML frontmatter carrying `id`, `title`, `description`, `kind` and `target`, and a markdown body carrying the content. Cards exist because their files exist, so the space file holds no `cards` array — it keeps `version`, `id`, `title`, `routes`, `layouts` and `defaultView`, which is structure and nothing else.

What this replaces was never decided, which is why it survived nineteen ADRs without being examined. A card's metadata sat in `space.json` and its body in `cards/<name>.md`, and the result had the costs of two files with the benefits of neither. Neither artifact was complete: a card file was an orphan body that could not tell you what card it was, and the space file knew every card's name and no card's content. Adding one card meant editing two things. Reviewing a change to one card meant reading two diffs.

The clearest evidence that the split was wrong is the rule it forced on authors: **a card body must not begin with a heading**, because the heading would repeat the title held in the other file and render twice on every surface. That rule made the project's markdown not quite markdown, and it needed an e2e test to police it. Under this decision the hazard does not exist — the title is in the same file as the body, so a heading is simply a heading, and both the rule and its test go.

**Discovery is by directory, and identity is not.** Two locations are scanned, non-recursively: `*.md` beside the space file, and `cards/*.md`. A minimal space is therefore one directory holding `space.json` and `intro.md`, and organising into `cards/` is available without being required. Non-recursion is deliberate: ADR 0001's nested spaces will want subdirectories, and a recursive scan would make every one of them ambiguous with card discovery. A card's identity comes from its frontmatter and never from its path — matching filename to card is a convention worth following and not a rule, so renaming a file is not an identity change. A duplicate id across the two locations is a load error, because letting one silently win would make the file you are editing depend on scan order. Default order is by title, since array order is read only by automatic strategies and nothing else.

**`loadSpace` gains an argument, not a capability.** It takes the space file *and* the raw card files, and parses the frontmatter itself — so ADR 0010's promise that one call "parses, validates references, and indexes" stays literally true rather than becoming true in two places. Purity is untouched, because purity here is about I/O and not arity: bytes in, `Space` out, no filesystem, still synchronous, still property-testable. Reading the bytes stays outside, where it already is.

We rejected **inline content in the space file**, which fixes "two files" by making the one remaining file bad to author — markdown inside JSON strings diffs badly and edits worse, and the file-first premise is that authored content is editable in a text editor. We rejected **listing card files in the space file**, which would fix a card being split across two files while preserving the part that actually hurts: adding a card would still touch two. We rejected **deriving a card's id from its filename**, which makes renaming a file a data migration and puts identity in the one place the author is least deliberate about. And we rejected **a directory per kind**, which puts a domain distinction into the filesystem, where moving a file would silently change what a card is.

The costs accepted. `graph` gains a frontmatter dependency, its first beyond zod, because hand-rolling the `---`/YAML/`---` split means hand-rolling YAML. The card set becomes implicit: every `.md` in scope is a card, so there is nowhere to leave a draft, and a convention for that can be carved out later only by adding a rule. Deleting a card file breaks any route referencing it — loudly, at intake, which is the behaviour to want, but it is a sharper edge than editing an array. Migration touches the schema, intake, the plugin, both space files and every test that builds a space. And **a card cannot yet be written**: the save endpoint persists one fixed path by design, so a space the app mints has a card no file describes, and it cannot survive a reload until the writer grows to persist card files — deliberately a separate step, so this change can be verified on reads alone.
