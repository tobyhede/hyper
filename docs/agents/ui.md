# UI Foundation

shadcn, Base UI, Lucide, and the Escape/commit and focus conventions that follow from them. Read before touching `packages/ui` or a `CardPane`/menu/combobox surface in `packages/app`.

- **A shadcn component is the default, and a hand-roll is a deviation (ADR 0047).** Two rules, and the second is the one that was missing. First, **the component**: where shadcn ships one for a surface this app needs, build on it and the headless primitive it composes rather than writing our own. Second, **its behaviour**: start from that component's documented keyboard, focus, dismissal and accessibility defaults and shape Hyper's feature around them rather than recreating or overriding them. Both carry the same bar — every deviation needs an explicit product requirement and an interrogated, recorded reason — and **"our case is special" is not a reason until it has been tested against the primitive**. That last clause is what `CardPane` failed: 175 lines reimplementing a dialog primitive's focus trap, initial focus, `aria-modal` and pointer containment, justified by "React Flow keeps its nodes in the tab order, so `inert` is not available" — true about the platform, and irrelevant to a primitive that traps with its own focus scope and never wanted `inert`. It is now some fifty lines over a real Dialog. The primitive layer is one whole-repo decision, not a per-component preference, and **ADR 0050 has taken it: Base UI**, whose bullet below carries what that means in practice. The corollary is live: a written contract that contradicts a primitive's default loses unless the deviation clears the bar, which is how issue `16` resolved.
- **Base UI and Lucide are the UI foundation (ADR 0050) — built.** ADR 0050 took the whole-repo choice ADR 0047 left open, and the migration landed it across `90231e0`..`e6978c7`, ticket by ticket, with a report per migrated component in `.scratch/base-ui-migration/`. Both shadcn workspaces declare `base-nova`, a `neutral` base and CSS-variable theming; `Button`, `Select`, `Popover`, `Dialog` and the `Menu` behind `AddCardControl` are `@base-ui/react` `1.7.0`; every facade in `packages/ui/src/icons.tsx` is a Lucide glyph and none is a local SVG; and **no authored module imports `@radix-ui/*`**. Hyper's palette and spatial presentation are preserved — the custom classes were replayed onto the Base variants, and the registry style stays a component-generation baseline rather than a product restyle. Lucide stays the default vocabulary: keep a custom `@project/ui` icon only when no Lucide glyph communicates a genuinely Hyper-specific concept, and take that exception by naming the missing meaning, never a preferred silhouette. **`cmdk` behind `Command` is deliberately not migrated** — it is a search primitive, not a Radix wrapper, and it carries `@radix-ui/react-dialog` and friends transitively, so a lockfile grep for `@radix-ui` still answers and that answer is cmdk's. `packages/ui/package.json` no longer declares `@radix-ui/react-dropdown-menu`, `react-popover` or `react-select` — the three were removed with the lockfile regenerated once the last importer went, which is `.scratch/base-ui-migration/issues/08`'s dependency item. **08's own status line reads done, with one honest remainder**: its whole-project migration report is written (`.scratch/base-ui-migration/08-whole-project-migration-report.md`), but that report's own "Baseline comparison and manual QA" section records that the human pass against the pre-migration baseline it asks for has not actually been run — the per-component reports 02–07 plus 08 are the record everything else rests on. No workspace importer names `@radix-ui/*` at all now, so a lockfile hit is transitive and cmdk's. Four migration decisions are load-bearing and a sweep would undo them: **`PopoverAnchor` is inert on purpose** — Base UI has no Anchor part, so a non-trigger anchor is a ref handed to `PopoverContent`'s `anchor` and forwarded to `Positioner` (the Edge toolbar is the one caller), and that export is a bridge for old imports rather than a component; positioning props belong to `Positioner` and popup props to `Popup`, and a `side` left on the popup does nothing at all; **`nokey` stays on every portalled popup and on any chrome control outside the canvas** — the withdrawn Select trigger carried it, and the Sidebar's content and footer carry it now — because React Flow subscribes its delete key on `document` and neither a portalled surface nor a control beside the canvas sits inside the canvas's own guard; **Base UI spells the controlled empty state `null`**, which is what the View, Layout and Graph selectors passed and why each ignored the `null` from `onValueChange` — Hyper has no clear-selection action, and the three selectors themselves are gone under ADR 0053 (see the Sidebar bullet below); and **`CardPane` declines both of Dialog's focus hooks** (`initialFocus={false}`, `finalFocus={false}`) so the product's declared starting field and App's post-close restore win, while the primitive keeps the trap, Escape and `disablePointerDismissal`.
- **Escape and commit are decided by the surface, not by the field (ADR 0048, refined by ADR 0051).** Card Front commits its title on blur and Escape reverts it. Card Editor panes pend every field: **`Done`** commits the whole Edit, while Cancel and Escape discard it. `CardSearchCombobox` may dismiss its open list on the first Escape; once closed, the pane owns Escape and cancels the draft. A selection only updates the pending Target, so it must not commit or remount an opened Alias. `CardPane` remains the shared Base UI modal and declines Dialog's focus hooks so the product's declared initial field and post-close restoration win.
- **The workspace's command surface is a Sidebar, and the canvas takes one choice (ADR 0053) — built.** `WorkspaceSidebar` in `app` composes the shared `Sidebar` family over shadcn's registry component: the Space title in the header, Add Card, one exclusive canvas renderer selected from two labelled `SidebarMenu` groups for the computed Views and authored Layouts, the Graphs list, and Present plus the persistence cue in the footer. The canvas header inside `AppShell`'s `SidebarInset` carries the trigger and `SelectedCanvasRenderer` — the name of what is drawing and whether it is computed or authored — and nothing else. `SelectedCanvasRenderer` takes the **row** naming the current renderer — one prop, `renderer`, and a caller gets that row from `currentRenderer(renderers, id)` — and never a bare title and kind: handed those two, a caller can derive what is drawing off the resolved renderer instead, which is the second path `canvas-renderers.ts` exists to remove. **Name the renderer, not the control that presents it (ADR 0055, refining 0053)** — the identity is `CanvasRendererId` and the aggregate of every row the canvas can draw is `CanvasRenderers`; the three names that came before each said which surface was asking, so every new presentation invited a fourth. The sidebar's own per-group list component is `RendererGroup` for the same reason: it draws one group, and reusing the aggregate's name for it would put one identifier back over two things. **What can draw and what is drawing are two answers from one module, and the aggregate carries no field for the second** — `canvasRenderers(space)` is `computed` and `authored` and nothing else, and `currentRenderer(renderers, id)` names the row, throwing the shared `layoutNotFound` — the constructor `resolveRenderer` raises the same refusal from, so the two cannot word it differently — when the id is a Layout the Space no longer holds. Making the current id an input to the total list is the coupling that split removed, so don't reach for a `selected` on the aggregate: there is none, and a second derivation of the pressed row is the defect `canvas-renderers.ts` exists to remove. `ViewSelector`, `LayoutSelector`, `GraphSelector` and `SelectorTrigger` are **deleted** with their tests, and with them the two `None` values that only ever meant "the other control is the one drawing"; don't restore either, and don't add a second control for the canvas renderer. `Select` itself stays as an ADR 0050 foundation primitive with its own test and **no current consumer** — retiring a primitive that ADR names is a foundation decision, not a surface one. Four facts the migration paid for, each found by something breaking: **the Sidebar's desktop container is `fixed … z-10`**, so every portalled surface needs a stacking level above it — `DropdownMenuContent`'s positioner now carries `z-50` as `Popover` and `AlertDialog` already did, and without it the Add Card menu opened *behind* the sidebar and Playwright's click landed on a group label; **`nokey` belongs on `SidebarContent` and `SidebarFooter`** rather than on the root, because React Flow's delete key listens on `document` and excludes a target only by tag or by a `.nokey` ancestor, and the mobile `Sheet` portals those same regions out of the root — without it, Delete with focus on a canvas renderer row deleted the selected Edge, which `edge-authoring-react.test.tsx` now pins; **an open `CardPane` marks the app root `inert`**, so a test asking about the covered sidebar must locate it by `data-renderer` rather than by role, since the accessibility tree no longer holds it; and **jsdom declares `window.matchMedia` and leaves it `undefined`**, so `vitest.setup.ts` stubs it by reading the value rather than asking `in` — `useIsMobile` calls it on every render of the shell. One deliberate departure from the accepted working design: the canvas rows carry **no tooltip**. `collapsible="offcanvas"` has no icon-only state for a tooltip to label, and a `side="right"` tooltip opens over the canvas — chrome covering the work it describes. **Below the 768px breakpoint the whole surface is a modal Sheet drawn over the canvas, and every command in it dismisses that sheet before it runs** — Add Card, Add Alias, canvas renderer selection, Graph activation and Present/Overview all go through `WorkspaceSidebar`'s `onCanvas` wrapper, which calls `setOpenMobile(false)` when `useSidebar()` reports mobile. Two of those are correctness rather than manners: Add Card and Add Alias open an editor *on the canvas*, and a Dialog's focus trap will not let it take focus while the sheet is up, so the flow cannot be completed at all. The persistence control is deliberately **not** wrapped: its result is a dialog stacked over the sheet, not the canvas. `mobile-sidebar.spec.ts` is the only place the Sheet branch is exercised, and it needed the e2e `page` fixture fixed first — that fixture built its context from `baseURL` alone and dropped Playwright's resolved `contextOptions`, so `test.use({ viewport })` was silently served a desktop. Two deviations from the registry drop went with it: **`Sidebar` forwards the caller's props and className to `SheetContent` rather than to the `Sheet` root**, because the root renders no DOM and was swallowing the surface's `nokey`, test id and classes below the breakpoint; and its props are `Omit<…, 'ref'>`, since a `ComponentProps<'div'>` ref is a legacy type Base UI's popup will not take.
- **A menu that opens a surface is `modal={false}` and declines focus return for that close.** Otherwise its popup can reclaim focus after the Alias pane opens. On the way back, the disabled Add Card control cannot receive focus until the render that re-enables it, so restoration happens from that effect. In tests, remember that Base UI dispatches a `PointerEvent` for keyboard-activated menu items while jsdom does not provide that subclass.
- **Styling is split:** `ui` uses Tailwind v4 + shadcn-style primitives; the graph/card CSS stays hand-rolled in `packages/app/src/styles.css`. Tailwind scans `app` + `ui/src` via `@source` in `tailwind.css`.
- **Card markdown is sanitised before it is injected.** `CardContent` renders through `dangerouslySetInnerHTML`, and `marked` has had no `sanitize` option since v5, so `DOMPurify.sanitize()` sits between them. Don't remove it on the argument that a card came from a local import: backend implementations and future import sources broaden that premise. `packages/ui/test/CardContent.test.tsx` fails without the sanitiser.
