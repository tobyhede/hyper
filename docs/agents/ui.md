# UI Foundation

UI components and operational feedback built on shadcn, Base UI and Lucide, including the Escape/commit and focus conventions that follow from them. Read before touching `packages/ui` or a pane, menu, combobox or feedback surface in `packages/app`.

- **ADR 0070 removes the existing-Alias metadata editor.** An Open Alias stays on the canvas, keeps its own Title, and renders its immutable Target's Markdown read-only through `CanvasCard`. `CardSearchCombobox` remains the Target picker for Alias creation only. References below to `OpenCard`, `card-editor.css`, Alias retargeting or an existing-Alias metadata pane describe the superseded surface and are retained only as history until this long-form baseline is rewritten.

- **A shadcn component is the default, and a hand-roll is a deviation (ADR 0047).** Two rules, and the second is the one that was missing. First, **the component**: where shadcn ships one for a surface this app needs, build on it and the headless primitive it composes rather than writing our own. Second, **its behaviour**: start from that component's documented keyboard, focus, dismissal and accessibility defaults and shape Hyper's feature around them rather than recreating or overriding them. Both carry the same bar — every deviation needs an explicit product requirement and an interrogated, recorded reason — and **"our case is special" is not a reason until it has been tested against the primitive**. That last clause is what `CardPane` failed: 175 lines reimplementing a dialog primitive's focus trap, initial focus, `aria-modal` and pointer containment, justified by "React Flow keeps its nodes in the tab order, so `inert` is not available" — true about the platform, and irrelevant to a primitive that traps with its own focus scope and never wanted `inert`. It is now some fifty lines over a real Dialog. The primitive layer is one whole-repo decision, not a per-component preference, and **ADR 0050 has taken it: Base UI**, whose bullet below carries what that means in practice. The corollary is live: a written contract that contradicts a primitive's default loses unless the deviation clears the bar, which is how issue `16` resolved.
- **Base UI and Lucide are the UI foundation (ADR 0050) — built.** ADR 0050 took the whole-repo choice ADR 0047 left open, and the migration landed it across `90231e0`..`e6978c7`, ticket by ticket, with a report per migrated component in `.scratch/base-ui-migration/`. Both shadcn workspaces declare `base-nova`, a `neutral` base and CSS-variable theming; `Button`, `Select`, `Popover`, `Dialog` and the `Menu` behind `AddCardControl` are `@base-ui/react` `1.7.0`; every facade in `packages/ui/src/icons.tsx` is a Lucide glyph and none is a local SVG; and **no authored module imports `@radix-ui/*`**. Hyper's palette and spatial presentation are preserved — the custom classes were replayed onto the Base variants, and the registry style stays a component-generation baseline rather than a product restyle. Lucide stays the default vocabulary: keep a custom `@project/ui` icon only when no Lucide glyph communicates a genuinely Hyper-specific concept, and take that exception by naming the missing meaning, never a preferred silhouette. **`cmdk` behind `Command` is deliberately not migrated** — it is a search primitive, not a Radix wrapper, and it carries `@radix-ui/react-dialog` and friends transitively, so a lockfile grep for `@radix-ui` still answers and that answer is cmdk's. `packages/ui/package.json` no longer declares `@radix-ui/react-dropdown-menu`, `react-popover` or `react-select` — the three were removed with the lockfile regenerated once the last importer went, which is `.scratch/base-ui-migration/issues/08`'s dependency item. **08's own status line reads done, with one honest remainder**: its whole-project migration report is written (`.scratch/base-ui-migration/08-whole-project-migration-report.md`), but that report's own "Baseline comparison and manual QA" section records that the human pass against the pre-migration baseline it asks for has not actually been run — the per-component reports 02–07 plus 08 are the record everything else rests on. No workspace importer names `@radix-ui/*` at all now, so a lockfile hit is transitive and cmdk's. Four migration decisions are load-bearing and a sweep would undo them: **`PopoverAnchor` is inert on purpose** — Base UI has no Anchor part, so a non-trigger anchor is a ref handed to `PopoverContent`'s `anchor` and forwarded to `Positioner` (`SelectedEdgeControls` is the one caller), and that export is a bridge for old imports rather than a component; positioning props belong to `Positioner` and popup props to `Popup`, and a `side` left on the popup does nothing at all; **`nokey` stays on every portalled popup and on any chrome control outside the canvas** — the withdrawn Select trigger carried it, and the Sidebar's content and footer carry it now — because React Flow subscribes its delete key on `document` and neither a portalled surface nor a control beside the canvas sits inside the canvas's own guard; **Base UI spells the controlled empty state `null`**, which is what the View, Layout and Graph selectors passed and why each ignored the `null` from `onValueChange` — Hyper has no clear-selection action, and the three selectors themselves are gone under ADR 0053 (see the Sidebar bullet below); and **`CardPane` declines both of Dialog's focus hooks** (`initialFocus={false}`, `finalFocus={false}`) so the product's declared starting field and App's post-close restore win, while the primitive keeps the trap, Escape and `disablePointerDismissal`.
- **`Kbd`/`KbdGroup` are shadcn's keyboard-key primitive**, generated into `packages/ui/src/components/kbd.tsx` from the `base-nova` registry and exported from `@project/ui`. Hyper deliberately extends the registry drop with `keyName="modifier"`: the modifier label must resolve to Command on Apple platforms and Ctrl elsewhere without each consumer duplicating that policy. Preserve that extension when refreshing the registry component. Its consumers are the presenting chrome's keyboard guidance and the Expanded Markdown Card's shortcut hint. Use it wherever a surface names a key rather than hand-rolling a `<kbd>` — and note it is presentation only: the control that *performs* a shortcut still announces it with `aria-keyshortcuts`, as `AddCardControl` does.
- **Escape and commit are decided by the surface, not by the field (ADR 0048, refined by ADR 0051).** Card Front commits its **title** on blur and Escape reverts it; its Expanded Markdown **body** does not (ADR 0064) — `Mod-Enter`, `Escape` and the rail's Save and Cancel are the only exits, because a document is not a refusable line (see `MarkdownCardBody`). Card Editor panes pend every field: **`Done`** commits the whole Edit, while Cancel and Escape discard it. `CardSearchCombobox` may dismiss its open list on the first Escape; once closed, the pane owns Escape and cancels the draft. A selection only updates the pending Target, so it must not commit or remount an opened Alias. `CardPane` remains the shared Base UI modal and declines Dialog's focus hooks so the product's declared initial field and post-close restoration win.
- **Expected errors keep their owner (ADR 0057) — built through Authoring, UI and HTTP.** Application composition exhaustively maps structured Authoring refusals to the surface conducting the interaction: correctable Card Editor input uses `FieldError` on Title or Target and preserves the draft. An accepted Edit closes immediately; retryable persistence failure, permanent rejection and conflict remain the Space's existing `Alert`/`AlertDialog` states rather than reappearing inside that editor. HTTP transports stable Problem Details identities and the adapter translates them once into persistence outcomes; UI code does not branch on wire prose or wire shapes. A stable Ladle story exercises a production-reachable refusal rather than injecting display prose through a callback to manufacture one — where a refusal is genuinely unreachable through a browser gesture, the story is handed the **structured** refusal and the claim declares its `applicationEvidence` exemption. The Edge surfaces follow the same rule: Edge Authoring retains an `EdgeRefusal` naming one of three channels (endpoint editing with the attempted endpoint, deletion, and the canvas announcement a finished pointer gesture leaves behind), and `SelectedEdgeControls` maps its two channels to a Field or a form channel per render. The refusal cascade is cached in `docs/agents/authoring-refusal-cascade.md`; wire rules live in `docs/agents/http.md`.
- **Operational feedback is one deep module.** Use `StatusFailure` for a blocking startup, render or placement failure and `StatusBusy` for an in-progress operational state; compose a product-specific component around them so production and Ladle mount the same surface. `StatusFailure` owns the destructive announced `Alert` and the named, keyboard-focusable diagnostic region. Set `boundedDetail` where the panel shares a viewport with chrome, and leave it unset where the page owns the viewport and can scroll; choose the surface width through `panelClassName`. `StatusBusy` owns one labelled `role="status"`; its Spinner is decorative and must not create a second live region. These panels are distinct from `FieldError` for correctable input and from `AlertDialog` for a decision or recovery action.
- **The Space command surface is a Sidebar, and the canvas takes one Layout choice (ADR 0053/0079).** `SpaceSidebar` lists authored Layouts in one exclusive group, then the selected Layout owned Graphs. It takes the Space's `layouts` and the `selected` Layout as domain values, and a row is the selected one when its Layout id matches. `SelectedLayoutName` names that Layout in the canvas header, taking the Layout itself. Add Layout remains available and creates an empty Layout. The former selector controls stay deleted; do not add a second canvas selector. Mobile commands dismiss the Sidebar sheet before acting, while persistence dialogs remain layered over it. `Select` has a consumer again: the Layout and Graph an Open Space Card selects, and the target on the Space Card creation pane (`entity-url-addressability/07`). Both call sites carry `nokey` on the portalled popup themselves rather than the wrapper carrying it — React Flow subscribes its delete key on `document`, and a Select drawn anywhere but over a canvas needs no marker.
- **A menu that opens a surface is `modal={false}` and declines focus return for that close.** Otherwise its popup can reclaim focus after the Alias pane opens. On the way back, the disabled Add Card control cannot receive focus until the render that re-enables it, so restoration happens from that effect. In tests, remember that Base UI dispatches a `PointerEvent` for keyboard-activated menu items while jsdom does not provide that subclass.
- **Creating a Card from a pane is one state machine, `card-creation.ts`.** Both creation panes — Alias and Space Card — share one instance, and the kind rides on the choices it is offering, so two panes at once is unrepresentable and `creatingCard` is `pane.status !== 'closed'`. Three arms: `closed`, `choosing` and `submitting`; `submitting` is an arm rather than a flag beside `choosing`, which is what stops a busy flag outliving the pane it disables. The kinds differ in two seams — `readChoices` and `submit`, both sync-or-async — and in the component `App` picks off `choices.kind`; and the pane goes busy only for a `submit` that actually answers a promise, so an Alias's synchronous Edit never flickers through disabled controls. **A reducer, not an observable-state module.** `edge-authoring.ts` is a store because React Flow asks it synchronous questions mid-gesture, because its operations answer values to their callers, and because it invalidates itself from two collaborator subscriptions; none of that is true here, so the transitions are a pure function driven by `packages/app/test/card-creation-state.test.ts` with no React tree, `createCardCreation` is the asynchronous shell over it, and `useCardCreation` is `useReducer` plus one memo. Nothing is added to `compose-app.ts`: the seams are memoized by `App` and passed to the hook. **Refusals are presented at the seam.** `submit` answers an already-presented `CardCreationRefusalErrors` rather than a raw refusal, so the module holds one refusal type instead of being generic over `AuthoringRefusal` and `SpaceCardRefusal`; `authoring-refusal.ts` stays the only place a creation's prose is written, including `presentCardCreationBreak` for a rejected coordination. A refused attempt and a failed listing are held apart on the state, because a keystroke ends the first and nothing typed ends the second. **`continuation` names where an Edit continues** — `{ target, select, then }` — declared on this state under `architecture-review/19`'s vocabulary so that ticket lifts it into `continuation.ts` by a rename rather than a redesign; it replaces the `restoringAddCardFocus` ref and its effect, and `App` spends it on a render with no pane over the target. The word is deliberately **not** in `CONTEXT.md`: it names a surface's state machine rather than anything in the authored world, the same reason *projection* is absent there.
- **Styling is split:** `ui` uses Tailwind v4 + shadcn-style primitives, and so does any production module that owns its own semantic presentation — `GraphHud` in `react-flow-adapter` is one. Tailwind scans `app`, `ui/src` **and `react-flow-adapter/src`** via `@source` in `tailwind.css` — the third was added with the HUD's utilities, without which they are purged. What stays hand-rolled in `packages/app/src/styles.css` is what is React Flow's: node and card sizing, handle visibility, the one `.rf-card-node--active :is(.card, .canvas-card)` rule naming the actively presented Card, and the portal layers a Card's and an Edge's controls are placed in (`.edge-control-layer` is placement and pointer-events only; `SelectedEdgeControls` owns how those controls look). **Every block that file declares is now recorded with its reason** — see the inventory bullet below — so what is actually in there is a list rather than a claim. One order in it is load-bearing: `CardContent`'s own `.card--full` rules sit *above* the `.rf-card-node__content` container-query block, because `.card--full .card__title` and `.rf-card-node__content .card__title` have equal specificity and only source order separates them. With the base rules last, a presented Card's title took a fixed `1.3rem` instead of scaling with the frame, against ADR 0027; `presenting.spec.ts` now pins the computed `13px`. **The canvas Card runs the other way**: its own CSS is hand-rolled and lives with its component, in `packages/ui/src/canvas-card.css` beside `CanvasCard.tsx` — kind treatment, the four interaction states, the rail, the actions and the title editor. Its colour tokens (`--canvas-card-*-color`) stay app-owned in `tailwind.css`, and `--card-width`/`--card-height` arrive as inline custom properties from `cardSizeVars` in `packages/app/src/card.ts`, so a `CanvasCard` mounted without them draws content-sized. `test/unit/canvas-card-contrast.test.ts` holds every text role the Card draws on its own cream faces to WCAG AA — the app is dark and the Card is not, so a token that reads well elsewhere can be invisible here. Markdown Card content and editing are owned by `CanvasCard` and the `@project/ui` Markdown components. The app never names a `.cm-*` class. `packages/ui/src/card-search-combobox.css` continues to theme the shared Card picker used by Alias targets and Edge authoring.
- **The design system's two gaps are written down and checked (design-system baseline Issue 08).** `packages/app/stories/design-system-inventory.ts` declares them as literal lists, and `pnpm ui:catalog:check` — which runs in `verify` — holds both to the tree. **Start a new story by copying `packages/app/stories/story-template.tsx`** — its header comment is the source of truth for which `stories/<section>/` it belongs in and for the `StoryCanvas`/`StoryCanvasFrame` pattern a real-canvas story must use. **`uncataloguedComponents`** names every production `.tsx` under `packages/{ui,app,react-flow-adapter}/src` that no stable story renders; reachability is resolved through the real import graph from the stable `stories/components`, `stories/surfaces` and `stories/space` sections, while `stories/review` remains outside parity evidence even when a staged surface appears under a production section in Ladle. A package barrel is followed by the *names taken through it*, so importing one component from `@project/ui` does not silently catalogue the package. Three resolution rules matter: a `#subpath` specifier resolves through **its own package's** `imports` map (`packages/ui` has one too, and `sidebar.tsx` uses it); a re-export alias is matched by the name consumers import, not the local one, since `packages/ui/src/index.ts` carries both `CardContent` and `CardContent as CardSection` from different modules; and a type-only import is erased, so it never counts as rendering. A whole-namespace import (`import * as UI`) reaches **nothing** through a barrel — deliberately the conservative direction, since the alternative is cataloguing a package silently. **`handRolledStyles`** names every block `packages/app/src/styles.css` still declares — by class; or, for a rule that names no class, by its leading attribute or id; or, failing both, by its leading element name — so `#root` and the bare `*` and `body` resets cannot slip past by having no class to record. Attribute and id win where a selector carries both, so `html, body, #root` is keyed as `root`. **The dead-rule half also runs over the stylesheets that live beside their component** — `canvas-card.css`, `card-search-combobox.css`, `markdown-source-editor.css` — so moving a block out of `styles.css` and next to what draws it is not a way to leave the ratchet behind. Only that half: colocation is the approved home for product appearance, so those sheets owe no inventory entry, and recording them would turn the inventory into a list of things that are fine. `tailwind.css` is excluded with `styles.css`, its classes being Tailwind's to emit rather than a module's to name. Both lists are ratchets in both directions: a new component or a new block fails until it is built from `@project/ui` or recorded with a reason, and an entry that stops being true — a component that gains a story, a block whose rules go, a module that is deleted, a module outside the scanned set, the same subject recorded twice — fails too. The stylesheet also fails on a rule no production module names, which is how seven dead rules (`.btn`, `.controls__btn`, `.persistence-refusal`, `.rf-edge--reference` among them) were found. Three details of that scan are load-bearing and each was a real defect: **a class counts as named only where a class is actually written** — a `className`/`class` attribute, a `className` property, or a `cn()`-style call — because reading every string literal let `{ kind: 'card' }` and `type: 'card'` hold `.card` alive; **classes built by interpolation** count through their template stem, so `` `…--${role}` `` does not report its rules dead; and **React Flow's own `react-flow__*` classes are exempt**, because nothing here emits them and demanding a reference would only invite one written to satisfy the check. `stories/support` is held to catalogue furniture: its stylesheets may only declare `inv-*` classes, and a support harness may not name a production class — reproducing a surface instead of rendering it is exactly what ADR 0052 excludes. **The inventory is not a backlog.** Some entries are permanent and correct (a composition root has no state to catalogue; camera modules render nothing), and one names real debt with an owner: `space-selection` is product appearance condemned with its component under ADR 0058, and goes with `space-cards/04`. `card-editor` was the other until ADR 0070 deleted the component it styled, taking its entry with it. `AuthorableEdge` has no stable story because the Edge line's review story is blocked on the reconnected-Edge selection defect.
- **Card markdown is sanitised before it is injected.** `CardContent` renders through `dangerouslySetInnerHTML`, and `marked` has had no `sanitize` option since v5, so `DOMPurify.sanitize()` sits between them. Don't remove it on the argument that a card came from a local import: backend implementations and future import sources broaden that premise. `packages/ui/test/CardContent.test.tsx` fails without the sanitiser.
- **Expanded-Card movement uses production geometry, not an entrance-animation library.** Opening, closing and neighbour displacement are transitions between React Flow node rects (ADR 0064). The node wrapper owns that geometry; content inside it is a passenger. Motion must use one duration/easing token and honour reduced motion. No animation library is currently adopted, and fixed entrance keyframes do not represent authored before/after placement.
