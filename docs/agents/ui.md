# UI Foundation

UI components and operational feedback built on shadcn, Base UI and Lucide, including the Escape/commit and focus conventions that follow from them. Read before touching `packages/ui` or a pane, menu, combobox or feedback surface in `packages/app`.

- **Application stories use the production host.** `components/Application.tsx` takes a startup resolver, shares one opening across StrictMode effect replay, and delegates rendering and startup failure to `startApplication`. Both `main.tsx` and full-application Ladle stories mount it. `stories/support/application.ts` supplies only fixture snapshots and an isolated memory/history adapter; setup opens and enters through Open Spaces and causes failure states through backend outcomes. Commands, persistence recovery, Exit, Availability and focus remain the application's own. The Dock fixture builds no `DockChrome`, holds no second session map and implements no snapshot Edits. Reach transient states through production operations or controls; the left-edge story presses the existing Dock position menu. Browser assertions must account for inactive Spaces remaining mounted.

- **Opening and editing a Resource are separate (ADR 0064).** Open and Close author the Map-owned Open/Closed state and nothing else ([`maps-and-graphs.md`](maps-and-graphs.md) R38). A Closed Resource offers Edit and Open, an Open Resource offers Edit and Close, and Edit on a Closed Resource opens it before placing the caret. While Markdown editing is live, Save and Cancel replace Edit, Close stays visible but disabled, and blur ends nothing (see the Escape and commit bullet below). The Open Resource renders Markdown through the shared sanitised renderer; editing swaps that body for `MarkdownSourceEditor`. Add no `nowheel`, 16:9 constraint or camera follow to an Open Resource.
- **An Open Reference Resource shows its immutable Target's content read-only (ADR 0070, ADR 0089).** A Reference Resource is otherwise authored like any Resource: its Title, placement, Edges, Open/Closed state and size all change as for any other. Opening one is the ordinary Open — pointer, Enter and Space all use the one `opened-resource` completion — and it draws its Target's content through the same surfaces its own kind would: Markdown through `CanvasResource`, a Space Resource Target's selected Map and Graph through the shared embedding, an Image Resource Target's picture with no Replace on the rail or in the failed-image state. It offers Close and inline Title editing and no Edit, Save, Cancel or Target picker. Target immutability is Space Authoring's, not the surface's ([`editing-and-persistence.md`](editing-and-persistence.md)); content resolves once, in `@project/graph` ([`rendering.md`](rendering.md)); descendants of a Reference Resource whose Target is a Space Resource stay read-only. A Reference Resource is created *from* its Target: a `Create Reference` row on that Resource's own command menu supplies the Target, names the new Resource after it (copied once) and puts the caret in its Title. The row is drawn **unavailable**, not absent, on a Reference Resource, which is where the product says referencing terminates. A Space Resource's entity menu groups Rename and Create Reference, Enter and Open in New Tab, its three copy links, and Remove from Map. `ResourceSearchCombobox` has no consumer and carries an inventory entry.

- **A shadcn component is the default, and a hand-roll is a deviation (ADR 0047).** Two rules. First, **the component**: where shadcn ships one for a surface this app needs, build on it and the headless primitive it composes rather than writing our own. Second, **its behaviour**: start from that component's documented keyboard, focus, dismissal and accessibility defaults and shape Hyper's feature around them rather than recreating or overriding them. Both carry the same bar — every deviation needs an explicit product requirement and an interrogated, recorded reason — and **"our case is special" is not a reason until it has been tested against the primitive**. For example, "React Flow keeps its nodes in the tab order, so `inert` is not available" is true about the platform and no reason to hand-roll a dialog's focus trap, initial focus, `aria-modal` or pointer containment: a dialog primitive traps with its own focus scope and never needs `inert`. The primitive layer is one whole-repo decision, not a per-component preference, and **ADR 0050 has taken it: Base UI**, whose bullet below carries what that means in practice. The corollary: a written contract that contradicts a primitive's default loses unless the deviation clears the bar.
- **Base UI and Lucide are the UI foundation (ADR 0050) — built.** ADR 0050 takes the whole-repo choice ADR 0047 left open; the per-component migration reports are in `.scratch/base-ui-migration/`, and the whole-project report (`08-whole-project-migration-report.md`) records that its manual QA pass against the pre-migration baseline has not been run. Both shadcn workspaces declare `base-nova`, a `neutral` base and CSS-variable theming; `Button`, `Select`, `Popover`, `Dialog` and the `Menu` behind the Command Dock's Map, Graph and Space disclosures are `@base-ui/react` `1.7.0`; general-purpose glyphs in the shared icon facade use Lucide; Parent/Meta uses the approved OPEN infinity-cube artwork, while Spaces and Space Resources share the optically corrected Lucide cube; and **no authored module or workspace manifest names `@radix-ui/*`**. Hyper's palette and spatial presentation are Hyper's own: the custom classes sit on the Base variants, and the registry style is a component-generation baseline rather than a product restyle. Lucide is the default vocabulary: keep a custom `@project/ui` icon only when no Lucide glyph communicates a genuinely Hyper-specific concept, and take that exception by naming the missing meaning, never a preferred silhouette. **`cmdk` behind `Command` is deliberately not migrated** — it is a search primitive, not a Radix wrapper, and it carries `@radix-ui/react-dialog` and friends transitively, so a lockfile hit for `@radix-ui` is transitive and cmdk's. Four rules a sweep would undo: **Base UI has no Anchor part**, so a non-trigger anchor is a ref handed to `PopoverContent`'s `anchor` and forwarded to `Positioner`; positioning props belong to `Positioner` and popup props to `Popup`, and a `side` left on the popup does nothing at all; **`nokey` stays on every portalled popup and on any chrome control outside the canvas** — the Command Dock's controls and its portalled menus carry it — because React Flow subscribes its delete key on `document` and neither a portalled surface nor a control beside the canvas sits inside the canvas's own guard; **Base UI spells the controlled empty state `null`**, and a controlled choice here ignores the `null` from `onValueChange`, because Hyper has no clear-selection action; and **a modal that declares its own starting field declines both of Dialog's focus hooks** (`initialFocus={false}`, `finalFocus={false}`) so that field and the caller's post-close restore win, while the primitive keeps the trap, Escape and `disablePointerDismissal` — `Dialog` has no consumer, so this is the rule for the next one.
- **`Kbd`/`KbdGroup` are shadcn's keyboard-key primitive**, generated into `packages/ui/src/components/kbd.tsx` from the `base-nova` registry and exported from `@project/ui`. Hyper deliberately extends the registry drop with `keyName="modifier"`: the modifier label must resolve to Command on Apple platforms and Ctrl elsewhere without each consumer duplicating that policy. Preserve that extension when refreshing the registry component. Its consumers are the presenting chrome's keyboard guidance and the Open Markdown Resource's shortcut hint. Use it wherever a surface names a key rather than hand-rolling a `<kbd>` — and note it is presentation only: the control that *performs* a shortcut still announces it with `aria-keyshortcuts`, as `CanvasResource`'s Save and Cancel rail actions do.
- **Escape and commit are decided by the surface, not by the field (ADR 0048, refined by ADR 0051).** A drawn Resource commits its **title** on blur and Escape reverts it; its Open Markdown **body** does not (ADR 0064) — `Mod-Enter`, `Escape` and the rail's Save and Cancel are the only exits, because a document is not a refusable line (see `MarkdownResourceBody`). No surface pends several fields behind one commit: every creation completes its Edit on activation (ADR 0089).
- **Expected errors keep their owner (ADR 0057) — built through Authoring, UI and HTTP.** Application composition exhaustively maps structured Authoring refusals to the surface conducting the interaction: a refused Title keeps its inline editor open with the draft (see the end of this bullet). Retryable persistence failure, permanent rejection and conflict remain the Space's existing `Alert`/`AlertDialog` states rather than reappearing inside the editor that made the Edit. HTTP transports stable Problem Details identities and the adapter translates them once into persistence outcomes; UI code does not branch on wire prose or wire shapes, **and does not print it either** — persistence's own codes have application-owned copy in `authoring-refusal.ts` beside the Authoring sentences, so `problem.detail` reaches no surface and one module holds every sentence the author reads. A stable Ladle story exercises a production-reachable refusal rather than injecting display prose through a callback to manufacture one — where a refusal is genuinely unreachable through a browser gesture, the story is handed the **structured** refusal and the claim declares its `applicationEvidence` exemption. The Edge surfaces follow the same rule: Edge Authoring retains an `EdgeRefusal` naming one of two channels — `command`, any of an Edge toolbar's three commands, drawn in the one alert region under that Edge's toolbar, and the canvas announcement a finished pointer gesture leaves behind — and `AuthorableEdge` derives the sentence per render. A refused Title keeps its field open, described by that region: `InlineTitleEditor`'s `errorShownBy` names it so the reason is said once. The refusal cascade is cached in `docs/agents/authoring-refusal-cascade.md`; wire rules live in `docs/agents/http.md`.
- **Where an Edit continues is one module, `continuation.ts`.** The rule `CONTEXT.md` states in several places — *an Edit continues at the entity it produced* — has one implementation, and one timing hazard to answer: **the continuation runs before the surface it targets exists**. A gesture calls `request({ target, select, then })` and an adapter spends it once. **One pending continuation, never a queue** — a second request replaces an unspent one silently, because a continuation says where the author should be *now* — and `take()` is what stops one firing twice. **Two axes, not one intent list**: a creation is select *and* rename, an Edge drop is select *and* nothing, Add to Map is focus with no selection move. Targets are `resource | edge | canvas | control`, and a chrome target is a **string the adapter resolves against an addressing attribute** — `data-continuation-control` — rather than a ref, because the module has no framework and a name→ref registry carries its own lifetime bug. **`ContinuationControl` has one member, `'map-name'`**: Add Map creates an empty Map and selects it, and the caret lands in the new Map's name. Every Resource creation, a Reference Resource's included, completes its Edit on activation and continues at the Resource it made — a canvas `resource` target, not a chrome one (ADR 0089). A Map or Graph rename needs no chrome address: the Command Dock draws each name once and its editor replaces that one control, so the editor hands focus back itself. It is composed in `compose-app.ts` before Edge Authoring, which publishes into it, and it invalidates on **two** facts subscribed from Authoring — the replacement epoch (ADR 0042) and entering presenting — and deliberately not on the selected Map or Active Graph, because over-invalidating silently loses a legitimate continuation. **Two adapters, and they cannot be one**: `CanvasContinuation` mounts inside `ReactFlowProvider` (it owns `resource | edge | canvas`, moves the camera for `reveal`, and is the only place a continuation is focused for them — `repairFocus` in `edge-authoring-react.tsx` focuses the canvas, but as a repair to React Flow's native Edge Escape rather than as a continuation) and `ChromeContinuation` mounts at the App root, because the `ReactFlowProvider` subtree is conditional on there being Resources at all, so the chrome half has to be reachable whether or not the canvas is mounted. Each checks the kind itself and calls a nullary `take()`; which kinds it owns is a fact about the React tree and never enters the module's signature. **Readiness is discovered, waiting is policy**: the canvas adapter re-resolves on *every* render — with no dependency list, because React Flow draws its nodes a commit or more after the projection arrives and every prop identity is unchanged when it does — and `staysOwed` in the module says a canvas subject waits while chrome and the canvas fall through. `rename` reaches `CanvasResource` as the `nameOnCreation` prop: `@project/ui` owns that editor, depends only on `core`, and a component refocusing its own control after its own edit is genuine locality. The word is deliberately **not** in `CONTEXT.md`: it names a surface's state machine rather than anything in the authored world, the same reason *projection* is absent there.
- **Operational feedback is one deep module.** Use `StatusFailure` for a blocking startup, render or placement failure and `StatusBusy` for an in-progress operational state; compose a product-specific component around them so production and Ladle mount the same surface. `StatusFailure` owns the destructive announced `Alert` and the named, keyboard-focusable diagnostic region. Set `boundedDetail` where the panel shares a viewport with chrome, and leave it unset where the page owns the viewport and can scroll; choose the surface width through `panelClassName`. `StatusBusy` owns one labelled `role="status"`; its Spinner is decorative and must not create a second live region. These panels are distinct from `FieldError` for correctable input and from `AlertDialog` for a decision or recovery action.
- **The Space command surface is the Command Dock, and the canvas takes one Map choice (ADR 0082, ADR 0079).** ADR 0082 binds that the canvas takes **one** exclusive choice over authored Maps, with no second control and no empty value, and leaves where that choice sits to treatment. `CommandDock` (`packages/app/src/components/CommandDock.tsx`, with its Map and Graph clusters in `CommandDockMapGraph.tsx`) draws it as the Map cluster's `ChoiceMenu` — a labelled radio list the shared component renders — taking the Space's `maps` and the `selected` Map as domain values. **The one spatial fact the ADR binds is that the surface takes no layout space from the canvas**, so it is a `Toolbar` floating over `.graph-area` in one of twelve slots rather than a gutter, and `AppShell` frames no Sidebar and yields no strip to anything. Everything else about it — which edge, how it moves, how its commands are grouped, every glyph — is treatment settled by `stories/space/command-dock.stories.tsx` and its two suites, and does not come back to an ADR. Do not add a second canvas selector, and do not give the surface layout space because it needs room (disclosure, orientation or a filter inside a group is the answer). **The responsive story is the Dock's own**: there is no Sheet, because the surface never took the canvas away, so no command dismisses anything before acting — what it owes is to fit, and it does that by capping to its container and scrolling along its own axis. Presenting hides the command toolbar; `PresentingChrome` carries the way out, and an outstanding persistence failure remains visible with Retry reachable. Persistence is reported **beside** the toolbar and never inside it — status is not a command — and there is deliberately no resting saving cue, because a commit settles faster than a dot can be read. A Resource's own commands belong to the Resource rail (ADR 0073), which is where Copy link to Resource in Map, Copy link to Resource and Delete from Space are drawn. **The Dock's Resources list carries one of them, Delete from Space, and no other**: a Resource the selected Map does not place has no rail, and the list is the one surface naming it. Each Resource row arms the same `resourceDeletion` confirmation the Resource's Actions menu arms, offered exactly when that menu's is (`availability.deleteResource`); a Space row and the `connect` purpose offer none (`.scratch/resource-deletion/issues/02`). **The Dock's surface and its Map/Graph lists are `@project/ui`'s, shared with the Resource rail** (`.scratch/command-dock/issues/12`). The neutral panel every command surface wears is `CommandSurface`/`CommandToolbar` and `command-surface.css`, which the Dock mounts and so does `CanvasCommandToolbar` — a Resource's toolbar (floated by `ResourceNode` in React Flow's `NodeToolbar` while the Resource is selected, ADR 0102) and the Dock are one surface drawn twice rather than two stylesheets that agree today, and `test/unit/command-surface-sharing.test.ts` holds that. So the Resource rail is neutral, and the Active Graph's colour stays on the handles and Edges, where it names a Graph. **A toolbar drawn on the canvas is `CanvasCommandToolbar` with `CanvasCommand`s in it** (`.scratch/edge-toolbar/issues/03`): the shared surface plus the keydown stop on the root, and a command carrying `nodrag nopan`, the click and pointer-down stops and `holdFocus`. `ResourceRailActions`/`ResourceRailAction` are those two with the Resource's slot names and `resource__rail-action` hook, and the Resource's kind and shared groups stay the Resource's; the Edge toolbar builds on the same two. The sharing test lists every canvas toolbar and reports any module other than the Dock and `CanvasCommandToolbar` that mounts `CommandToolbar` directly. Choosing a **Map or a Graph** is `ChoiceMenu`, which the Dock's Map and Graph clusters and an Open Space Resource's two choices all draw: it owns the labelled radio list, the mark, the keyboard and the dismissal, and takes the set, the selection and the operation from its caller — because those are *not* shared, one moving the canvas the author stands on and the other writing which Map a Resource shows. `ChoiceMenu` also renders the group and its items from one type parameter, so no caller binds item components by hand. An Ur Resource's Shape is the same list on the Resource's rail (ADR 0121): `ResourceShapeMenu` draws it uncaptioned (`captioned={false}`, the list still named `Shape` to assistive technology), its trigger a `ToolbarButton` in the rail's one tab stop whose face is the current Shape and whose name is `Shape: <Shape>`, and each row is the Shape's glyph and name. The glyph is `ResourceShapeIcon` and the names are `RESOURCE_SHAPE_LABELS`, both in `ResourceShape.tsx` as the head shape's are in `GraphHeadShape.tsx`: each Shape is drawn from `resourceShapeOutline` — the geometry the canvas draws it in — in a box with the Closed Size's proportions, at Lucide's stroke, because Lucide has no ellipse or capsule; the rectangle alone takes Lucide's corner radius in the glyph, though the canvas draws it square. `CanvasResource` draws no kind glyph on an Ur Resource, in any Shape, Open or Closed, because its Shape says what it is; `CanvasResource` decides that once, and the Resources list draws the Ur glyph on its row, where there is no Shape to say it. **`Select` and `Dialog` have no consumer**, and each carries an inventory entry. Creating a Space Resource makes its own Space and chooses nothing, and referencing an existing one is the Resources list's add-Space row, so no flow asks for a Space through one widget and for its Map through another. A third picker is not the answer to anything. Every call site carries `nokey` on the portalled popup itself rather than the wrapper carrying it — React Flow subscribes its delete key on `document`, and a popup drawn anywhere but over a canvas needs no marker.
- **A chrome continuation is spent by `ChromeContinuation`, not by a handler calling `.focus()`.** The one chrome address is `'map-name'`: Add Map creates an empty Map and continues in its name. The visible name discloses the Map list (`.scratch/command-dock/issues/26-identity-clusters-disclose-from-the-name.md`), so the adapter presses a dedicated hidden sibling that begins the same editor Rename does, rather than the name a reader clicks. **A menu that runs such a command has to be told not to take the caret back**: a Base UI popup restores focus to its trigger in a microtask *after* it closes, so the New Map row raises a flag the Map cluster's `ChoiceMenu` reads through `restoresFocusOnClose` — without it the restoration lands on the chevron a frame after the editor has focused itself, blurs it, and completes the rename nobody typed. `modal={false}` stays on `ResourcesPopover` for a reason written beside it there: it declines the `outside-press` and `focus-out` dismissals a drag from the list onto the canvas produces. That is its Dock purpose only: as a Resource's Connect list (`purpose: 'connect'`, `.scratch/edge-toolbar/issues/07`) it has no trigger of its own — Connect to Resource in the Resource's Actions menu opens it, and it hangs from that menu's trigger (the `opener` an `EntityAction`'s `onSelect` is handed) and hands the caret back to it on Escape, but not after a drawn Edge or a dismissal that already put the caret elsewhere — takes both dismissals, stops events inside it from travelling the React tree to the canvas it is drawn in, and unmounts its popup with its close rather than after Base UI's exit, because a closing popup holds the caret and `CanvasContinuation` focuses the Edge a choice drew only once focus is nowhere. In tests of a menu, remember that Base UI dispatches a `PointerEvent` for keyboard-activated menu items while jsdom does not provide that subclass — and that a test which opens and dismisses a menu before the gesture under test leaves that focus-restoring microtask in flight across it.
- **Choosing a Resource is the Resources list, `ResourcesPopover`, in one of two purposes.** The Dock's list places what the selected Map does not. Connect to Resource, in a Resource's Actions menu, chooses an Edge's other end from what the Map *does* place, bar that Resource: the same search and kind filters, no drag and no Spaces source, a refused target kept as an unavailable but still focusable row carrying its reason (asked through `connectChoices`, the pointer gesture's own eligibility), and a last New Resource row that is the keyboard form of the Option/Alt empty drop. A choice draws the Edge in the Active Graph and continues at it, selected and focused. Do not add a second picker for choosing a Resource: the Resources list serves both purposes.
- **Creation is one press per kind, from `CreatePeers`** (`packages/app/src/components/CommandDockResources.tsx`). It draws four glyphs as peer toolbar buttons (ADR 0082): markdown, space, image — whose one press opens the file picker and completes on the files chosen — and ur (ADR 0113). Each completes its Edit on activation (ADR 0089). There is no Reference glyph: a Reference Resource is created from the Resource it points at. Create stays outside the Resources list. Do not restore `AddResourceControl`: its design, a split button with a hidden default, contradicts `CreatePeers` on purpose — the kind is chosen at creation, so no kind is a default. On a side edge the Resources cluster packs onto one row rather than taking a verb track each: it does not need the `1fr` name track the three *authored* names need, because "Resources" is a fixed word. Both are ADR 0052 treatment, held by `packages/app/stories/parity-claims.ts`'s `command-dock-creates-each-kind-in-one-press` and `command-dock-packs-resources-onto-one-row`.
- **The chrome has no Sidebar, Sheet, Drawer or Tabs (ADR 0082).** The Command Dock floats over the canvas and takes no layout space, so nothing frames a gutter, overlays the end edge or yields a strip: the Resources list is a Popover anchored to the Dock's own trigger, and the Dock's Open Spaces menu is the open set's one surface. The words that report an unwell open Space are `open-space-status.ts`. A registry primitive is regenerated from shadcn when one is wanted; `components/skeleton.tsx` is one, for `ResourceImage`'s loading state.
- **`InlineTitleEditor` draws `Textarea` wherever a Title may be written on more than one line**, in place of `Input`. ADR 0083 makes that the Resource's Title and no other entity's: `CanvasResource` sets `multiline` and the Dock's header does not.
- **Markdown source is edited through `MarkdownSourceEditor`, the one component allowed to know CodeMirror exists (ADR 0063, refined by ADR 0067).** `ui` owns the split point that reaches it, `markdown-source-editor-lazy.ts`, beside the component that needs it: `MarkdownResourceBody` is a second consumer inside the package, and a static import from it would put the whole stack into the barrel and from there into every consumer of `@project/ui`. So `app` names the editor nowhere, and the `@project/ui/*` ESLint zone is a plain bar with no negated entry. Two responsibilities are the wrapper's and not a caller's: which keys it withholds from CodeMirror (`PANE_OWNED_KEYS` — `Escape` and `Mod-Enter`, the two exits the mounting surface spends, both of which `defaultKeymap` would otherwise take), and every `.cm-*` selector. A caller that needs a say over CodeMirror's appearance sets a custom property the component's own theme reads; no stylesheet in the repository names a `.cm-*` class. `test/unit/codemirror-encapsulation.test.ts` holds both that and the dynamic-import split, scanning both source trees.
- **There is no creation pane, and reintroducing one is a decision (ADR 0089).** No surface holds a creation in progress for other surfaces to stand out of the way of. Every Resource creation completes its Edit on **activation**: one press places a Resource at a position the gesture already knows, selects it, and puts the caret in its inline Title editor. What a kind needs beyond a Title it takes from the context the gesture was made in — a Reference Resource from the Resource whose menu ran the command, a Space Resource from the Space it mints for itself — rather than from a field the author fills. So a refusal has no field to sit beside: a Space Resource's reports on command outcomes' `space-resource-create` channel, beside the Map creation notice on `map-create`, and a Reference Resource's on the standing `reference-create` notice — the Create Reference row carries no `report` and closes when pressed, because the caret goes to the new Resource's Title on the canvas, so there is no menu row left to swap a word on (`EntityActionsMenu`). A kind that seems to need a value at creation is the case for siting the gesture where that value already exists, not for a form; a fourth kind that genuinely cannot is a decision refining ADR 0089, with the reason in hand.
- **Styling is split:** `ui` uses Tailwind v4 + shadcn-style primitives, and so does any production module that owns its own semantic presentation — `GraphHud` in `react-flow-adapter` is one. Tailwind scans `app`, `ui/src` **and `react-flow-adapter/src`** via `@source` in `tailwind.css`; without the third, the HUD's utilities are purged. What stays hand-rolled in `packages/app/src/styles.css` is what is React Flow's: node and resource sizing, handle visibility, the one `.rf-resource-node--active :is(.resource, .canvas-resource)` rule naming the actively presented Resource, and the portal layers a Resource's and an Edge's controls are placed in (`.edge-control-layer` is placement, pointer-events and the revealed Edge's raised stacking only; `EdgeTitle` and `EdgeToolbar` own how the Edge's chrome looks, the Title in its colocated `packages/ui/src/edge-title.css`). **Every block that file declares is recorded with its reason** — see the inventory bullet below — so what is actually in there is a list rather than a claim. One order in it is load-bearing: `PresentedResource`'s own `.resource--full` rules sit *above* the `.rf-resource-node__content` container-query block, because `.resource--full .resource__title` and `.rf-resource-node__content .resource__title` have equal specificity and only source order separates them. With the base rules last, a presented Resource's title takes a fixed `1.3rem` instead of scaling with the frame, against ADR 0027. Presenting draws on the Stage (ADR 0123), so that order serves only the canvas presented display ticket 03 deletes: the Stage's own container-unit rules live in `packages/ui/src/stage.css` beside `Stage.tsx`, out-specify the base rules, and `presenting.spec.ts` pins the name at 5cqw of the frame. **The canvas Resource runs the other way**: its own CSS is hand-rolled and lives with its component, in `packages/ui/src/canvas-resource.css` beside `CanvasResource.tsx` — kind treatment, the four interaction states, the rail, the actions and the title editor. Its colour tokens (`--canvas-resource-*-color`) stay app-owned in `tailwind.css`, and `--resource-width`/`--resource-height` arrive as inline custom properties from `resourceSizeVars` in `packages/app/src/resource.ts`, so a `CanvasResource` mounted without them draws content-sized. `test/unit/canvas-resource-contrast.test.ts` holds every text role the Resource draws on its own cream faces to WCAG AA — the app is dark and the Resource is not, so a token that reads well elsewhere can be invisible here. Markdown Resource content and editing are owned by `CanvasResource` and the `@project/ui` Markdown components. The app never names a `.cm-*` class. `packages/ui/src/resource-search-combobox.css` themes `ResourceSearchCombobox`, which has no consumer.
- **The chrome and the Resource each draw from one named structural scale, and a bare value or an unregistered utility fails the build (`.scratch/structural-tokens/`).** Radius, border width, font weight and shadow are named tokens — `--radius-chrome-*`/`--text-chrome-*`/`--shadow-chrome-elevated`/`--shadow-chrome-lifted`/`border-chrome-accent` in `packages/app/src/tailwind.css` for the chrome, `--canvas-resource-border-width`/`--canvas-resource-radius`/`--canvas-resource-shadow-*` beside them for the Resource's own, deliberately separate scale (ticket 06) — and a control states one by name rather than restating `rounded-[6px]` or `border-radius: 6px`. Five `test/unit` files over one shared reader, `test/support/structural-scan.ts`, hold this — `structural-arbitrary-classes`, `structural-css-literals`, `black-shadow` and `chrome-utility-registration`, one per arm, and `structural-scan` for the reader itself. Together they fail a new Tailwind arbitrary value (`rounded-[…]`, a length-like `text-[…]` or `border-[…]`, `shadow-[…]`/`drop-shadow-[…]`, each in its `(--x)` shorthand too) in `.ts`/`.tsx` under `packages/*/src`, a bare `border-radius`/`border`/`box-shadow`/`font-weight` literal (or a weight inside the `font` shorthand) in a hand-rolled `.css` file there — `.css` only, by decision: a TSX style object, inline or CodeMirror's theme in `MarkdownSourceEditor.tsx`, is not read as a declaration by any arm — and any shadow — including one hidden inside a token's own definition — whose colour is written as black rather than taken from the theme, `shadow-black` included, and any Tailwind named shadow step (`shadow-sm`, `shadow-lg`, …, and the `inset-shadow-*`, `text-shadow-*` and `drop-shadow-*` steps too) the theme does not restate off black — Tailwind's own defaults are black, so `tailwind.css` restates all seven in `--foreground` (ticket 10). **Add a new `*-chrome-*` theme utility and register it beside `cn()` in the same change**: ticket 02 found `tailwind-merge` does not recognise a custom utility name, so an unregistered one does not evict the built-in class it replaces and two conflicting declarations ship silently — `chrome-utility-registration.test.ts` fails the build when the theme's class-generating utilities and `extendTailwindMerge`'s registration disagree either way. A direct `:root` custom property such as `--shadow-chrome-elevated` is never on that list; only a name inside a `@theme` block (plain or `inline`, every one of them) or a `@utility` block generates an actual class, and a `@theme` chrome key in a namespace the test does not map fails it too. A handful of enumerated carve-outs (a nested-corner `calc()` relative to `--radius-md`, a glyph's black contrast outline, the universal 1px hairline default, the full-circle and full-pill radius idioms, and two named shadow exceptions) each carry a reason and are asserted to still excuse a declaration the scan would otherwise report, so the list cannot silently outlive what it excuses. A spelling earns an arm only when it occurs in the tree, a tool this repo uses emits it by default, or it is the obvious idiomatic way to write the value here; ticket 08's Resolution records that rule and what the regex scan cannot see (`font-size` in CSS among them), for which resolving computed styles in e2e, not more patterns, is the complete check.
- **The design system's two gaps are written down and checked (design-system baseline Issue 08).** `packages/app/stories/design-system-inventory.ts` declares them as literal lists, and `pnpm ui:catalog:check` — which runs in `verify` — holds both to the tree. **Start a new story by copying `packages/app/stories/story-template.tsx`** — its header comment is the source of truth for which `stories/<section>/` it belongs in and for the `StoryCanvas`/`StoryCanvasFrame` pattern a real-canvas story must use. **`uncataloguedComponents`** names every production `.tsx` under `packages/{ui,app,react-flow-adapter}/src` that no stable story renders; reachability is resolved through the real import graph from the stable `stories/components`, `stories/surfaces` and `stories/space` sections, while `stories/review` remains outside parity evidence even when a staged surface appears under a production section in Ladle. A package barrel is followed by the *names taken through it*, so importing one component from `@project/ui` does not silently catalogue the package. Three resolution rules matter: a `#subpath` specifier resolves through **its own package's** `imports` map (`packages/ui` has one too, and `components/card.tsx` uses it); a re-export reference is matched by the name consumers import, not the local one, since `packages/ui/src/index.ts` carries the domain `PresentedResource` and the shadcn registry's `CardContent` from different modules; and a type-only import is erased, so it never counts as rendering. A whole-namespace import (`import * as UI`) reaches **nothing** through a barrel — deliberately the conservative direction, since the alternative is cataloguing a package silently. **`handRolledStyles`** names every block `packages/app/src/styles.css` declares — by class; or, for a rule that names no class, by its leading attribute or id; or, failing both, by its leading element name — so `#root` and the bare `*` and `body` resets cannot slip past by having no class to record. Attribute and id win where a selector carries both, so `html, body, #root` is keyed as `root`. **The dead-rule half also runs over the stylesheets that live beside their component** — `canvas-resource.css`, `resource-search-combobox.css`, `markdown-source-editor.css`, and `command-dock.css`, the first of them under `packages/app/src` — so moving a block out of `styles.css` and next to what draws it is not a way to leave the ratchet behind. The scan walks the production roots rather than a list, so a new colocated sheet is covered the day it is written. Only that half: colocation is the approved home for product appearance, so those sheets owe no inventory entry, and recording them would turn the inventory into a list of blocks that are fine. `tailwind.css` is excluded with `styles.css`, its classes being Tailwind's to emit rather than a module's to name. Both lists are ratchets in both directions: a new component or a new block fails until it is built from `@project/ui` or recorded with a reason, and an entry that stops being true — a component that gains a story, a block whose rules go, a module that is deleted, a module outside the scanned set, the same subject recorded twice — fails too. The stylesheet also fails on a rule no production module names. Three details of that scan are load-bearing: **a class counts as named only where a class is actually written** — a `className`/`class` attribute, a `className` property, or a `cn()`-style call — because reading every string literal let `{ kind: 'resource' }` and `type: 'resource'` hold `.resource` alive; **classes built by interpolation** count through their template stem, so `` `…--${role}` `` does not report its rules dead; and **React Flow's own `react-flow__*` classes are exempt**, because nothing here emits them and demanding a reference would only invite one written to satisfy the check. `stories/support` is held to catalogue furniture: its stylesheets may only declare `inv-*` classes, and a support harness may not name a production class — reproducing a surface instead of rendering it is exactly what ADR 0052 excludes. **The inventory is not a backlog.** Some entries are permanent and correct (a composition root has no state to catalogue; the browser entry point is one `createRoot` call). `AuthorableEdge` is catalogued by `Space/Edge Toolbar`, which mounts it through the production application.
- **Resource markdown is sanitised before it is injected.** `RenderedMarkdown`, beneath `PresentedResource`, renders through `dangerouslySetInnerHTML`, and `marked` has had no `sanitize` option since v5, so `DOMPurify.sanitize()` sits between them. Don't remove it on the argument that a resource came from a local import: backend implementations and future import sources broaden that premise. `packages/ui/test/PresentedResource.test.tsx` fails without the sanitiser.
- **Open-Resource movement uses production geometry, not an entrance-animation library.** Resizing and neighbour displacement are transitions between React Flow node rects (ADR 0064, ADR 0122); Opening and Closing change what a rect draws, not the rect. The node wrapper owns that geometry; content inside it is a passenger. Motion must use one duration/easing token and honour reduced motion. No animation library is currently adopted, and fixed entrance keyframes do not represent authored before/after placement.
