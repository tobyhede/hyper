# UI Foundation

shadcn, Base UI, Lucide, and the Escape/commit and focus conventions that follow from them. Read before touching `packages/ui` or a `CardPane`/menu/combobox surface in `packages/app`.

- **A shadcn component is the default, and a hand-roll is a deviation (ADR 0047).** Two rules, and the second is the one that was missing. First, **the component**: where shadcn ships one for a surface this app needs, build on it and the headless primitive it composes rather than writing our own. Second, **its behaviour**: start from that component's documented keyboard, focus, dismissal and accessibility defaults and shape Hyper's feature around them rather than recreating or overriding them. Both carry the same bar — every deviation needs an explicit product requirement and an interrogated, recorded reason — and **"our case is special" is not a reason until it has been tested against the primitive**. That last clause is what `CardPane` failed: 175 lines reimplementing a dialog primitive's focus trap, initial focus, `aria-modal` and pointer containment, justified by "React Flow keeps its nodes in the tab order, so `inert` is not available" — true about the platform, and irrelevant to a primitive that traps with its own focus scope and never wanted `inert`. It is now some fifty lines over a real Dialog. The primitive layer is one whole-repo decision, not a per-component preference, and **ADR 0050 has taken it: Base UI**, whose bullet below carries what that means in practice. The corollary is live: a written contract that contradicts a primitive's default loses unless the deviation clears the bar, which is how issue `16` resolved.
- **Base UI and Lucide are the UI foundation (ADR 0050) — built.** ADR 0050 took the whole-repo choice ADR 0047 left open, and the migration landed it across `90231e0`..`e6978c7`, ticket by ticket, with a report per migrated component in `.scratch/base-ui-migration/`. Both shadcn workspaces declare `base-nova`, a `neutral` base and CSS-variable theming; `Button`, `Select`, `Popover`, `Dialog` and the `Menu` behind `AddCardControl` are `@base-ui/react` `1.7.0`; every facade in `packages/ui/src/icons.tsx` is a Lucide glyph and none is a local SVG; and **no authored module imports `@radix-ui/*`**. Hyper's palette and spatial presentation are preserved — the custom classes were replayed onto the Base variants, and the registry style stays a component-generation baseline rather than a product restyle. Lucide stays the default vocabulary: keep a custom `@project/ui` icon only when no Lucide glyph communicates a genuinely Hyper-specific concept, and take that exception by naming the missing meaning, never a preferred silhouette. **`cmdk` behind `Command` is deliberately not migrated** — it is a search primitive, not a Radix wrapper, and it carries `@radix-ui/react-dialog` and friends transitively, so a lockfile grep for `@radix-ui` still answers and that answer is cmdk's. `packages/ui/package.json` no longer declares `@radix-ui/react-dropdown-menu`, `react-popover` or `react-select` — the three were removed with the lockfile regenerated once the last importer went, which is `.scratch/base-ui-migration/issues/08`'s dependency item. **08's own status line reads done, with one honest remainder**: its whole-project migration report is written (`.scratch/base-ui-migration/08-whole-project-migration-report.md`), but that report's own "Baseline comparison and manual QA" section records that the human pass against the pre-migration baseline it asks for has not actually been run — the per-component reports 02–07 plus 08 are the record everything else rests on. No workspace importer names `@radix-ui/*` at all now, so a lockfile hit is transitive and cmdk's. Four migration decisions are load-bearing and a sweep would undo them: **`PopoverAnchor` is inert on purpose** — Base UI has no Anchor part, so a non-trigger anchor is a ref handed to `PopoverContent`'s `anchor` and forwarded to `Positioner` (the Edge toolbar is the one caller), and that export is a bridge for old imports rather than a component; positioning props belong to `Positioner` and popup props to `Popup`, and a `side` left on the popup does nothing at all; **`nokey` stays on every portalled popup and on the Select trigger**, because React Flow subscribes its delete key on `document` and a portalled surface sits outside the canvas's own guard; **Base UI spells the controlled empty state `null`**, which is what the View, Layout and Graph selectors pass and why each ignores the `null` from `onValueChange` — Hyper has no clear-selection action; and **`CardPane` declines both of Dialog's focus hooks** (`initialFocus={false}`, `finalFocus={false}`) so the product's declared starting field and App's post-close restore win, while the primitive keeps the trap, Escape and `disablePointerDismissal`.
- **Escape and commit are decided by the surface, not by the field (ADR 0048).** Two surfaces author a Card and each gets one rule for both. **Card Front**, in place on the canvas: the field commits on **blur**, and Escape reverts it to the stored value and dismisses the editor — that is `CardTitleEditor` and it does not change. **Card Editor**, the pane: every field pends — an Alias pane's Title and Target, a Markdown pane's Title, Description and Markdown source — **`Done`** commits all of them and closes, and **Escape is an alias of Cancel** — discard every pending field, close, with no field intercepting it. Each rule is forced by the other: a surface needs exactly one non-committing exit, and in place blur *is* the commit so a key must supply it, while in the pane `Done` is the commit so every other exit already fails to commit and Escape can take the meaning already on screen with a label on it. This **withdrew** the keyboard contract's "a field draft consumes the first Escape" — it had exactly three in-pane instances (`CardPicker`'s search clear, `OccurrenceTitleEditor`'s and `NewAlias`'s Title restores), it was never a primitive's behaviour (`CardPicker`'s own comment records that "cmdk leaves Escape to the containing surface"), and it was a second unlabelled copy of the Cancel button beside it. It also **withdrew the single-step retarget**: committing the Target on select changed the pane's resolved content under an open editor and remounted it, destroying an uncommitted body. Don't reintroduce a field-level Escape inside a pane, don't commit a pane field on blur or select because the Edit is "atomic" (atomicity is about the Edit, not about when the author is asked), and don't guard a remount whose real cause is an early commit — the content editor's key stays as it is. **Built**, over `@project/ui`'s Base UI `Dialog`: `CardPane` is the shared modal surface and each pane draws one Edit subject, an Alias's own Title and Target never reaching the Card its Target resolves to — which is **ADR 0049**, refining 0039, 0046 and this one, and the reason the two field lists above differ. That document reached this branch by `git checkout` from the paused `feat/card-pane-radix-dialog`, which is an independent sibling of main rather than an ancestor: `e6978c7` reconciled 0049's *semantics* here while the *document* stayed over there, so the citations in `App.tsx` and `OpenCard.tsx` pointed at nothing. Don't merge that branch to close the gap — it is built on the Radix Dialog this migration replaced. Package 4a's ticket (`.scratch/card-route-editing/issues/18`) still reads `ready-for-agent` and still names Radix Dialog — the tracker is behind the code, and the code is the answer.
- **A menu that opens a surface is `modal={false}` and declines the focus return, and a cmdk filter must not score a UUID.** Facts about `AddCardControl` and the shared `Command` in `@project/ui`, each found by a focus or a search behaving unlike the docs imply. A **modal** menu traps focus inside its own popup until that popup unmounts, which happens after the item handler has opened the Alias creation pane — so the pane took focus in its mount effect and had it pulled straight back into the menu on its way out, landing on `<body>` when the menu finally went. Non-modal is also the honest description: nothing behind a toolbar menu is unusable while it is open. Base UI then restores focus to the trigger on close, which is right for every close *except* the one that opened a surface, so `Menu.Popup`'s **`finalFocus` callback answers `false` for exactly that close** and leaves the default in place for Escape and outside clicks — a `useRef` set in the item's handler is what tells the two apart. Third, the mirror image on the way back: **a disabled control cannot take focus**, and the Add Card control is disabled while the pane it opened is open, so cancelling restores focus from an effect on the render that re-enables it rather than from the handler. Separately, **cmdk's default `commandScore` runs over each item's `value`**, and `CardPicker`'s values are Card UUIDs — a search for `a` then matches every id carrying a hex `a` and ranks by noise. The picker supplies its own case-insensitive substring-over-title filter for that reason, and the value stays the id: it is what `onSelect` answers, and two Cards may legitimately share a title. One test-environment fact rides along: **Base UI dispatches a `PointerEvent` when a keyboard-activated menu item completes**, and jsdom ships `MouseEvent` without that subclass, so `AddCardControl.test.tsx` stubs the missing constructor — platform, not application behaviour. Pinned in `packages/ui/test/AddCardControl.test.tsx`, `packages/ui/test/AddCardControl-base-ui.test.tsx` and `packages/app/test/card-creation.test.tsx`.
- **Styling is split:** `ui` uses Tailwind v4 + shadcn-style primitives; the graph/card CSS stays hand-rolled in `packages/app/src/styles.css`. Tailwind scans `app` + `ui/src` via `@source` in `tailwind.css`.
- **Card markdown is sanitised before it is injected.** `CardContent` renders through `dangerouslySetInnerHTML`, and `marked` has had no `sanitize` option since v5, so `DOMPurify.sanitize()` sits between them. Don't remove it on the argument that a card came from a local import: backend implementations and future import sources broaden that premise. `packages/ui/test/CardContent.test.tsx` fails without the sanitiser.
