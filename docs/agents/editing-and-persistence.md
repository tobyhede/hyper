# Editing & Persistence

`SpaceBackend`/`SpaceSession`, Space Authoring's completed-edit lifecycle, and the Layout/Graph aggregate model. Read before touching `packages/persistence`, `packages/graph`, `space-authoring.ts` in `packages/app`, `migrations/**`, or `src/prisma/**`.

**ADR 0070 refinement:** an existing Alias Target is immutable. `edited-card` may rename an Alias but refuses a changed Target with `alias-target-immutable`; the existing-Alias metadata pane and its retargeting surface are removed. References below to Alias retargeting describe the superseded surface.

## PostgreSQL & the document contract

- **A renamed persisted key is a codebase edit and nothing else (ADR 0056, refining ADR 0054).** Rename the field, roll the fixtures, seeds, stories, exporter and tests forward with it, confirm the old spelling appears nowhere the repo generates, and stop. **`documentRefusal` is not where a retired key goes.** Every database and space directory is derived, so the stored documents a compatibility path would protect are regenerated by the reset that follows any format change — there is nothing on the other side of the gate to answer. This is the trap the `defaultView` → `defaultLayout` rename set twice: review proposed a transitional read, then a pre-parse refusal beside `retiredSpaceGraphs`, and both were refused on the same grounds. The refusals already there stay, and are a different thing — `unsupportedDocumentVersion` answers a version this build cannot read, and `retiredSpaceGraphs` answers a shape a *current* hand or stale producer can still write. Both are consistency inside the codebase; neither is compatibility with a build that is gone.
- **Prisma Next 0.16.0 packaging workaround.** Its emitted `contract.d.ts` imports types directly from `@prisma-next/adapter-postgres`, `@prisma-next/target-postgres`, `@prisma-next/sql-contract`, and `@prisma-next/contract`, but pnpm's strict layout does not expose transitive packages to that project-owned file. Those four packages are therefore exact `0.16.0` root devDependencies only so generated types resolve. Authored config/runtime/application code still imports database capabilities only through the `@prisma-next/postgres` facade. Do not add hoisting or patch emitted artifacts; remove the four direct devDependencies when an upstream release emits facade-resolvable types.
- **Prisma Next 0.16.0 `int8` typing workaround.** Its PostgreSQL codec declares `int8` input and output as JavaScript `number`, although the codec and node-postgres runtime pass bigint-compatible values through unchanged. Repository revisions remain `bigint`; one compatibility cast is isolated in `toDatabaseRevision` and runtime values are checked when read. Do not convert revisions through `Number`, which loses PostgreSQL `bigint` range, and remove the cast when upstream exposes a lossless `int8` type.

## The Layout/Graph aggregate

- **ADR 0079 — every working Space has a Layout.** New Spaces start with one Card centered in `Layout 1` and one empty Active Graph. The first complete working read of a stored or imported layoutless Space atomically persists an empty `Layout 1`, its empty `Graph 1`, Active Graph and `defaultLayout`; listing, import completion, export and reference checks do not initialize. Add Layout creates and selects another empty Layout with one empty Active Graph. The last Layout cannot be deleted.
- **Layout selection is navigation, not an Edit.** The Sidebar selects one declared Layout; `positionedStrategy` draws only that Layout's Cards and owned Graphs. A later successful Edit may record the selection as `defaultLayout`. Automatic strategies remain non-addressable capabilities and are not canvas selections.
- **`Layout` is data and `LayoutStrategy` is behaviour — don't collapse them back (ADR 0014, ADR 0040).** A `Layout` (in `core`) owns an authored card→position map whose keys are explicit Card membership, plus the ordered Graphs over those Cards; a `LayoutStrategy` (in `graph`) is `(graph: LayoutStrategyGraph) => Promise<LayoutStrategyGraph>` in the first-public vocabulary. Every Layout has a strategy that renders it; not every strategy has a Layout behind it. There is no `Arrangement` type and geometry rides as optional fields on the elements (ADR 0005) — don't introduce one. Older comments call the *function* a Layout; that is stale vocabulary, not a second concept. The strategy intermediates are `LayoutStrategyGraph`, `LayoutStrategyCard` and `LayoutStrategyPort`.
- **A card is one file: frontmatter, then body (ADR 0020, refined by ADR 0051).** Shared frontmatter is `id`, `title` and `kind`; Alias adds `target`, while Markdown content follows the fence as the body. There is no shared Description. The space file holds `version`, `id`, `title`, `layouts`, `defaultLayout` — structure, and no `cards` array; a Layout holds the Graphs it owns, so there is no space-level `graphs` key (ADR 0040). Cards are discovered by scanning two locations, **non-recursively**: `*.md` beside the space file, and `cards/*.md`. Non-recursion is deliberate — ADR 0001's nested spaces will want subdirectories, and a recursive scan would make each one ambiguous with card discovery. A card's identity is its frontmatter `id` and never its filename, so renaming a file is not a data migration; a duplicate id across files is a load error naming both. A body may begin with a heading — the title lives in the same file, so a heading is just a heading. Every `.md` in scope *is* a card, so there is nowhere to leave a draft — and a `README.md` beside a space file would be read as one, which is why the fixture's moved to `packages/app/README.md`. **`body` is the field, `content` is the domain word**, and they are not synonyms to be reconciled: `CONTEXT.md` still lists "body" under _Avoid_ for a card's content in general, because a space-card's content is a graph and has no body. `Card.body` is what a *markdown* card's content is stored as. Don't rename one into the other in either direction.
- **Graphs are a Layout's only connection structure.** There is no authored `edges` array *beside* Graphs; ADR 0007 deleted that along with the `sequence`/`reference` kinds, and it stays deleted — don't reintroduce a structural layer next to Graphs. Under ADR 0040/0041 a Layout owns one or more Graphs over its explicit Card members, and every Graph Edge is closed over that set. A Graph **is** a set of `{from, to}` Edges the author draws (ADR 0032), so “Edge” names both the Graph's stored element and React Flow's drawn line — one word for one thing, and the only place the render layer and the domain share vocabulary. Cycles and self-Edges are legal; an exact duplicate within one Graph is not. The built types are `GraphEdge` (`core`) for the authored value, `GraphRenderEdge` (`graph/graph-rendering.ts`) for the handle-resolved projection, and `LayoutStrategyEdge` (`graph/layout.ts`) once a strategy has routed it. Do not preserve superseded Route-named aliases.
- **`manifest` is retired, in vocabulary and code (ADR 0010).** The top-level domain value is a **Space**, minted only by `loadSpace(input, cardFiles) → { ok, space } | { ok: false, errors }` in `@project/graph` — the one intake that parses (the space file *and* every card file's frontmatter), validates references, and indexes, so a `Space` is consistent and O(1)-resolvable by construction. `space.lookup` reads that index; every `graph`/adapter/app signature takes a `Space`. The on-disk shape is a **space directory**: the **space file** (`space.json`, validated by `core`'s `spaceFileSchema`) plus a markdown file per card (ADR 0020). A value that only passes that schema is *not yet* a Space. `loadSpace` gained the card files as an argument, not a capability — it still does no I/O and is still synchronous, and reading the bytes stays outside it. Don't reintroduce `manifest` anywhere — not as a type, not as the word for the file. There is no shared `Draft`: unfinished gestures and invalid editor input remain local to that editor. An editor installs valid authoritative state and emits a payload-free notification; Edit completion then derives and validates the whole next Space before effects.
- **A Graph may contain cycles and self-Edges (ADR 0032, terminology refined by ADR 0041).** Authoring records the Graph the author draws; Graph navigation and Presenting decide how to traverse it. An Alias is still the way to place and title the same content as a distinct Card, but it is not required merely to return to an existing Card. `loadSpace` rejects only an exact duplicate Edge within one Graph; drawing that duplicate live is an idempotent no-op.

## The SpaceBackend / SpaceSession contract

- **The browser never imports files or names storage.** `SPACE_DIR`, `virtual:space-file` and the Vite file plugin are gone. File discovery and parsing remain server-side CLI/import concerns. Browser resources list and lazily load individual Spaces under `/api/spaces`, read complete integrity state from `GET /api/aggregate`, and send every authored write to the collection `POST`; requests cannot carry database URLs, filesystem paths or arbitrary targets. Canonical export belongs to the CLI (ADR 0030), never an app Save action.
- **Persistence crosses the app through one aggregate-aware contract.** `SpaceBackend` and the stored `SpaceResourceRepository` both expose lazy `loadSpace`, complete `loadAggregate`, and one non-empty `commit({ changes })`. Each uniquely named change creates a snapshot, updates one at its expected revision, or deletes one at its expected revision. One update remains the ordinary `SpaceSession` path; topology edits use the same operation rather than selecting a second persistence method. Success returns every assigned revision and deleted id, conflicts return all mismatched current values, and complete-intake refusals carry stable aggregate error identities and locations. The PostgreSQL adapter serialises integrity-affecting transactions on the singleton repository-state row that owns `metaSpaceId`; memory applies the same candidate validation atomically. A candidate is accepted only by `loadSpaceAggregate`: every Space passes normal intake, Space/Card identities and Space Card selections resolve, Meta is the sole root, convergence is legal, and cycles, dangling targets, duplicate aggregate-wide Card ids and unreachable ordinary Spaces are refused. A proposed deletion that authoritative state still references is a conflict, not an aggregate refusal, so its caller reloads instead of inventing an aggregate revision.
- **Space Card lifecycle is the only multi-Space Edit interface (ADR 0076).** The registry exposes the three domain operations through `spaceCards(newId)` — create a Space Card with a new target, link one to an existing target, and delete one with the zero-reference cascade — and exposes no generic coordinated snapshot-submit operation. Coordination is private. It raises one browser-wide persistence barrier, waits for commits already in flight, then derives every participant and expected revision from the latest authoritative working sessions. The complete candidate passes normal Space and aggregate intake before every participant is installed atomically and published; the barrier remains raised until the repository answer settles, so an ordinary commit cannot overtake the topology Edit. Later ordinary Edits remain authoritative queued work rather than being overwritten by a stale coordinated snapshot. Deleting the last reference decrements references through the newly unreachable closure and deletes that closure in the same change set; convergence keeps a target alive while any reference remains.
- **A coordinated Edit has one persistence outcome and one recovery.** A successful repository answer must acknowledge every changed or created participant exactly once and every requested deletion, or it is a protocol rejection; locally installed created sessions become acknowledged and deleted sessions leave only after that complete answer. Retryable failure, conflict and permanent rejection are installed across all participants together. Retry resubmits the newest complete local Edit, including ordinary Edits queued behind it; Keep local and Accept stored resolve a conflict for the whole participant set rather than one Space at a time. Thrown calls, malformed results and observer failures cannot strand the barrier: every participant leaves coordination in an explicit failed, conflicted or rejected state, and a later valid Edit may supersede a permanent rejection.
- **A session submits complete snapshots after completed edits.** It allows one commit in flight, coalesces waiting edits to the newest snapshot, chains the committed revision into the next optimistic write, and exposes pending, retryable failure, permanent rejection and conflict states. Persistence is totally asynchronous: Edit completion relies only on `submit` installing the local working snapshot synchronously, never waits for backend acknowledgement, and immediately selects the resulting Layout from that local state. Accepting remote replaces the session snapshot through Space Authoring rather than remounting: `acceptStoredSpace` validates the stored snapshot first, then installs the session, placement and a fresh Navigation together and advances `replacementEpoch`, which is what makes the render adapter drop the projection and drag bookkeeping so no store retains stale local positions. Graph activation is not an edit and does not submit.
- **Session notification is non-throwing, and a submit made from an observer is queued rather than re-entered.** An observer that throws cannot interrupt the publisher: `publish` contains each listener's failure, hands it to `SpaceSessionOptions.reportObserverError` (defaulting to `console.error`) and carries on to the remaining observers, so persistence, the working Space and any reentrant Edit completion all continue. The reporter is wrapped too, and unlike `@project/http`'s `invokeLogError` it never rethrows — nothing above a notification could handle the failure. Separately, an observer *may* legally submit the next Edit while the publishing submit is still on the stack, so **`submit` decides from `state.working`, never from its argument** — a reentrant call runs to completion first, and deciding from the argument queues the older snapshot behind the newer one and stores it last, undoing a completed Edit at the next load. Nothing suppresses a nested call to stop it double-committing; identity against the in-flight snapshot answers that at any depth. **Don't replace it with a guard scoped to a call's publication**: `retry` and `resolveConflict` publish `pending` from *inside* an optimistic publication, and a submit answering that notification has a commit to wait behind while the call underneath it is gated on the failure it published under and will decide nothing — the newest Edit then reaches no queue at all and the session reports `settled` without it. All of this is pinned in `session.test.ts`.

## Space Authoring's completed-edit lifecycle

- **Every semantic operation answers `completed`, `unchanged` or `refused`, and the three are not interchangeable (ADR 0042, refined by ADR 0057).** `AuthoringCompletion` is one discriminated union naming the completed authored fact an interaction knows — identities and a settled value, never a plan — and `complete` is the one operation over all of them. **`unchanged` is the value the author already authored** and is a surface's ordinary close. **`refused` carries a stable discriminated identity and typed domain context; application composition owns its wording, field placement and recovery.** ADR 0057 is built through Authoring, UI and HTTP; `docs/agents/http.md` owns the wire rules. A broken invariant is neither and still throws. `edgeEligibility` is the proposal-shaped query behind every Edge gesture and returns the same structured refusal the completion re-asks. Domain tests assert refusal codes and context; presentation tests assert prose and accessibility. `space-authoring.property.test.ts` continues to hold every non-Edit to leaving the working snapshot's identity alone. The exact per-action guard/check order and all 22 refusal codes are tabulated in `docs/agents/authoring-refusal-cascade.md` — read it before adding an action, a check, or a refusal code.
- **Authoring installs a completed Edit atomically.** `deriveCompletedEdit` computes and validates the complete next snapshot before effects. `installCompletedEdit` submits that snapshot first, then moves placement and Navigation together to the Layout and Active Graph the Edit produced. `continueInLayout(layoutId, activeGraphId)` keeps that pair valid as one operation. The surviving operation and property tests in `space-authoring-operations.test.ts` and `space-authoring.property.test.ts` cover this sequence.
- **The install gate counts depth, publishes in the `finally`, and contains a drained completion's failure.** Both windows (completion and `acceptStoredSpace`) run through `installTogether`, which raises the `installing` gate and **publishes in the `finally`**: the gate means Authoring's publication is the only one a subscriber gets, so a publication skipped by a throw left `getState()` answering the pre-Edit state permanently, until an unrelated notification happened along. That is not a `catch` — the failure still reaches the caller. **The gate counts depth and is not a boolean**, because the windows nest: `acceptStoredSpace` notifies from inside its own, when `session.acceptRemote()` publishes before the placement, Navigation and `replacementEpoch` have moved, and an observer is as entitled to complete an Edit from there as it is to submit from a session notification. A flag is cleared by the inner `finally`, and the rest of the outer sequence then publishes every part-way state the window was raised to hide, including the accepted Space carrying the `replacementEpoch` of the Space it replaced. Only the outermost window publishes. Separately, a completion the drain *reaches* is contained — its failure is reported and draining stops there, because the Edit that drained the queue had already installed and published and must not be charged someone else's failure. Completions still queued behind that failure are discarded, and that too is reported. What is **not** contained is a throw from the Edit the caller made itself: treat that as an unhandled case, and restoring the guarantee means making the sequence total, not adding a `catch`. **The drain also gates on ADR 0042's `replacementEpoch`** — the counter formerly called `opening`, which is one counter and not two: each entry records the epoch current when it was enqueued, and the drain discards, without deriving, any entry whose epoch differs. Refusing would not save it, since the identities usually still exist in the replacement and nothing would reject the completion — it would write an abandoned gesture over the Space the author has just accepted. The discard skips rather than stops, because a completion queued from inside the accept's own publication carries the new epoch and is the one the ADR says must still be honoured, and it reports once per drain through the same `safelyReport`. **This is where that argument is written out** — the drain comment, the ticket and both tests point here rather than restating it, and a fifth copy is a drift risk, not thoroughness. Interaction-draft invalidation, 0042's other half, reads the same epoch and is **unevenly built rather than unbuilt**: two of the four drafts the ADR names — a picker's unconfirmed target, an armed destructive control — do not exist to invalidate, and of the two that do, every gesture but React Flow's connection attempt is discarded on every replacement already, by a subtree unmount, Navigation's reset and the render adapter's own epoch reset, behind a `key={replacementEpoch}` that is currently redundant — the connection attempt is the exception, its document listeners outliving every unmount. `packages/app/test/replacement-invalidation.test.tsx` is the ADR's one shared contract test and pins that discard for the two drafts the app's only trigger can leave open, an inline title draft and an in-flight drag. The older pane draft no longer exists; the conflict fixture cannot stage an opened Markdown draft because opening is authored and raises its waiting conflict. What genuinely remains is that question, the focus effect, which cannot tell a replacement from a pane close, and two survivors behind a trigger no input reaches — `.scratch/interaction-draft-invalidation/issues/02-interaction-draft-invalidation-is-mostly-already-covered.md` has the argument and the product questions it waits on. All of it is pinned in `space-authoring-operations.test.ts`.
- **Layout resolution answers one authored Layout, from one module.** `layout-resolution.ts` in `app` exports exactly four names: `requireDefaultLayout` (the Space's opening selection, throwing when it has none), `resolveLayout` (the Layout an id names, defaulting through it and throwing when the id names nothing), `layoutCards` (the Space's own Card objects for that Layout's members, in `space.cards` order) and `LayoutNotFoundError`. It answers `@project/graph`'s `ResolvedLayout` unchanged — there is no aggregate wrapping it, and no injected resolver: Navigation, Space Authoring and the canvas all import `resolveLayout`. Card membership comes from position keys (ADR 0040) and a Layout's owned Graphs are read off the Layout, so a Card or Graph outside it cannot appear through another rendering path. The positioned strategy is built at its one consumer. Automatic strategies remain non-addressable capabilities.
- **A completed edit persists automatically (ADR 0030).** The editor first installs its authoritative completed state and synchronously emits a payload-free `EditCompleted` notification. Edit completion derives and validates the complete current `SpaceSnapshot`, submits it to `SpaceSession`, and immediately selects its resulting Layout; intermediate drag frames never reach persistence. The session status (`Persisting…`, `Persisted`, retry, rejection or conflict) is the persistence indicator. There is no Save button, keyboard Save command or browser file write-back. The `beforeunload` guard is registered only while persistence is not settled — an always-attached handler would cost the page its bfcache. It calls `preventDefault()` and nothing else; `event.returnValue = ''` is deprecated and lint rejects it.
- **A completed Resize at the exact Closed rect is Close (ADR 0066).** The application owns the magnetic interaction range and turns an in-range two-axis proposal into that exact rect before completion; Space Authoring owns the semantic decision. It changes `open` to false without replacing the remembered `openSize`, so release submits one Close Edit and reopening after reload restores the pre-gesture Open Size. A proposal sharing only the Closed width or height remains an ordinary Resize. React Flow wiring never completes Close directly.
