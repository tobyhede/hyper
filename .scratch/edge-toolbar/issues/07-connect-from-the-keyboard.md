# 07 — Connect from the keyboard

Status: resolved

**What to build:** A Connect icon on a Resource's toolbar that opens `ResourcesPopover` (the Dock's Resources list), reused with row dragging disabled and its Spaces source off, over the Map's **placed** Resources bar this one. Refused ones stay listed, disabled, with their reason, through the same Edge eligibility pointer Connect uses. A final "New Resource" row creates a Markdown Resource beside this one and connects to it — the keyboard form of Alt-drop. The Edge is created in the Active Graph, from this Resource to the chosen one; focus then lands on the new Edge, selected, so Enter reaches its toolbar.

**Why:** With reconnect dropped, drawing an Edge is the one way to change one, and it must be reachable without a pointer (ADR 0073). A keyboard connect existed (`keyboard-connect` draft, a "Connect to" combobox) and went out in `1212feb88` with the expanded-cards integration, apparently as collateral; `70c60e4fc` holds its tests.

- [x] `ResourcesPopover` today lists what the Map does **not** place; Connect needs it over placed Resources, with dragging and the Spaces source off. Unplaced Resources are not offered — placing and connecting in one Edit is out of scope.
- [x] The kind filters and search carry over.
- [x] AGENTS.md's "Choosing a Resource has one component" note, which names `ResourceSearchCombobox`, is updated to say which surface chooses a Connect target.

## Answer

Built. A Resource's rail carries **Connect** (Lucide `Spline`, `ConnectIcon`), first in its shared group, on every Resource the canvas lets the author edit. It opens `ResourcesPopover` in a new `connect` purpose (`ResourcesConnectingProps`); the Dock's list is the `place` purpose and is unchanged.

- **What it lists.** The Map's placed Resources, not counting the source. Every row is asked the pointer gesture's own eligibility through `connectChoices` in `edge-authoring.ts`: `connect` for each Resource, `create-and-connect` for the New Resource row. A refused row stays listed and unavailable, with its reason under its name. It stays focusable (`focusableWhenDisabled`), and the reason is its accessible description. Unplaced Resources are not offered, and neither is the source itself, although self-Edges stay legal by handle.
- **Filters and search carry over.** The kind toggles drop the Spaces source. Rows cannot be dragged. New Resource comes last and ignores search and filters.
- **Completing.** `EdgeAuthoring.connectTo(from, target, projected)` completes through `connection-completion.ts`. A Resource target draws `connected-resources`. The New Resource target draws `create-and-connect` with `position: 'beside-source'`, which Space Authoring places when the Edit is derived. It goes right of the source's drawn rect (Open Size included), plus half a collapsed width, with the top edges level, using `avoidingOverlap`. On completion it requests `{ target: { kind: 'edge', graphId: <Active Graph after the Edit>, edge }, select: true, then: 'focus' }`. A refusal comes back to the list, which keeps it in an `Edge not drawn` alert. It is not published on Edge Authoring's canvas channel.
- **Focus.** The connect list unmounts its popup in the same commit as its close, and it declines the trigger's `finalFocus` after a completed choice. The first version relied on Base UI's own close. During the exit frame Base UI parked the caret on the popup, and an Edge to a Resource already on the canvas drew inside that frame. `CanvasContinuation` then found focus held and spent the continuation without focusing anything. Escape still returns to Connect. The popup also stops keydown, click and pointerdown from travelling the React tree to the rail's toolbar and React Flow's node.
- **Opening selects the source.** That keeps its rail revealed while focus is in the portalled list.

**A consequence for the rail.** A closed Resource's revealed rail now runs from the trailing edge to past the middle of the header: Actions, Edit, Connect, Open. That is where the e2e `dragBy` helper used to grab, and a press on a command drags nothing (`nodrag`), so the helper now grabs a quarter of the way in. Two e2e tests assert the rail's order and now include Connect: `editing.spec.ts` for an open Markdown Resource, and `space-resource.spec.ts` with its Ladle twin `space-resource-embedded-map.spec.ts` for the arrow order. A pointer author grabbing the middle of the header will now hit Connect while the rail is revealed. **Settled** — see the comment below: Connect moved to the Actions menu, and the rail, the grab point and the rail-order assertions are back to what they were before this ticket.

**Deviation.** There is no `keyboard-connect` draft. A choice is one press from open to Edit, and whatever would invalidate a draft disposes of the list instead. The list is the canvas's, not the rail's, so the rail unmounting does not take it: a replacement remounts `SpaceCanvas`, which is keyed on the replacement epoch, and `SpaceCanvas` itself closes the list when another Map is selected or authoring is withdrawn (presenting included), without reopening it when authoring returns. `resource-rail-actions.test.tsx` holds the Map and presenting cases.

**Docs.** AGENTS.md's "Choosing a Resource" note now names `ResourcesPopover` as the Connect target chooser. It says `ResourceSearchCombobox` has no consumer and is recorded in the inventory. `docs/agents/rendering.md` no longer says there is no keyboard Connect. `docs/agents/ui.md` records how the connect purpose's dismissal and focus differ.

**Evidence.**
- Unit tests: `edge-authoring.test.ts` covers the choices, including a property test that each row agrees with `accepts`, and the connect, refusal, beside placement for closed and Open sources, and the Active Graph continuation.
- Component tests: `ResourcesPopover.test.tsx` covers the connect purpose, `CanvasResource-rail-toolbar.test.tsx` the slot, `canvas-resource-decoration.test.ts` the gating, and `resource-rail-actions.test.tsx` the rail-to-Edit wiring.
- Three parity claims on `Space/Edge Toolbar`: `resource-connect-draws-an-edge-from-the-keyboard`, `resource-connect-keeps-refused-targets` and `resource-connect-creates-a-new-resource`. They are proved in `ladle-e2e/resource-connect.spec.ts` and `e2e/keyboard-connect.spec.ts`.

## Comments

**Connect moved from the rail to the Actions menu** (the user's decision). On the rail it made a closed Resource's revealed rail reach past the middle of the header, which is where a Resource is grabbed to drag it, so a press there landed on a command. It is now **Connect to Resource**, with the Graph glyph (`GraphIcon`, Lucide `Route`), in a group of its own in the Resource's Actions menu, second after Create Reference: the two commands that author something from this Resource lead, and the addresses and the leaving commands follow as before. `SpaceCanvas` builds the group, because Edge Authoring and the placed Resources meet there, and hands it to `App`'s `resourceRailActions`, which places it among the others. So it appears on every Resource that has an Actions menu and only where authoring is on, the gate the `connect` slot had.

- **One list per canvas.** `ResourceConnect` is mounted once by `SpaceCanvas` and opened for one Resource at a time. The list has no trigger. It hangs from the Actions trigger whose menu ran the command: an `EntityAction`'s `onSelect` is now handed the element its menu was opened from (`opener`), and `ResourcesPopover`'s connect purpose takes it as `anchor`. Choosing the item still selects the Resource, which keeps the rail, and so the anchor, revealed.
- **Focus.** The list takes the caret into its search, whether the menu was opened by keyboard or pointer. The menu's own return to its trigger does not win that hand-off: Base UI returns a closing menu's focus only when focus was still in the menu, or on the body (`keyboard-connect.spec.ts`, `Connect opens by pointer with the caret in the search, and stays open`). Escape returns the caret to the Actions trigger. A drawn Edge still declines that, and so do an outside press and a focus-out, because the caret is already where the author put it.
- **Removed:** the rail's `connect` slot (`CanvasResource`, `ResourceNodeData`, the decoration and `useCanvasResourceAuthoring`), `ConnectIcon` (Spline), and the Dock-only trigger props from the connect purpose's type. The e2e `dragBy` helper grabs the middle of the header again. `editing.spec.ts`, `space-resource.spec.ts` and `space-resource-embedded-map.spec.ts` assert the rail without Connect.
- **Found on the way.** When the list was mounted in the rail, Tab went from its search straight to the rows, as the old keyboard proofs asserted. Mounted outside the rail, Tab stops once at the kind filters first, as in the Dock's list, and the two keyboard proofs now Tab through them. A likely cause is the rail's Toolbar context reaching the filter toggles through the React tree, but that has not been confirmed.
