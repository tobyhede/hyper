# 25: Run mutation testing in CI

**Status:** needs-triage — deferred by Toby Hede (2026-09-25) and excluded from the active queue (`../DECISIONS-2026-09-25.md`). The decisions below stay open until it is picked up again.

**Blocked by:** None; follows the Stryker decision in 13

**What to build:** A CI job that runs the StrykerJS campaigns, so the mutation findings stop depending on someone remembering to run `pnpm mutate:*` by hand. Ticket 13 recorded the decision to keep Stryker and run it in CI (2026-09-25); the CI half was then deferred.

This reverses a standing rule. AGENTS.md ("a deliberate local diagnostic, never a gate") and the comment at the top of `stryker.conf.mjs` ("run on purpose, never a gate … not in CI") say so outright; `docs/agents/build-tooling.md:9` calls it "a deliberate diagnostic" and a kept tool without stating the CI rule. It is not in `verify` or CI, `thresholds.break` is `null`, and the tickets that introduced it forbid a threshold (`.scratch/mutation-testing/`). The change therefore needs an ADR, and all three passages have to be updated in the same change.

**Report only, never required.** `../DECISIONS-2026-09-25.md` keeps mutation testing "outside mandatory CI gates" with no score threshold, and ticket 13's decision line says the same. So the job publishes its report and fails nothing: it is not an input to `CI passed`, and no score, survivor count or ratchet decides its outcome. A gate or ratchet would need that decision reopened first.

## To decide

- **What a report-only job surfaces.** It can upload the HTML report as an artifact, and it can also summarise the survivors in the job summary so they are read without downloading it. It must not fail the run on a score or survivor count.
- **Trigger.** Run on every push, or only when a campaign's `--mutate` or `--testFiles` paths change (`ci.yml` has no path filtering today, so this would be its first). Each campaign takes 17–37s locally, plus install.
- **Campaigns.** There are two today, `mutate:session` and `mutate:graph`. Each pairs its mutated files with an oracle chosen by hand, because the whole suite cannot run inside Stryker's sandbox (`test/unit`'s repo-meta test shells out to `git ls-files`). A CI job makes that pairing load-bearing. Decide whether anything checks that the pairing still makes sense.
- **Known false survivors.** `.scratch/mutation-testing/engine.md` records this runner's `static: true` false survivors. The published report should say so, so a reader does not take them for oracle gaps.

## Acceptance

- [ ] An ADR records the report-only, non-required job, its trigger and its campaign set, and amends the "never in CI" half of the rule while keeping "never a gate"
- [ ] A CI job runs the chosen campaigns on the chosen trigger and publishes the HTML report, and is not an input to `CI passed`
- [ ] AGENTS.md, `docs/agents/build-tooling.md` and `stryker.conf.mjs` describe the new arrangement
- [ ] `thresholds.break` stays `null`, and `ci-container-image-pin` and any other CI-shape test still pass
