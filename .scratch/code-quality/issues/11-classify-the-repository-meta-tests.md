# 11: Classify the repository meta-tests

**What to build:** A decision sheet covering every root unit test that inspects the repository rather than running product code — its documents, tracker, skills, CI config, source text or vocabulary. Each is classified as protecting a code boundary (keep) or policing document or tracker hygiene (candidate for deletion), with a one-line reason. A human decides each row.

**Blocked by:** None (can start immediately)

**Status:** ready-for-human

- [x] Every repository-inspecting test is listed, with what it guards and the last change it actually caught (from git history), if any
- [x] Each row has a recommendation: keep, delete, or fold into another test
- [ ] Each row has the human's decision recorded

## Method

Scope, widened by the review (`REVIEW.md`, rows 11–12): root `test/unit` **and** `packages/*/test`. A test counts as repository-inspecting when it reads source text, documents, tracker files, skills, CI or tool configuration, or git metadata, rather than executing product behaviour. Tests that write to a temporary directory and exercise product or script code are not meta-tests, even though they touch the filesystem.

1. Listed every tracked `*.test.ts(x)` outside `e2e/` and `ladle-e2e/` with `git ls-files` (258 files).
2. Grepped them for `readFileSync|readdirSync|readFile(|readdir(|git ls-files|execFileSync|spawnSync|execSync|import.meta.glob|?raw|existsSync|statSync|node:fs` — 49 hits.
3. Grepped the rest for repository targets reached by import rather than by `fs`: `package.json`, `.github`, `AGENTS.md`/`CLAUDE.md`/`CONTEXT.md`, `docs/adr`, `eslint.config`, `.oxlintrc`, `tsconfig`, the Playwright/Vitest configs, `.scratch`, `eslint-suppressions`, `new ESLint`, `ts.createSourceFile`. Most hits were comments citing a ticket; the real ones were added.
4. Grepped non-test helpers (`test/support`, `packages/*/test`) for the same reads, which found `test/support/structural-scan.ts`, and followed it to the five tests that import it.
5. Read each hit and dropped the ones that exercise behaviour over temporary directories (see *Excluded* below).
6. History, per file, with `git log --follow`: total commits, and "small co-edits" — commits after creation where the test diff was ≤12 lines while the commit touched ≥3 other files (a proxy for being edited alongside an unrelated change; renames such as `5a9d7161` and `631f3ba4` account for many). "Last catch" comes from commit message bodies that name the test beside *red / fail / caught / reported*; a test's own red-first creation is not counted as a catch. Catches made locally before a commit leave no trace, so "no evidence" means *no recorded catch*, not *never caught*.

For files that mix behavioural and inspecting tests (marked *partial*), the row covers only the named inspecting `it`/`describe`; the history columns are for the whole file and overstate the cost of the inspecting part.

Kinds: **boundary** — a structural rule of the code (imports, ownership, exported surface, retired types); **style** — a property of shipped CSS/HTML computed from source; **config** — tool, CI, build or lint configuration; **hygiene** — documents, tracker, skills, vocabulary or git state.

### Excluded after reading

These matched the search but exercise behaviour, not the repository:

- `test/unit/ui-catalog.test.ts`, `test/unit/roadmap.test.ts` — run the `ui:catalog` and roadmap scripts over temporary trees. The real-repo check is `pnpm ui:catalog:check` in `verify`, which is a script, not a test.
- `test/unit/anti-slop/*.test.ts` — unit tests of the custom lint rules over inline fixtures.
- `packages/app/test/space-files.test.ts` — loads the tracked fixture and example Spaces through `loadSpace`; it validates data by running product intake.
- `packages/app/e2e/read-only.spec.ts` — snapshots the fixture directory to prove an edit writes nothing back; behavioural.
- `test/unit/sqlite-dev-script.test.ts` — runs `scripts/dev-sqlite.ts`.
- Aggregate, CLI, export, import, env-path and runtime tests (`aggregate-round-trip`, `export-aggregate*`, `import-aggregate`, `read-aggregate`, `read-single-space`, `hyper-cli`, `hyper-command`, `prisma-postgres-env-path`, `sqlite-root-env`, `test/integration/*`) — `fs` against `mkdtemp` directories only.
- Tests importing `src/prisma/contract.json` or `src/sqlite/contract.json` as data (`sql-connection-failure`, `sqlite-space-repository`, the contract half of `prisma-sqlite-foundation`) — they feed the emitted contract to product code.
