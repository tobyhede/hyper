# 01: Command ids and one dispatcher

Status: ready-for-agent

ADR 0138. Depends on the keyboard-shortcuts stack (#426–#430), merged into `main` on 2026-10-28: the bindings, listeners, guards and tests named here are `main`'s, not this branch's. No behaviour changes: every key does what it does today.

**What to build.** Give each binding in `key-bindings.ts` a stable command id (`canvas.addResource`, `canvas.presentFromHere`, `presenting.advance`, `help.showShortcuts`, …) and a context: the canvas, Full View, presenting, or everywhere. Replace the canvas's four window `keydown` listeners (`SpaceCanvas.tsx`: `C`, `P`, `F2`, Delete), the presenting keys' listener (`presenting-keys.ts`) and the `?` sheet's capture-phase listener (`ShortcutSheet.tsx`) with one dispatcher per Space. It reads each press once, applies `keyBelongsElsewhere` and then the context's own guard (see Keep), finds the binding for the Space's current context, and runs the command registered for that id. Commands register a handler and an availability check (today's per-listener guards, such as `availability.present` and `spaceOnCanvas`); they never add a listener. The presenting keys move under the same dispatcher.

**Keep.** Some keys answer from fewer places than `keyBelongsElsewhere` allows. Delete, Enter, Space and Shift+Enter on a canvas Resource also refuse any target inside `NOT_A_CANVAS_COMMAND` (`.nokey`, `input`, `button` and the surfaces that own their keys, in `SpaceCanvas.tsx`), so a node's rendered content and toolbar keep those keys. A binding's context carries that narrower guard, and the dispatcher applies it after the shared one; applying `keyBelongsElsewhere` alone would let Delete fire from more places than today. The sheet still listens in the capture phase, because Full View stops every key pressed in it. A hidden open Space answers nothing, which is the bug #426 fixed for `P` (`SpaceApp.test.tsx`, "the P shortcut across open Spaces"). While Full View is shown, the canvas context answers nothing: today `C`, `P` and `F2` each check `latestFullViewShown` themselves (#427 review), and the dispatcher's context replaces those checks, so a command added later cannot act on the hidden Map.

**Not a command.** Edge Authoring tracks the Alt modifier with a window `keydown` and `keyup` listener while an Edge is being connected (`updateModifier` in `edge-authoring-react.tsx`). It binds no key and performs nothing, so it stays where it is, outside the keymap.

**Done when.** A test lists every window `keydown` listener the app adds and finds the dispatcher's and Edge Authoring's modifier tracking, and nothing else. The test names that one exemption and why, so a second listener fails it. The existing key tests and `packages/app/e2e/keyboard-shortcuts.spec.ts` pass unchanged. Each command id appears in exactly one binding.
