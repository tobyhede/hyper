# 01 — Decide whether to enable the React Compiler

Status: ready-for-human

**What to decide:** Whether this repo enables the React Compiler, or commits to
hand-memoization as the standing convention.

It is **not enabled**, verified four ways: no `babel-plugin-react-compiler` and no
`reactCompiler` key in `package.json`, in the application's Vite configuration or
in `pnpm-lock.yaml`. `packages/app/vite.config.ts` delegates to
`packages/app/database-vite-config.ts`, whose two targets (`:56`, `:76`) use a
plain `react()` plugin.

Two facts bear on the cost. React is `^18.3.1` (`package.json`), and the compiler
targets React 19 by default, so on 18 it also needs the `react-compiler-runtime`
package and a `target: '18'` option. And `eslint-plugin-react-hooks` 7 is already
installed with its recommended rules on (`eslint.config.js:242`), which include
the compiler-derived lint rules, so the code is already linted against what the
compiler would require whether or not it is enabled.

**The catalogue has its own pipeline, and it lacks the compiler too.**
`packages/app/.ladle/config.mjs` exists and points `viteConfig` at
`packages/app/ladle-vite.config.ts`, which deliberately does not reuse the
application configuration and carries `tailwindcss()` as its only plugin. So a
decision to enable the compiler is two configurations to change, not one — and
ADR 0052 makes that mandatory rather than optional, since a stable story is
production-parity evidence and a catalogue compiled differently from the
application is no longer evidence of what the application does.

This surfaced in the Command Dock prototype, where a derivation was written
un-memoized on the assumption the compiler would handle it, and had to be given
its `useMemo` back (`b7a2e3bf`). The choice was written into
`command-dock.stories.tsx` as an open decision, which was the wrong place for it —
it is a toolchain decision for the whole repository and it is filed here so it
stops being one prototype's footnote. `fad244874` has since removed that comment
from the story (now `packages/app/stories/space/command-dock.stories.tsx`).

- [ ] Decide. Either enabling is worth the toolchain change, or hand-memoization
      is the convention and reviewers stop asking.
- [ ] If enabled: it must reach the Ladle catalogue too, or stories and the
      application compile under different rules and a story stops being the
      parity evidence ADR 0052 says it is.
- [x] Either way, remove the open decision from the prototype source. Done in
      `fad244874`.

Note ADR 0061 before touching the toolchain: `tsc` is TypeScript 7 while the
package name `typescript` deliberately resolves to the TypeScript 6 bridge, and
`pnpm typecheck:toolchain` fails the moment that arrangement stops holding.
