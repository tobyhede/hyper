# 04 — An embedded Map's Edges honour their interaction width

**What to build:** The interaction width the embedding sets on an embedded Map's Edges takes effect, or is removed if it is not wanted. Today the embedding sets it to zero, but the routed Edge path forwards only the Edge's id, end marker and style to React Flow's base Edge, so the base Edge falls back to its default hit area of 20 and the setting does nothing.

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

**Tags:** Defect

**Surfaced by:** the design review for `typescript-7/13` (2026-09-23), while checking whether embedded Edges would render differently under their own Edge type. Not caused by that ticket.

## Decide first

Embedded Edges are also minted not selectable, not focusable, not reconnectable and not deletable, so it is not obvious a zero hit area is still needed. Establish what an embedded Edge's hit area currently intercepts — for example, whether it takes pointer events from the Open Space Resource or the canvas beneath it — and either:

- forward interaction width through the routed Edge path so the embedding's zero applies, or
- delete the setting and say here why the other flags make it redundant.

## Acceptance

- [ ] If kept: an embedded Edge's hit area matches what the embedding asks for, and an Edge of the Map on the canvas keeps its current hit area.
- [ ] If removed: the setting and any test pinning it are gone, and nothing it guarded regresses.

## Triage — 2026-09-23

> *This was generated by AI during triage.*

**Decision: delete the setting.** The maintainer confirmed it.

**Evidence.** The claim holds: `RoutedEdgePath` forwards only `id`, `path`, `markerEnd` and `style` to React Flow's `BaseEdge`, and `BaseEdge` defaults `interactionWidth` to 20. So the embedding's `0` never arrives, and it is the only use of the setting in the tree. No test pins it. But the 20-wide hit area intercepts nothing. React Flow gives an Edge's `<g>` the class `inactive` when the Edge is not selectable and the canvas has no `onEdgeClick`. Its stylesheet sets `.react-flow__edge.inactive { pointer-events: none }`, and that is inherited by the transparent interaction path inside the group, where nothing resets it. Embedded Edges are minted `selectable: false`, and `SpaceCanvas` passes no `onEdgeClick`. So an embedded Edge takes no pointer events, whatever its interaction width. Forwarding the width through `RoutedEdgePath` was rejected: it would widen the adapter's public path to enforce something that already holds for another reason.

## Agent Brief

**Category:** enhancement
**Summary:** Remove the ineffective zero interaction width from an embedded Map's Edges, and guard what actually makes them inert to the pointer.

**Current behavior:**
`embeddedMap` mints each embedded Edge with `interactionWidth: 0`. The routed Edge path never forwards interaction width, so React Flow draws its default 20-wide interaction path anyway. That path is inert only because the Edge's group carries React Flow's `inactive` class. The class comes from `selectable: false` together with the canvas having no Edge click handler, and nothing states or tests that.

**Desired behavior:**
- Embedded Edges are minted without `interactionWidth`. Every other flag the embedding sets stays as it is: `selectable`, `focusable`, `reconnectable` and `deletable` false, the z-index and the clip path.
- A test holds the real invariant: an embedded Edge's rendered group has React Flow's `inactive` class, so a press on or beside it reaches the Open Space Resource or the canvas beneath it. That test should fail if an Edge click handler is added to the canvas, or if embedded Edges become selectable. It belongs where embedded Edges are actually rendered (a Ladle embed spec, or an existing embedded-Map rendering test), not in a projection unit test.
- The canvas's own Edges are unchanged: selectable, with React Flow's default hit area.

**Key interfaces:**
- `embeddedMap`'s minted `Edge` objects lose `interactionWidth`.
- `RoutedEdgePath` / `routedEdgePathProps`: unchanged. Do not start forwarding interaction width.

**Acceptance criteria:**
- [ ] No embedded Edge carries `interactionWidth`, and nothing else in the tree sets it.
- [ ] A rendering test asserts an embedded Edge's group is `inactive`, and fails when that group is made selectable (non-vacuity checked by flipping `selectable` temporarily).
- [ ] The embedding bullet in `docs/agents/rendering.md` says what makes an embedded Edge inert to the pointer, if it does not already.
- [ ] `pnpm verify`, `pnpm e2e` and `pnpm e2e:ladle` pass.

**Out of scope:**
- Forwarding interaction width (or any other new prop) through `RoutedEdgePath`.
- Changing the canvas's own Edges' hit area or selection behavior.
- Anything about embedded Edge types or conversion to Edge selections (typescript-7/13, resolved).
