# 01 — A Resource with no kind is an Ur Resource

Status: ready-for-agent

**What to build:** ADR 0120's rule for a missing `kind`. Both frontmatter schemas stop defaulting `kind` to `markdown`. In `packages/core/src/schema.ts`, `defaultMarkdownKind` (:200-203) is applied by `resourceFrontmatterSchema` (:211-212) and by `importResourceFrontmatterSchema` (:237-238). A Resource file with no `kind` and no body is an Ur Resource. One with no `kind` and a body is refused at intake, as an Ur Resource with a body already is: `parseResourceFile` refuses it with `invalid-frontmatter` (`packages/graph/src/resource-file.ts:129`).

**Also in the same change:**

- Invert the test `defaults a resource with no kind to markdown, so the common resource declares neither` (`packages/core/test/schema.test.ts:300`) so that it asserts that a missing `kind` reads as `ur`.
- Correct the comments that state the old default. `schema.ts:208` says `kind` defaults to `'markdown'` "exactly as `resourceSchema` does", and `resourceSchema` has no default at all. The `serializeResourceFile` doc comment (`resource-file.ts:152`) says the reader defaults `kind`.
- `docs/aggregate-directory.md:128` gives `markdown` as "the default when `kind` is absent". That document is the authority the `hyper-authoring` skill defers to, so it changes to say that a Resource with no `kind` is an Ur Resource and must have no body.

**Roll forward in the same change (ADR 0054):** 23 tracked Resource files declare no `kind`: 17 under `packages/app/fixture/` and 6 under `packages/app/example/`. Each gets `kind: markdown` where a test reads, opens or presents its document. Otherwise it becomes an Ur Resource with its body removed. To settle which is which, search the unit, E2E and Ladle tests for each file's Title and body text. The `hyper-authoring` skill says that a Resource with no `kind` is an Ur Resource and that a Markdown Resource declares `kind: markdown`.

**Acceptance:**

- A Resource file with no `kind` and an empty body loads as an Ur Resource, through both `resourceFrontmatterSchema` and `importResourceFrontmatterSchema`.
- A Resource file with no `kind` and a non-empty body is refused at intake with `invalid-frontmatter`, naming the body.
- Every tracked Resource file loads, and every test that read a fixture's document still finds it.
- Export of an Ur Resource round-trips through Import.
- `docs/aggregate-directory.md` and the `hyper-authoring` skill state the new rule, and no comment in `schema.ts` or `resource-file.ts` still says `kind` defaults to `markdown`.
