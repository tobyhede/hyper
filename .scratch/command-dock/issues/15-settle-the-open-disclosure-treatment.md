# 15 — Settle the open-disclosure treatment, which now reaches every ghost trigger

That belongs on the shared quiet Button recipe, keyed off `aria-expanded`, not

**Both premises still hold**, checked at `37e44bc2`: `packages/ui/src/Button.tsx`

## What happened

`07`'s adversarial review found the Command Dock still owning Button appearance
through application selectors — `command-dock.css` overrode the open
disclosure's foreground and background, and the parent crumb's foreground, over
controls the shared recipe draws. That breaches the styling rule
(`className` for layout, not styling) and left a second owner of Button
appearance after the Space-name typography pass.

Both rules also won only by load order, which is worth recording because it
means neither was ever a deliberate override: `.command-dock__crumb` carries
specificity (0,1,0) and merely *tied* Tailwind's `text-muted-foreground`.

The fix moved both into `packages/ui/src/Button.tsx`: an `aria-expanded` state
on the shared quiet recipe, and a new `receded` variant for the crumb. Keying
the open state on `aria-expanded` was chosen deliberately, because it preserves
the property the deleted rule had — a control added later is covered without
being told.

## The consequence, which is this ticket

`aria-expanded` on the shared recipe reaches **every** `ghost` disclosure
trigger, not only the Dock's. Two candidates were checked at the time:

- `CardSearchCombobox`'s trigger swaps for the Clear button when open, so it
  takes no fill and is unaffected.
- `SelectedEdgeControls`' **"Edit this Edge"** popover trigger now fills while
  its editor is open. This is a visual change to a surface outside the Dock,
  and it was neither asked for nor reviewed as part of `07`.

It was judged correct rather than a regression — a trigger with something open
reading as open is the rule the ADR text already argues for — and `07` shipped
on that judgement. **That judgement is the thing to confirm or overturn here**,
which is why this is `needs-triage` and not `ready-for-agent`: the work is small
either way and the decision is the whole of it.

## The two answers

**Keep it.** The rule becomes application-wide: a ghost disclosure trigger
reads as open while it is. Then this ticket's work is evidence rather than
change — `SelectedEdgeControls` gains a claim and a story showing the open
treatment, because right now the behaviour ships with nothing asserting it.

**Narrow it.** A dedicated `disclosure` variant carries the open state and
`ghost` goes back to being inert. This was the alternative at the time and was
not taken for a reason that no longer applies: it needed call-site changes in
`App.tsx` and `command-dock-triggers.ts`, both outside the ownership of the
agent doing the work. It also loses the "covered without being told" property,
so every future disclosure trigger has to remember to opt in.

## Evidence

A production surface and a story, so all three bars: `pnpm verify`, `pnpm e2e`,
`pnpm e2e:ladle`. The third is the only one that can see a story left behind.

## Agent Brief

**Category:** enhancement
**Summary:** Confirm the application-wide open-disclosure treatment with
evidence on the Selected Edge Edit trigger; do not change the Button recipe.

**Current behavior:**
The shared quiet Button recipe (`ghost` and `receded`) fills on
`aria-expanded`. Command Dock disclosures and an Open Space Thing's
`ChoiceMenu` already take that fill. The Selected Edge "Edit this Edge"
trigger does too, because it is a popover trigger. Nothing claims or stories
that the trigger *looks* open. Ladle already asserts `aria-expanded` on Edit;
it does not assert the fill.

**Desired behavior:**
The rule stays: a quiet disclosure trigger reads as open while it is, at
hover-weight fill and ink, not as a selected mode. A future disclosure
trigger is covered without opting in. The Selected Edge closed and open
stories, plus a parity claim, make that visible and dual-proved (ADR 0052).

**Why Keep, not Narrow:**
Current shadcn Button recipes put `aria-expanded` fill on `ghost` itself.
WAI-ARIA APG styles disclosure visuals from `[aria-expanded]` so paint cannot
drift from the announced state. Base UI emits `aria-expanded` on the trigger
and `data-open` on the popup — styling `data-open` on the Button would miss.
A `disclosure` variant would recreate the opt-in / second-owner problem `07`
ended. No ADR: this is UI treatment (workflow: ephemeral).

**Key interfaces:**
- Quiet Button feedback — already carries the open state; do not add a
  variant and do not move the selectors onto a surface stylesheet.
- Selected Edge Edit — a `ghost` popover trigger; the closed story is the
  resting control, the open story is the same trigger with the editor up.
- Parity inventory — a new claim that the open trigger reads as open, with
  Ladle and application evidence.

**Acceptance criteria:**
- [x] A parity claim states that a selected Edge's Edit trigger reads as
      open while its editor is open.
- [x] A stable story mounts the production Selected Edge controls in that
      open state (existing EndpointEditor may already be the mount; the
      claim must name it).
- [x] Ladle evidence observes the open treatment, not only `aria-expanded`.
- [x] Application evidence covers the same claim, or records why a browser
      gesture cannot see the fill and where the dual proof lives instead.
- [x] The quiet Button recipe is unchanged: no `disclosure` variant, no
      removal of `aria-expanded` from the shared feedback.
- [x] `pnpm e2e` and `pnpm e2e:ladle` are green. `verify:static` is
      green. Full `test:coverage` flaked on untouched files that pass in
      isolation (see Answer).

**Out of scope:**
- Changing Button variants, tokens, or the receded crumb.
- Restyling Command Dock disclosures or ChoiceMenu.
- Narrowing the rule to an opt-in variant.
- An ADR.

## Answer

Keep. The quiet recipe is unchanged. Evidence is the new parity claim
`selected-edge-edit-trigger-reads-as-open` on the existing EndpointEditor
story: Ladle and application both assert the Edit trigger's computed
background equals resolved `--secondary` while the editor is open, and that
its unexpanded neighbour does not.

Red first: stripping `aria-expanded:bg-secondary` from the quiet recipe made
the Ladle assertion fail (transparent vs `rgb(236, 237, 237)`). Restoring it
went green. Button.tsx is byte-identical to `main`.

**Bars.** `pnpm e2e`: 191 passed. `pnpm e2e:ladle`: 85 passed.
`verify:static` (toolchain through format:check, including the catalogue):
green. Full `pnpm test:coverage` timed out on untouched jsdom files
(`space-thing-embedded-diagram`, `space-set-freshness`, `dock-commands`) that
pass in isolation; those files are not in this diff.
