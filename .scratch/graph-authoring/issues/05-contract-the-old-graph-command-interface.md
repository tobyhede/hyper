# 05 — Contract the old Graph command interface

Status: resolved
Blocked by: 04

**What to build:** Make the Command Dock and the Open Space Resource rail consume only the Graph authoring capabilities. Delete `coordinated-context-create.ts`, the Graph arm of `coordinated-context-delete.ts`, `runGraphEdit`, `DockGraph.editsDisabled`, the rail's `deleteDisabled`, and the second command shape in `SpaceResourceSelectors` so Map and Graph commands reach `@project/ui` in one shape. Remove App-mount Graph tests whose rule the contract suite now holds. See `../spec.md`.

**Why:** Tickets 02–04 expand the new form beside the old so each lands green; this completes the refactor, as `.scratch/command-outcomes/issues/09` did for Maps.

- [x] Each surface derives a Graph command's unavailable treatment and invocation from one capability; no separate flag can disagree with it.
- [x] `coordinated-context-create.ts` is deleted; `coordinated-context-delete.ts` is deleted or holds nothing Graph-specific.
- [x] `SpaceResourceSelectors` takes one command shape for both selectors; `ui` still names no app type.
- [x] Superseded tests are removed (`graph-delete-notice.test.tsx` and the Graph cases of `space-resource-context-commands.test.ts` are the candidates); tests proving distinct surface treatment remain.
- [x] The deletion test holds: removing the Graph module would redistribute availability, the last-Graph rule, persistence ordering, the survivor rule and report translation across both callers.
- [x] `pnpm verify`, `pnpm e2e` and `pnpm e2e:ladle` green.

- **`completeEmbedded` retired from the rail.** `SpaceResourceRailContext.complete` (unread since 03), `CanvasResourceDecorationContext.completeEmbedded` and its wiring in `canvas-resource-authoring.ts` / `canvas-resource-decoration.ts` are deleted, and the two tests stop supplying them. `completeEmbeddedAuthoring` is no longer exported: `createEmbeddedAuthoring` is its one caller. - **Tests removed, and where their rule lives.** `graph-delete-notice.test.tsx` (a refused Dock deletion says "Graph not deleted", and the next completed attempt clears it): the report is `graph-authoring-commands.test.ts`'s "answers a refused deletion with the complete Graph report, which command outcomes holds"; the clearing is `command-outcomes.test.ts`'s `graph-delete` block (refused, then completed, leaves no notice). - **The deletion test holds.** Both callers now hold only presses: `dock-chrome.ts` spends `offered(activeGraphCommands.rename|recolor|delete, …)` and `offered(mapGraphCommands.create, …)` into `commandOutcomes.run('graph-edit' | 'graph-create' | 'graph-delete', …)`; `space-resource-context-commands.ts` does the same over `embeddedGraphAuthoringCommands`, adding only the row colour and Copy link. Remove `graph-authoring-commands.ts` and each would get back: general availability and addressing (the Active Graph of the selected Map at the top level; any owned Graph while the entry is current, embedded); the last-Graph rule at read and at invocation; the embedded settled/recheck prologue, the target wait, the selection write and the containing wait; the survivor preference (`preferredSurvivor`); and the translation of refusals and failed waits into "Graph unchanged", "Graph not created", "Graph not saved", "Graph not selected" and "Graph not deleted". No separate flag remains beside any Graph press on either surface to disagree with its capability.
