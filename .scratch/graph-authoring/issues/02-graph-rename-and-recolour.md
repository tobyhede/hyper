# 02 — Graph rename and recolour through both context adapters

Status: resolved
Blocked by: 01

**What to build:** Introduce `packages/app/src/graph-authoring-commands.ts` with `map(mapId).graph(graphId)` answering synchronous `rename` and `recolor` capabilities, and a public constructor per context (`topLevelGraphAuthoringCommands`, and the embedded one) built over one private definition of each context shared with the Map module — addressing, completion, before/after waits — extracted from `map-authoring-commands.ts` in this ticket. Top level addresses only the Active Graph of the selected Map; embedded addresses any Graph of the target while it is the open entry. `graph-edit` becomes a reported channel: Graph authoring owns "Graph unchanged" and its message. See `../spec.md`.

**Why:** Rename and recolour are the synchronous slice, so they prove the interface and the shared context before asynchronous coordination joins it — as ticket 06 of `.scratch/command-outcomes` did for Map rename.

- [x] Both surfaces spend rename and recolour through `offered`; the Dock's rename gate stays `chromeTitleEdit` and recolour's stays `entityEdits`.
- [x] Invocation rechecks Graph existence and addressing (and, embedded, entry identity); a stale invocation answers `unavailable` and publishes nothing.
- [x] A refused rename or recolour returns the complete report; `graph-edit` holds and dismisses it. The rail's local sentence for these is gone.
- [x] A refused rename is said twice on both surfaces: inline (the editor holds the draft) and as the `graph-edit` notice. The Dock's Graph branch of `renameChromeTitle` goes.
- [x] `graph-authoring-commands.test.ts` runs a rename and a recolour contract against both adapters, plus what each context addresses; a source scan holds that the module imports no continuation, React or DOM.
- [x] The Map module's contract suite still passes over the shared context.
- [x] `pnpm verify`, `pnpm e2e` and `pnpm e2e:ladle` green.

## Comments

**2026-09-26, resolved.** `pnpm verify` green (256 files, 3493 passed, 19 skipped). `pnpm e2e` green (233 passed) and `pnpm e2e:ladle` green (127 passed); no e2e or story asserted on text this changed.

- **The shared context lives in `packages/app/src/authoring-contexts.ts`**, a sibling of both modules rather than a part of either. It holds `AuthoringContext` — `space`, `current()` (always at the top level; embedded, `spaces.entry(target.id) === target`), `addressesMap`, `addressesGraph`, `complete(mapId, completion)` and `coordination` — and its two constructors, `topLevelContext(space)` and `embeddedContext(embedded)`. `coordination` is `null` at the top level; embedded it is the neutral waits (`settled`, `targetSaved`, `containingSaved`) and `select`, each answering a boolean or a sentence, so the reports a failed wait is said in stay each module's own ("Map not created", "Map not saved", ...). `AuthoredSpace`, `AuthoringApp` and the embedded input moved there too; the input is renamed `EmbeddedAuthoring`, because `EmbeddedMapAuthoring` is also the React component's name. `CompletedMapEdit` stays in the Map module.
- **The Map module now builds on it.** `MapCreation`/`MapDeletion`/`MapAuthoringContext` are gone; `createMap` and `deleteMap` read `context.coordination`, and embedded creation's entry check is now the core's `available.create() && context.current()`. The Map contract suite passes unchanged.
- **`completionOutcome(result, title)`** joins `authoring-commands.ts`: the synchronous `AuthoringResult`-to-`EditOutcome` translation both modules' rename (and Graph recolour) spend, `queued` answering `completed` as before.
- **The Graph module.** `graph-authoring-commands.ts`: `GraphAuthoringCommands { map(mapId): { graph(graphId): { rename, recolor } } }`, `GraphAuthoringAvailability { rename, recolor }`, `topLevelGraphAuthoringCommands(space, available)` and `embeddedGraphAuthoringCommands(embedded)`. Top level addresses the selected Map's Active Graph only (read from Navigation, and owned by the Map); embedded addresses any Graph a Map of the target owns while the target is the open entry. Refusals report under "Graph unchanged".
- **Command outcomes.** `graph-edit` is a reported channel whose result is `EditOutcome`; a throw on it reaches the reporter and leaves the channel clear, as for Map channels. The Dock's New Graph still runs the old path until ticket 03, so it is a transitional command, `graph-add`, on the `graph-edit` channel that says an `AuthoringResult` refusal (and a break) under "Graph unchanged" itself. Ticket 03 deletes it with the `graph-create` channel.
- **Surfaces.** `DockGraph.onRename` is `((title) => string | null) | null` and `onRecolor` `((color) => void) | null`, both addressed to the Active Graph and built through `offered`; the gates stay `chromeTitleEdit` and `entityEdits`. `renameChromeTitle` is now `renameSpace`, and `runGraphEdit` is gone (creation calls `run('graph-add', ...)` directly). `GraphMenuActions.onRecolor` is nullable and disables Colour… itself; `editsDisabled` now governs New Graph only. The rail's `CanvasSpaceResourceGraphCommands.onRename`/`onRecolor` are the same nullable presses and say nothing on the rail; `SpaceResourceSelector` withholds recolour while the rail is disabled or busy, as it does rename.
- **Tests.** `graph-authoring-commands.test.ts` runs rename and recolour contracts against both adapters (completed, unchanged, refused with the complete report held and dismissed by command outcomes, withdrawn and vanished-Map unavailable with no publication), what each context addresses (top level: not a non-active Graph, not after another is activated, not a Map moved off, rename and recolour withheld separately; embedded: any owned Graph of any Map without moving the canvas, not a Graph the Map does not own, not through an exited entry), and a source scan for continuation, React and DOM. App coverage: `SpaceApp.test.tsx` holds a refused Dock Graph rename open and reports it as "Graph unchanged"; `space-resource-embedded-map.test.tsx` does the same for the rail on the containing Space.
- **For 03–05.** `AuthoredSpace.spaceResources` is `Pick<..., 'deleteMap'>`; ticket 04 widens it to `deleteGraph`. A Graph creation's completed arm is the same `{ kind, mapId, graphId }` as `CompletedMapEdit`; 03 can share or mirror it. `SpaceResourceRailContext.complete` now carries only `added-graph` from the rail, and `embedded-authoring.ts`'s comment listing "the Space Resource rail's rename / recolor / add-Graph commands" (and `renamed-map`) overstates what reaches `completeEmbedded` — 05 should trim both once creation moves.
