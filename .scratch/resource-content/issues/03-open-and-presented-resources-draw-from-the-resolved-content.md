# 03: Open and presented Resources draw from the resolved content

**What to build:** Every canvas node carries what it shows now — Closed (no content), Open or presented, each with the resolved content — and the Resource front and presenting draw from that through one exhaustive switch over the content kind, instead of inferring content from which node fields are present. Presenting-over-Open is decided once, in the projection. Read-only is decided once, at the top of the Resource front. A dangling Target draws a notice built from `Empty`, not an empty document. Presenting a Space Resource draws its Title only (07 asks what it should really draw). The presenting component is renamed `PresentedResource`, freeing `ResourceContent` for the content type. The old node fields stay populated until 06. Starts with `$shadcn-first-ui`.

**Blocked by:** 01, 02

**Status:** resolved

- [x] A Closed node carries no content; an Open node and a presented node carry the resolved content; a Resource both Open and presented is presented.
- [x] Authored Open state and the display cannot disagree unnoticed: the front's rule for which one it reads is stated once and tested for a Resource that is both presented and Open.
- [x] A Resource's own kind and its resolved content kind agree whenever `via` is `'self'` (property test over the projection).
- [x] Markdown, image and Space content and Reference Resources to each draw exactly as before, proved by the existing unit, application and Ladle proofs.
- [x] An unresolved Target draws the notice in the Open front and when presented (unit tests; no stable story, since intake makes it unreachable — recorded in the design-system inventory if the catalogue check asks).
- [x] Presenting a Space Resource draws its Title and no empty document.
- [x] `pnpm verify`, `pnpm e2e` and `pnpm e2e:ladle` pass.

## Comments

**2026-09-29** — Built. `ResourceDisplay` (`closed | open | presented`), `FrontDisplay` (without `presented`) and the shared `CLOSED_DISPLAY` are in `packages/ui/src/resource-display.ts`; the `editing` and `replacing` arms are 04's. `projectResourceNodes` sets `display` on every node from `resolveResourceContent`, deciding `presented` over `open` once; a Closed node's display carries no content. `data.open` stays beside it as authored geometry. The old node fields (`body`, `imageUrl`, `showContent`, `spaceContent`, `bodyEditor`, `imageReplacer`) are still populated. Nothing in `ui` or the adapter reads `body`, `imageUrl` or `showContent` any more. The app still reads `spaceContent`, which is 05's.

**The rule for authored Open versus the display:** what a Resource draws, and whether its front is Open, is read from the display alone. `CanvasResourceFront` no longer has `open`, `source`, `url` or `target`: it is the kind's operations, plus the body editor and image replacer until 04. `CanvasResource` takes `display: FrontDisplay`. `data.open` is geometry only: the resize control, z-order and the node's own `data-open`. `ResourceNode` draws `PresentedResource` whenever the display is `presented`, whatever `open` says. Evidence: `ResourceNode.test.tsx` "presents a Resource that is also Open, keeping its authored Open state on the node" (a presented body, no front and no Close, with the node's `data-open="true"`). Also `projection.test.ts` "presents the presented Resource even while it is Open", and the property "shows the presented Resource as presented, the Open ones as open, and the rest Closed" in `projection.property.test.ts`, which also holds `data.open` to the Open set.

`CanvasResource` makes the read-only decision once at the top. `contentAuthoring` (the drawn content is `via: 'self'` and not leaving) gates the body editor, the body's edit target, the image replacer and the failed-image Replace. The content area is one exhaustive switch over `markdown | image | unresolved`; a Space's content is its embedded Map, so it has no arm. What `usePresence` holds is memoised on kind, text and `via` (`useAreaContent`). `data-content-kind` is the content's kind while Open and the Resource's kind while Closed; its one CSS reader requires `data-open`. A Reference Resource to an Image Resource draws its Target's picture with no Replace, on the rail or in the failed-image state. Evidence: `CanvasResource.test.tsx` (also "offers no Replace for an image it draws through a Reference Resource", which fails if the `via` gate is removed) and `ResourceNode.test.tsx`. A Reference Resource to an image also fades out its picture on Close.

The presenting component is now `PresentedResource` (`packages/ui/src/PresentedResource.tsx`, test file renamed, inventory, `styles.css` and `docs/agents/ui.md` updated; `ResourceContentBody` deleted). It switches over `ResourceContent`: Markdown is rendered, an image is drawn with no Replace, a Space Resource draws its name alone (07), and `unresolved` draws the notice. `UnresolvedContent` (`packages/ui/src/UnresolvedContent.tsx`, from `Empty`, "Target not found") is drawn by both surfaces. It has unit tests only (`CanvasResource`, `PresentedResource` and `ResourceNode`) and no story, since intake makes it unreachable. `pnpm ui:catalog:check` asked for no inventory entry: the component is internal and reached through `CanvasResource`, which stories render.

Property (`projection.property.test.ts`, "draws content of the node's own kind whenever the content is its own"): over generated Spaces of every kind, all Open, `via === 'self'` implies the display's content kind equals `data.kind`. App test fixtures take a display from `fixtureDisplay` in `packages/app/test/render-adapter-fixtures.ts`. The React Flow story specimen builds its Open display by hand. `pnpm verify` passed (274 files, 3904 tests), as did `pnpm e2e` (264 passed) and `pnpm e2e:ladle` (137 passed).
