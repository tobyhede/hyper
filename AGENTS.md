# AGENTS.md

Instructions for AI coding agents working in this repo.

A local prototype for **graph-native technical presentations**: Markdown Things on spatial Diagrams, connected into curated directed Graphs and presented by traversal. PostgreSQL is the live write model and the browser reaches it over HTTP; memory repositories are confined to isolated development and E2E runs. Placement is **authored, not computed** — a **Diagram** owns an explicitly positioned subset of Space Things and the Graphs authored across them, while what arranges Things is a **LayoutStrategy** (ADR 0014, ADR 0040, ADR 0041). Newly created Spaces start with a complete authored Diagram, and first working load durably initializes a stored diagramless Space. **No strategy is privileged** — a strategy is one member of a growing set (grid, sorts, tree, cluster), never what "layout" means, and an automatic arrangement is an Edit over an authored Diagram rather than a render path (ADR 0086). A Diagram overview draws every Graph it owns at once, each as a coloured line of React Flow Edges, with the Active Graph emphasised. What draws the canvas is one authored Diagram, selected in the **Command Dock** — the Space's one command surface, floating over the canvas and taking no layout space from it (ADR 0079, ADR 0082, which supersedes ADR 0053). Things in the graph show their title; **opening** a Thing reads it in place, and **presenting** traverses the Active Graph (ADR 0006, ADR 0011, ADR 0024).

**Production UI work starts with `$shadcn-first-ui`, before any code.** Any change to a component, control, form, dialog, menu, popover, combobox, pane, thing or application surface goes through that skill: search `@project/ui` first, then the shadcn registry, and hand-roll interactive behaviour only as the last option with the deviation recorded before it is written (ADR 0047, ADR 0050). A new production component or a new hand-rolled block in `packages/app/src/styles.css` — by class, or, where a rule names no class, by its leading attribute, id or element — fails `pnpm ui:catalog:check` until it is either built from `@project/ui` or recorded with its reason in `packages/app/stories/design-system-inventory.ts`, and every stable story owes both a Ladle and an application proof (ADR 0052). See `docs/agents/ui.md`.

**The repo is the only source of state.** Development and CI are the only environments — no production, no release, no users, and no document or byte that outlives a reset. Every database and generated artifact is **derived**: the codebase mints it from tracked seeds, fixtures, migrations and scripts. So a format change rolls schema, fixtures and tests forward in one change, and generated state that disagrees with the code generating it is a bug fixed at the source rather than a shape intake keeps reading (ADR 0054, ADR 0056).

## Decided — read these before the code

Accepted ADRs run ahead of the code, and standing workarounds constrain it. Read them before touching the areas they govern, and do not read the current code as the design. Each entry states what is built and what is not; most of this section is now built, so the build status to trust is the one written in the entry.

- **ADR 0079 — V1 exposes only Diagrams, and first open initializes one — Tickets 01–04 built.** An authored **Diagram** is the only selectable and addressable canvas context. The persisted opening selection is `defaultDiagram`; obsolete canvas identities are invalid input and their product URLs are not found. Add Diagram creates and selects an *empty* Diagram with one empty Active Graph in one Edit, and the last Diagram cannot be deleted. New Spaces start complete; first working load atomically initializes stored or imported diagramless Spaces with an empty Diagram and Graph, while non-working reads do not initialize. Layout strategies stay distinct from Diagrams: the positioned strategy draws an authored Diagram and automatic strategies remain non-addressable capabilities. **Ticket 04 is built too, bar Enter.** A Space Thing's selection is durable: `spaceThingFrontmatterSchema` requires `diagram` and `graph`, so there is no valid Space Thing with nothing chosen and no surface that draws one. The lifecycle supplies the pair rather than taking it — `create` keeps what `initializeSpace` mints for its new target, and `link` makes the target working first, which durably initializes a stored diagramless Space, then records the Diagram it opens on with that Diagram's `activeGraph ?? graphs[0]`. So `LinkSpaceThingInput` declares no selection: the pane holds a `SpaceSummary` and shows no selector, and choosing differently is a later Edit on the Thing. A target that cannot be read, initialized or found refuses as `space-thing-target-unavailable`, on the pane's Target field beside `aggregate-refused`. Two consequences worth knowing before reading the aggregate: intake no longer falls back to the target's `defaultDiagram`, so `space-thing-diagram-missing` and its two siblings now mean a **dangling** reference rather than an unmade choice; and a diagramless ordinary Space can only be referenced by the very Edit that initializes it, which the adapters' shared `baselineUnreferenced` carve-out is what permits. **Enter is still open and is not this ticket's** — `entity-url-addressability/08` owns the surface that would resolve the stored context, and `OpenSpaces.enter` still has no production caller. The aggregate round trip is **built** (`.scratch/v1-release/issues/08`): the CLI imports and exports one complete Meta-rooted aggregate as a directory holding a versioned `hyper.json` plus one `<space-uuid>/` child per Space, and a Space Thing's selection survives that round trip intact. One consequence to know before writing an aggregate fixture: a diagramless *ordinary* Space cannot appear in a valid aggregate at all, because a Space Thing's `diagram` and `graph` must resolve in its target and an unreferenced ordinary Space is `ordinary-space-unreferenced` — only a diagramless **Meta** Space is valid, which is what the diagramless round trip is asserted against.

- **ADR 0061 — TypeScript 7 is the compiler and TypeScript 6 is a bridge — built.** `tsc` is TypeScript 7 and authoritative; the package name `typescript` deliberately resolves to the TypeScript 6 compatibility API that `typescript-eslint` and `prisma-next` consume, exposing `tsc6`. TypeScript 6 diagnostics are **not normative** — do not change source to satisfy it, do not add a TypeScript 6 typecheck, and do not "fix" the names so `typescript` means 7, which breaks typed linting. `pnpm typecheck:toolchain` asserts the arrangement and runs first in `verify`. The bridge's **removal condition is written in the ADR** — a stable release exposing the replacement compiler API, `typescript-eslint` and the other programmatic consumers supporting it, and `verify` green with `typescript` pointing at 7 — and the one known casualty is a `pnpm` patch on `@ladle/react` (`patches/`), whose bundled `.tsx` carries a `//@ts-ignore` that TypeScript 7's relocated diagnostic no longer sits under.

- **ADR 0062 — The narrowing assertions we have are the most we will have — built.** `@typescript-eslint/no-unsafe-type-assertion` is an error; the 79 sites already in the tree are recorded in the generated `eslint-suppressions.json` and **nothing new joins it**. It is a ratchet, not a backlog: `--prune-suppressions` runs in `verify`, the file only shrinks, and it is never hand-edited. `anti-slop/require-safety-comment-for-type-assertion` is unchanged and still applies to every surviving assertion — one rule demands a reason, the other caps the count. `tools/typing-fixtures/` is the executable evidence that both bite.

- **ADR 0064 — Opening and editing a Thing are separate — being built.** Opening and closing author the Diagram-owned Open/Closed state; an Open Thing displaces the Things `+x` and `+y` of it. **ADR 0084 reverses the sentence this entry used to carry** — displacement is no longer derived and unstored, it is applied by the Edit that causes it and written into the Diagram (see the ADR 0084 entry below). A closed Thing offers Edit and Open, an open Thing offers Edit and Close, and Edit on a closed Thing opens it before placing the caret. While Markdown editing is live, Save and Cancel replace Edit, Close stays visible but disabled, and blur ends nothing. The open Thing renders Markdown through the shared sanitised renderer; editing swaps that body for `MarkdownSourceEditor`. No `nowheel`, 16:9 constraint or camera follow is added to an Open Thing.

- **ADR 0066 — Open Size survives Closing — built.** Every Open Thing has one bottom-right resize control. Its canvas draft previews the resizing Thing's own rect and nothing else — under ADR 0084 a Thing's neighbours do not move until the Edit lands, so there are no displaced neighbours to preview. A proposal within the application-owned 24-canvas-unit magnetic range on both axes previews the exact Closed Size while the Thing remains Open for the gesture; release completes one Close Edit, preserves the remembered Open Size and restores it on the next Open. A one-axis match remains an ordinary Resize, and general grid snapping remains out of scope.

- **ADR 0084 — Displacement is applied by the Edit that causes it — built.** Opening a Thing moves the Things it grows past **once**, as part of the Open Edit, writing their new positions into the Diagram; Closing applies the negation and Resizing the difference. The rule is unchanged — growth is `openSize - COLLAPSED_THING_SIZE` floored at zero per axis, and a Thing strictly beyond the subject on an axis takes that axis's growth — but it runs at the Edit rather than at every render. `Placement.drawn` and `Placement.authoredPoint` are **deleted**, not reduced: `Placement.displace` and `Placement.growth` replace them, `Placement.next` merges what the canvas reports directly, and a settled drag authors the drop point exactly. So **a canvas coordinate is an authored one** — do not reintroduce a conversion at a drop site. Open and Close are **memoryless**: each reads the Diagram as it is at that moment, so Close reclaims from every Thing currently beyond the closing Thing, including ones the author moved there while it was open. That is deliberate; do not answer it by recording which Things a particular Open pushed. The round trip rests on the growth being **nonnegative**, which the floor guarantees — `displace` is not an involution for a negative initial growth, and the asymmetry is stated and tested rather than clamped. One Edit now changes more than one Thing's position, and undoing it undoes all of them.

- **ADR 0070 — An Open Alias shows its immutable Target content read-only — built.** An Alias chooses its Target once at creation and remains ordinarily authorable as a Thing and through its Diagrams and Graphs: Title, placement, Edges, Open/Closed state and Open Size all change as for any other Thing. Opening an Alias is the normal Diagram-owned Open operation — pointer, Enter and Space all use the one `opened-thing` completion — and the projection resolves the immutable Target's Markdown into the same `CanvasThing` content front a Markdown Thing draws, minus every content-authoring control: an Open Alias offers Close and inline Title editing and no Edit, Save, Cancel or Target picker. **Target immutability is Space Authoring's, not the surface's**: `edited-thing` refuses a changed Target with `alias-target-immutable` while still accepting a rename. The existing-Alias metadata pane, its Target picker, its retarget completion and `presentAliasThingRefusal` are gone; `ThingSearchCombobox` remains the Target picker for Alias **creation** only, which continues into inline Title naming. A future Space Thing Target follows the same read-only capability rule without ADR 0070 settling proposed ADR 0068's renderer or gestures. **`openThing` now admits every Thing kind**, the `space` front having gained a content arm with `entity-url-addressability/07`: an Open Space Thing draws the Diagram and Graph it selects, and still nothing that would change the Space it points at. **The Thing front names nothing outside itself (ADR 0083)**: neither an Alias's Target nor a Space Thing's target Space is drawn by name on it, so the kind glyph and the Alias's dotted border are what tell those Things apart from the ones they point at. Jump to Target and a possible Edit Target shortcut follow durable Thing URL implementation under `.scratch/alias-cards/issues/05-jump-to-alias-target.md`.

- **ADR 0069 / ADR 0072 — Entities have durable web addresses — built; ADR 0079's Diagram URL shape with them, its Ticket 04 still open above.** Every Space, Thing, Graph and Diagram has a product URL built from its Id, encoded as an unpadded 22-character base64url value; the domain, stored documents and HTTP resources keep canonical UUID spelling. What draws the canvas is a Diagram, identified by its own UUID, and `/spaces/:spaceId/diagrams/:diagramId` remains the durable Diagram URL shape. Accepted ADR bodies retain the earlier refinement history (`docs/agents/workflow.md`), so read their status blocks before their bodies.

- **ADR 0041 — Graph is the first-public name for Route — built.** The vocabulary rename is complete: schemas, code, tests and fixtures use Graph, Graph navigation and Traversal history; Route and Walk survive only in historical records and qualified HTTP or graph-layout routing prose. Unqualified `Graph` and `GraphEdge` name the domain; strategy and render intermediates use `LayoutStrategyGraph` and `GraphRenderEdge`; the canvas is `SpaceCanvas`. ADR 0040's Diagram-owned first-public document was a separate structural change, landed after it by `.scratch/first-public-aggregate/`.

Deeper build-status and gotcha detail for the ADRs that see the most churn now lives in the scoped `docs/agents/*.md` files listed under "Agent skills" below — read the one that covers the area before touching it.

## Commands

- Install: `pnpm install` (Node >= 26.8.1, pnpm 9).
- Dev: `pnpm dev` (app at http://localhost:5173) is the normal PostgreSQL-backed HTTP runtime and requires the configured database to be up. `pnpm dev:new` (port 5174) serves an initially empty memory repository; server-side startup creates the normal one-thing **new space** once (ADR 0018). `pnpm dev:fixture` (port 5175) serves the tracked fixture through the same HTTP boundary over an isolated memory repository. `pnpm dev:roadmap` regenerates and serves the V1 dependency-map Space on port 5176 through that memory runtime. Edits in any memory runtime survive browser reloads for that server's lifetime. None writes source files except `dev:roadmap`, whose generated files stay under its ignored `.scratch/v1-release/roadmap-space/` directory. **Never start, stop, restart or kill a server you did not start**, and do not free a port (`kill`/`pkill vite`/`lsof -ti:5173 | xargs kill` etc.). `strictPort: true`, so a second `pnpm dev` fails rather than picking another port — don't run one. **Whether a server is running is a fact about the machine, and this file cannot tell you.** Look, don't assume: `lsof -nP -iTCP:5173-5176 -sTCP:LISTEN`. A running dev server is hot-reloading (Vite HMR + React Fast Refresh), so your edits are already live in it; if none is running, nothing is serving your change and no amount of editing makes it visible. To verify changes, use `pnpm test`/`pnpm e2e` (Playwright starts its own servers) — never a dev server.
- Verify: `pnpm verify` runs `typecheck:toolchain` -> `typecheck` -> `typecheck:packages` -> `ui:catalog:check` -> `lint` -> `lint:anti-slop` -> `format:check` -> `test:coverage` (i.e. the ADR 0061 compiler assertion, then `tsc --noEmit` over the root program, then `pnpm -r typecheck` over each package's own config, `eslint . --max-warnings=0 --prune-suppressions`, `oxlint -c .oxlintrc.json` over the 15 vendored anti-slop rules, `prettier --check .`, `vitest run --coverage`). **`typecheck:toolchain` runs first** because a typecheck against the wrong compiler still passes, so proving which `tsc` ran has to happen before trusting what it said. CI runs that chain as **two jobs**, so a red lint and a red test suite are different check names: `verify:static` is the first seven commands and `test:coverage` is the eighth, and `verify` is defined as those two — the list of eight lives in `package.json` and nowhere else, so a developer's one command and CI's two cannot drift. **Both typechecks are needed**: the root program's `include` has `"*.config.ts"`, and `*` does not cross directory boundaries, so `packages/app/vite.config.ts`, `vite-space-http-plugin.ts` and `http-server-build.config.ts` are covered only by the per-package pass. Warnings fail the lint run; coverage thresholds are per-package and pinned at what already holds (`core`, `graph`, `persistence`), with no global threshold on purpose.
- Test: `pnpm test` (Vitest, `vitest` for watch). Unit + property tests (fast-check) live in `packages/*/test`.
- Mutation testing: `pnpm mutate:session` and `pnpm mutate:graph` run StrykerJS (`stryker.conf.mjs`) over one source file against a named oracle. **A deliberate local diagnostic, never a gate** — not in `verify`, not in CI, `thresholds.break` is `null`, and the tickets that introduced it forbid a threshold. `--mutate` and `--testFiles` are chosen as a *pair* per campaign, because the whole suite cannot run inside Stryker's sandbox (`test/unit`'s repo-meta test shells out to `git ls-files` and gets `[]`), so a campaign names the tests that are the oracle for the code it mutates — and nothing keeps that pairing honest but the reader. A score is evidence for a conversation about the oracle, not a number to move; the standing limits on what one means, including this runner's `static: true` false survivors, are in `.scratch/mutation-testing/engine.md`. Output goes to the gitignored `/reports/` and `/.stryker-tmp/`.
- E2E: `pnpm e2e` (Playwright, Chromium only) stays database-free and exercises HTTP; `pnpm e2e:fixture` selects only the tracked-fixture project. Every test owns a fresh Vite host, `E2eMemorySpaceRepository` and catalog; reloads and extra pages inside that test share them, while no revision leaks to another test. The `chromium` project imports the tracked fixture and `new-space` starts empty so database startup creates one thing. Hosts use worker-scoped ports beginning at 5300, away from the human's 5173–5175. `pnpm e2e:postgres` is the separate one-test project proving a real PostgreSQL edit survives a fresh Vite host. **CI runs it, as the last step of the `postgres` job** — it sits there rather than in `e2e` because it applies no migration of its own and needs the database `test:integration:postgres` has already migrated. Locally it stays opt-in: run it only with PostgreSQL up and migrated, and always stop PostgreSQL afterward. **It lives in `test/e2e/`, not `packages/app/e2e/`, and it drives the application surface** — it opens a Space and addresses the Space's name, its Things and `persistence-status` through the same helpers the normal suite uses. So a change to the Space's chrome breaks it exactly as it breaks the others, and **nothing in `verify`, `e2e` or `e2e:ladle` will tell you**: the one command that can observe it needs a database, so a surface change that swept `packages/app/e2e/**` and stopped there reaches CI red. When you change what the chrome draws, grep `test/e2e/` too. One-time first: `pnpm exec playwright install chromium`.
- Ladle E2E: `pnpm e2e:ladle` runs `playwright.ladle.config.ts` over `packages/app/ladle-e2e/`, against a `ladle serve --noWatch` catalogue it starts itself on port 61100. This is the behaviour half of ADR 0052's story evidence and it is **its own CI job**, run by neither `verify` nor `e2e` — so a component change that breaks a story is only caught here. The two Playwright configs share one flake policy (`retries: 2` and `failOnFlakyTests` under CI, `retries: 0` on a laptop); under `failOnFlakyTests` a retry that passes still fails the run, so the retries buy the trace and the reproduce-or-not signal rather than tolerance for a blip.
- Build: `pnpm build` (Vite build of the app).
- PostgreSQL integration: copy `.env.example` to the ignored `.env`, fill its password and matching `DATABASE_URL`, then run `pnpm postgres:up` followed by `pnpm test:integration:postgres`. Always finish with `pnpm postgres:down`; it keeps the named volume. `docker compose down --volumes` is the destructive reset. Normal `pnpm verify` and `pnpm e2e` do not require PostgreSQL.

## Package layout & boundaries

Seven `@project/*` workspace packages under `packages/`:

- `core` — domain model. Zod schemas (`schema.ts`, incl. `spaceFileSchema` — the space-file shape) + schema-derived `Thing`/`Graph`/`GraphEdge`/`Diagram` types (`types.ts`). No React, no framework deps.
- `graph` — pure graph logic over a `Space`: `loadSpace` (the one intake — parse, validate references including duplicate Edges within a Graph, index), the `Space` type and the one `SpaceLookup` it carries, Graph→Edge derivation, traversal, and the `LayoutStrategy` contract (`LayoutStrategyGraph`, `buildLayoutStrategyGraph`, `gridStrategy`, `positionedStrategy`). Depends only on `core`. **Its index is curated and there is no `export *`**, and the unit of curation is the **module**: it names every function something outside the package calls, and every type exported by a module those calls reach — whether or not a consumer writes that type down today. `frontmatter` and `validate` are absent as whole modules: the first is how `thing-file` reads a fence, the second runs inside `loadSpace`, which ADR 0010 makes the one intake. `SpaceReferenceError` is off the surface although `loadSpace`'s `SpaceError` union names it, while `ThingFileError` in that same union is offered — reachability is not the test, and neither is depth. Adding a name is a deliberate act — `test/unit/graph-package-surface.test.ts` holds the index's declarations and the module they produce to one list, so a new export fails until it is listed there. A test of an internal helper imports it from its own module rather than through the index.
- `http` — browser-safe Fetch transport: the Hono `/api/spaces` route tree, request and response policy and the inferred `SpaceHttpApp` client contract. It *consumes* the narrow `SpaceResourceRepository` seam rather than declaring it — that lives in `persistence`, beside the `LoadedSpace` and `SpaceSummary` it is written in terms of. Depends only on `core`, `persistence`, Hono and runtime-neutral media parsing; imports no host, database, app or render implementation.
- `persistence` — browser-safe `SpaceBackend` and `SpaceSession` contracts, optimistic revision handling, commit coalescing, retry/conflict states, and the memory adapter. It also declares the **stored** side of the seam once, for both consumers: `SpaceResourceRepository` and `RepositoryCommitResult` (`src/repository.ts`), which `@project/http` takes and which `src/persistence/space-repository.ts` extends into `SpaceRepository` by adding `initializeAggregate`, `replaceAggregate` and `markExported`. The server seam is a superset, never a second declaration — a `Thing`/`Graph` change cannot leave the two sides disagreeing, and the browser still cannot name the aggregate lifecycle or export because the seam the Fetch application consumes does not declare them. **Two lifecycle doors and no mode parameter on either (ADR 0078)**: the order-sensitive `importSpaces(input, 'insert' | 'truncate')` that used to sit there is gone, because it inferred Meta from array position and hid a destructive choice in an argument. Seeds, fixtures and tests seed through those same two. Depends on `core` and `graph` so every committed snapshot passes the normal domain intake. It also owns **`createObservableState`**, the one observable-state seam behind `SpaceSession`, Navigation and SpaceAuthoring's own `getState`/`subscribe` interfaces: publication installs the next state synchronously, snapshots the subscriber set so a listener added mid-publication begins at the next one rather than part-way through the current, contains synchronous throws and thenable rejections, continues to the observers behind the failure, and reports through a sink `createNonThrowingReporter` has made incapable of interrupting the work it describes. Each collaborator keeps its own state and its own interface — only notification moved. **`app` therefore imports observable state from `persistence` although Navigation has nothing to do with persistence**; `.scratch/authoring-seams/issues/01-one-observable-state-module.md` records why that home was taken and what the alternatives cost.
- `react-flow-adapter` — the ONLY place React-Flow (`@xyflow/react`) specifics live: projects a Space and its Diagram-owned Graphs into RF nodes/edges and renders `ThingNode`. It implements no `LayoutStrategy` — elkjs and the strategy built on it left with ADR 0086, and the two that survive, `gridStrategy` and `positionedStrategy`, are `graph`'s.
- `ui` — reusable, presentation-agnostic React components + shadcn-style primitives (Tailwind v4, CVA, Lucide, and Base UI controls including `Button`, `Select`, `Popover`, `Dialog`, `Menu` and `Combobox`), the `StatusPanel` operational-feedback module, plus the `AppShell` that frames the canvas. **The registry `Sidebar` is gone, and so is everything that stood only beside it**: ADR 0082 retired the gutter and `CommandDock` is a `Toolbar` over the canvas instead, so `.scratch/command-dock/issues/08` deleted `components/sidebar.tsx` with the cookie-backed open state and `Ctrl/Cmd-B` it carried, `components/sheet.tsx` and `components/skeleton.tsx` behind it, `hooks/use-mobile.ts` behind those, `AddThingControl` (the Dock's `CreatePeers` offers the three Thing kinds as peers rather than as a split control), and `OpenSpaces` with `components/tabs.tsx` (the Dock's Open Spaces menu is the open set's one surface). The words that reported an unwell open Space outlived the strip as `open-space-status.ts`. Regenerate a registry primitive from shadcn if one is wanted again; do not restore `AddThingControl`, whose recorded design — a split button with a hidden default — contradicts `CreatePeers`'s on purpose: the kind is chosen at creation, so none of the three is a default. `CreatePeers` replaced the `CreateMenu` that disclosed them, which charged two presses for every creation including `markdown`, the one kind that completes its Edit on activation; the three kinds being peers is unchanged and Create stays outside the Things list. On a side edge the Things cluster packs onto one row rather than taking three verb tracks, giving up the `1fr` name track the three *authored* names need and it does not — "Things" is a fixed word. Both are ADR 0052 treatment, so the evidence is `parity-claims.ts`'s `command-dock-creates-each-kind-in-one-press` and `command-dock-packs-things-onto-one-row` rather than an ADR. The registry `Drawer` and `AppShell`'s `insetEnd` are a separate pair and still stand: `08` ran while `ThingsDrawer` was their consumer and the Things Popover took it afterwards, so retiring them is a decision of its own — `.scratch/command-dock/issues/16-retire-the-registry-drawer-and-the-yielded-strip.md` owns taking it, not `08`, and the drawer carries an inventory entry meanwhile. **One command surface, drawn wherever the product draws chrome**: `CommandSurface`, `CommandToolbar` and `command-surface.css` carry the neutral translucent panel, and both the Command Dock and a Thing's hover toolbar (`ThingRailActions`) mount it — so the Thing rail is neutral and the Active Graph's colour stays on the handles and Edges where it names a Graph (`.scratch/command-dock/issues/12`), and `test/unit/command-surface-sharing.test.ts` holds the ownership a rendering test cannot state. `ChoiceMenu` is how a Diagram or a Graph is chosen: the Dock's Diagram and Graph clusters and an Open Space Thing's two choices all draw it, each supplying its own set, selection and operation, because the operation is deliberately not shared — one moves the canvas the author stands on and the other writes which Diagram a Thing shows. `Select`'s one remaining consumer is the target Space on the Space Thing creation pane, which leaves one flow asking two ways and is a known seam (`docs/agents/ui.md`); it had spent a while with no consumer at all after ADR 0053 deleted the three renderer selectors. `Textarea` has one again after its own while with none, the Thing body having become a source editor: `InlineTitleEditor` draws it in place of `Input` wherever a Title may be written on more than one line, which ADR 0083 makes the Thing's Title and no other entity's — `CanvasThing` sets `multiline` and the Dock's header does not. Depends on `core` only. **Markdown source is edited through `MarkdownSourceEditor`, the one component allowed to know CodeMirror exists (ADR 0063, refined by ADR 0067).** **`ui` owns the split point that reaches it**, `markdown-source-editor-lazy.ts`, beside the component that needs it — `MarkdownThingBody` is a second consumer inside this package, and a static import from it would put the whole stack into the barrel and from there into every consumer of `@project/ui`. So `app` no longer names the editor at all and the `@project/ui/*` ESLint zone is a plain bar with no negated entry. Two things are the wrapper's and not a caller's: which keys it withholds from CodeMirror (`PANE_OWNED_KEYS` — `Escape` and `Mod-Enter`, the two exits the mounting surface spends, both of which `defaultKeymap` would otherwise take), and every `.cm-*` selector. A caller that needs a say over CodeMirror's appearance sets a custom property the component's own theme reads; no stylesheet in the repository may name a `.cm-*` class, and `test/unit/codemirror-encapsulation.test.ts` holds both that and the dynamic-import split, scanning both source trees. **Choosing a Thing has one component and one interaction model**: `ThingSearchCombobox` is the shadcn/Base UI editable combobox used by Edge endpoints and Alias Targets. Its visible input displays the selected Thing and becomes the search field in place; filtering, active item, keyboard selection, dismissal, empty state and the `combobox`/`listbox` pairing belong to the primitive. A refused choice stays visible as a disabled row carrying its reason. Do not add a second inline or trigger-and-popup picker implementation.
- `app` — wiring/composition: **`compose-app.ts` states what an opened Space is composed of, once** — `composeCore` answers the one working-space reader, `currentSpace`, the opening Diagram and Navigation; `composeApp` adds Space Authoring, the render adapter, the continuation and Edge Authoring, in the order they have to be built in — the continuation before Edge Authoring, which publishes into it. **Where an Edit continues is that one module, `continuation.ts`**: a gesture requests `{ target, select, then }`, one pending continuation is held rather than a queue, and two adapters spend it — `CanvasContinuation` inside `ReactFlowProvider` for the canvas targets and `ChromeContinuation` at the App root for the chrome ones. **Creating a Thing from a pane is one reducer, `thing-creation.ts`**, shared by the Alias and Space Thing panes and composed by `App` rather than here, since its two seams are the component's. Every collaborator closes over that one reader, which is what gives them a single `Space` identity to share. **Open Spaces (`open-spaces.ts`) is the one caller of `composeApp`** — it composes each opened Space once, holds the result on the `OpenSpace` entry, and hands it to `createApp`, which builds the component over a composition it is given rather than making a second one. A test that wants collaborators calls `composeCore` or `composeApp` rather than writing the chain out. Also: Navigation and Space Authoring, each keeping its own state behind `createObservableState` and read through one `useSyncExternalStore` (the Active Graph, Traversal history). **Open/Closed is not among them** — it is authored on the Diagram (ADR 0064), so Navigation carries no opened-Thing field; the Zustand-backed **render adapter**, which owns the published projection, drag bookkeeping and the discriminated `none | thing | edge` canvas selection; **Edge Authoring**, which owns the complete Edge interaction lifecycle over both of them; product-URL navigation, Space loading, the canvas and its cameras, presenting chrome, hand-rolled CSS. Zustand is the render adapter's and nothing else's — Traversal history lives in Navigation. **There is no router library, and putting one back is a decision rather than a convenience.** `@tanstack/react-router` went when ADR 0069 gave entities durable web addresses: the destination contract is declared once in `@project/http` (`ProductDestination`, `productDestinationPath`, `resolveProductDestination`) and the Node host resolves the same one the browser does, so a router would have been a second copy of that table, in the browser only, disagreeing with the host the day either moved. **`browser-location.ts` is the one module that knows a browser exists**, and **no call site decides what the browser does** (ADR 0081). It takes the five-member `HistoryApi` — required with no default, the way `newId` is (ADR 0016) — and **`browserHistory()` in `space.ts` is the one adapter that owns it**: the whole of the application's `window.location` reads and `window.history` writes live in that function, alongside `main.tsx`'s one `window.location.pathname` read. `createSpaceStartup` does not reach the browser itself; it selects that adapter as the default of its third argument, which is what makes the composition root the place the ambient browser is named (ADR 0081). Every rule below is proved in the node environment against a recording adapter (`browser-location.test.ts`). `createOpenSpaces` composes it once for the session, because there is one history stack, and calls `follow(app)` with whichever composition is on the canvas; `App.tsx` reads the two fields it publishes, `addressedThingId` and `destinationNotFound`, through one `useSyncExternalStore` and keeps only the clipboard half of Copy link. Navigation answers a `NavigationAddress` — the selected Diagram, the Active Graph and the presenting Thing, derived from its state and never stored on it — and that module hands the address, plus the Thing the location addresses, to `destinationSync`, a pure function that compares the position against what the current pathname resolves to and answers `push`, `replace` or `none`. `none` is what lets `popstate` move Navigation without the move pushing an entry over the one the browser just navigated to, and what makes a redundant notification — StrictMode's second invocation included — decide nothing. So a Navigation operation is called for its own sake and never paired with a history write: **do not put a `moves = getState().x !== y` comparison beside a call site**, which is the five-diff shape ADR 0081 removed. The `popstate` listener still reopens whatever `resolveProductDestinationInSnapshot` answers for the current pathname, and a location it cannot resolve is *reported* rather than corrected — but only for the arrival: the first move away from it is written and clears the report. **`canvasProjection` is what the render adapter publishes**: `canvasProjection(space, resolved)` answers a `PendingCanvasProjection` — the `strategyGraph` it builds, the `colors` it derives from the Space, the `visibleGraphs` it reads off the Diagram's own `graphs`, and a `project(laidOut, interaction)` returning the React Flow nodes and edges. It takes `@project/graph`'s `ResolvedDiagram`; **`diagram-resolution.ts` is the one module between a Diagram id and the Diagram it names** — `requireDefaultDiagram`, `resolveDiagram`, `diagramThings` and `DiagramNotFoundError`, imported rather than injected, and there is no aggregate wrapping them. None of those is state anything carries. It is a pure module and deliberately not a hook — no store, no React, no DOM — so the whole derivation is tested in the node environment (`canvas-projection.test.ts`, and a property test for the handle-resolution invariant React Flow warns about as #008). The `LayoutStrategyGraph` it takes is **not nullable on purpose**: there is nothing worth projecting before a strategy resolves, and requiring one is what stops a caller publishing a projection whose every Thing sits at the origin. The word *projection* names this bridging construct in `app` and the adapter and is deliberately absent from `CONTEXT.md`, whose render-layer section forbids inventing a domain term between React Flow's vocabulary and ours.

Hard rules — **all four are now enforced, not just documented**. Two layers, because neither catches what the other does: ESLint `no-restricted-imports` zones catch package specifiers and relative escapes (`../../*`), and each package's narrowed tsconfig `paths` makes an illegal alias unresolvable. `rootDir` is set on `core` alone — anywhere else it rejects the legitimate `@project/*` import too, since the aliased file resolves outside the package, which is why the relative-escape half is a lint rule rather than a compiler setting. Before this, `core` could import `@project/ui`, cycle back into `@project/graph`, and reach `../../app/src/store` with typecheck and lint both green.

- Domain logic stays out of React (keep it in `core`/`graph`).
- React-Flow specifics stay in `react-flow-adapter`. Precisely: **`core`, `graph`, `persistence` and `ui` must not import it**, which is what `no-restricted-imports` enforces — the zone still names elkjs beside it, which is a dependency of no package since ADR 0086. Read that entry as banning a *render-time* engine from the domain, not as siting a returning one: ADR 0086 puts Auto-arrange in `graph`, attached to an Edit, so building it means re-siting the ban rather than obeying the lint message. `app` does import `@xyflow/react` and legitimately so, being the composition layer — the older "nothing else imports them" was already false.
- Reusable UI goes in `ui`; app-specific glue goes in `app`.
- A module bundled into a Vite config (`vite.config.ts`, `http-server-build.config.ts`) imports `@project/*` by **relative path only** — a bare specifier is externalized and hands Node the workspace TypeScript, and the dev server then will not start at all.

## Conventions & gotchas

- **Strict TypeScript everywhere**, incl. `noUncheckedIndexedAccess`, `noUnusedLocals/Parameters`, `noImplicitOverride`.
- **`package.json`'s TypeScript entries look wrong and are not (ADR 0061).** `@typescript/typescript7` is TypeScript 7 and owns the `tsc` binary; the package name `typescript` resolves to `@typescript/typescript6`, which owns `tsc6` and the `createProgram` API `typescript-eslint` and `prisma-next` need. `tsc` is the only type-checking truth here — a TypeScript 6 diagnostic is not a defect to fix, and `tsc6` is a migration aid, not a gate. Do not unify the two names. `pnpm typecheck:toolchain` fails the moment either half stops holding, and the ADR states the condition under which the bridge is removed.
- **`eslint-suppressions.json` is a ceiling, not a backlog (ADR 0062).** It records the narrowing assertions that predate the rule, and it is generated — never hand-edited, never added to. `--prune-suppressions` runs in `verify`, so it only shrinks, and it shrinks as files are edited for other reasons rather than as scheduled work. A new assertion fails lint even in a listed file; adding one to a file with suppressed sites reports every assertion in that file, because a count-based baseline cannot tell which is new.
- **`verbatimModuleSyntax` + ESLint `consistent-type-imports` are on** — use `import type` for type-only imports or lint/typecheck fails.
- **Cross-package imports** use the `@project/*` path aliases: declared in `tsconfig.base.json`, mirrored in `vitest.config.ts` `resolve.alias`, and **narrowed per package** in each `packages/*/tsconfig.json` so a package can only resolve what it may legally depend on. Vite needs no alias at all — it resolves through the workspace `exports`, and the third copy that used to sit in `packages/app/vite.config.ts` is gone (removing it built an identical bundle). Vitest's *is* load-bearing: the root package declares no `@project/*` deps, so there is no symlink to resolve through. Two lists to keep in sync, plus the package's own narrowed one.
- **Relative imports inside a package are EXTENSIONLESS** (`./foo`, not `./foo.ts`).
- **Use a functional core and imperative shell for cross-module coordination.** Compute and validate the complete next state in a private pure core before producing side effects; a thin imperative shell then updates collaborators in an order that preserves valid intermediate states. Expose the coordination as one operation rather than returning a plan for callers to execute. Keep framework and store events outside the seam, depend on existing module interfaces, and do not manufacture single-adapter ports for deterministic private helpers. An edit event is a notification, not state transfer: each editor first installs its authoritative completed state and only then emits the notification; the coordinator derives the next Space from the current state owned by its collaborators rather than from state carried by the event.
- **Inject nondeterminism once when composing a module, not through each domain operation, and never by mocking the ambient generator (ADR 0016).** A module that mints identities, reads time or otherwise depends on a nondeterministic in-process function receives that function at composition so tests can supply a deterministic one; its operational interface then stays in domain language and does not repeat the dependency on every call. `createSpaceAuthoring` takes `newId` exactly as it takes `reportObserverError` — **required, with no default** — and mints the Thing, Diagram and Graph ids of a completed Edit from it. **`packages/app/src/compose-app.ts` supplies it explicitly**, so every authored identity has one visible source, and **`createOpenSpaces` takes the same `newId` — required, with no default — and supplies it to every `composeApp` call it makes**, alongside its `reportObserverError`; omitting either lets `composeApp`'s own defaults reinstate the ambient generator and `console.error` behind the one owner's back. **Don't answer a test's need for a known id with `vi.spyOn(crypto, 'randomUUID')`** — ADR 0016 rejected that when `loadSpace` faced it and the grounds are general: a constant collides across a property test's cases so it needs a counter, at which point a generator exists anyway; `randomUUID` is an unseedable CSPRNG, so controlling it means owning it; and the mock stops working in silence the day the implementation moves to v7 and reads the clock as well as the entropy pool. The seventeen spies this replaced also hid a real defect — one of them named two ids for an Edit that mints three, so a Diagram quietly took an id from the real generator. Tests name the ids they assert on through `packages/app/test/minting.ts`. Do not hide nondeterminism behind global mocking, and do not manufacture a port or adapter seam when the dependency has one in-process implementation. Deterministic rules stay uninjected — `titles.ts` mints `Thing N`, `Diagram N` and `Graph N` through three named operations with the `<Prefix> N` arithmetic private, because there is nothing there a test would want to replace.
- **`path` means a file path only.** The document and the implementation agree on `graphs`/`activeGraph` — the sentence here used to contrast a planned spelling with a built one, and the rename closed that gap. Remaining `path` identifiers are filesystem paths, the HTTP and product URL paths `@project/http` builds and matches (`productDestinationPath`, `SPACE_COLLECTION_PATH`, Hono's `context.req.path`), or React Flow's own SVG `edge-path` class — don't “fix” those.
- **`CONTEXT.md` reserves “arrangement” for ordinary prose rather than a domain entity, and the code honours that.** The one deliberate survivor is `packages/graph/src/layout.ts`, which quotes the avoid-list in its own doc comment. `AuthoringRefusal` uses `placement-pending`, and `CanvasContent`'s third kind is `'things'`, produced by `canvasContent`'s `hasThingsOnCanvas`. **`'things'` is not a synonym for Placement** — it means “Things are mounted on the canvas”, which stays true while replacement placement is still pending.
- **A comment may only assert what its writer has checked (`docs/agents/workflow.md`).** Four rules, each from ticket 14, where each was broken by a claim that opening the named file would have settled. **A negative result belongs in a ticket, never in source** — "X was tried and reverted because it broke Y" forecloses the work, reads as settled because it is in the source, and is never re-run; `App.tsx`'s `entityActions` carried six embedded-Diagram failures that did not reproduce. **No measurement in source**: commit the instrumentation, or put the number in the ticket with its method. **A claim about another module names the test that holds it** — that family already exists (`command-surface-sharing`, `codemirror-encapsulation`, `graph-package-surface`, `current-domain-vocabulary`), and a subagent's summary is a report, not a fact. **A decision called load-bearing needs something that fails when it is reversed**; this ticket's reconciliation order was documented that way and swapping it broke nothing. None is lintable; they hold in review.

- **"workspace" is guarded, not merely avoided (issue 11).** `CONTEXT.md` retires it for two readings — the loaded Space, and the app chrome around it — and issue 08 brought the code into line; `test/unit/current-domain-vocabulary.test.ts` is what stops it drifting back. It reads for both: the bare word over the source the repo authors (`packages/**`, `src/**`, `test/**`, `scripts/**` and the root `.ts` configs), and the identifier, test-id, CSS-block and module-name shapes over every tracked Markdown document outside the historical trees. Root tool configuration — `eslint.config.js`, `.oxlintrc.json`, `.coderabbit.yaml`, `ci.yml`, the two `pnpm-*.yaml` — is out by construction, each being written in some tool's vocabulary. Say Space for the loaded Space, and Dock or canvas for the chrome. **pnpm's sense is untouched, and where it is allowed is the exemption list**: five modules (`packages/app/workspace-aliases.ts`, the two Vite configs that import it, `scripts/check-typescript-toolchain.ts` and its test), each asserted to still contain a hit so an exemption cannot outlive its reason. The dependency protocol is forgiven **by the line, not the file** — a manifest is read like anything else, so a script name, an `imports` entry or a renamed package is still reported. **Monorepo prose in a document stays writable while it is bare and lowercase** — "workspace packages", "a pnpm workspace" — because that arm reads shapes rather than the word. What it reports is the word capitalised as a noun, the word hyphenated onto anything in either direction bar the two carve-outs (`workspace-aliases`, `pnpm-workspace`), and pnpm's two exported camelCase names — so this bullet cannot write any of those shapes, and neither can any other document. That is the point: those are how the retired component, test id, CSS block and module were written. If pnpm ever genuinely needs one in prose, that is a decision to take rather than a rule to route around.

## Before claiming done

- Run `pnpm verify` and report the real output.
- For any UI/graph change, also run `pnpm e2e` and report it.
- For any change to a component with a story, also run `pnpm e2e:ladle` and report it. It is not part of `verify` and not part of `e2e`, so nothing else runs it for you, and it is a CI job — a story left behind by a component change fails there.
- Do not assert success without having run the commands.
- **Assume a green baseline. Never run the bar to establish one.** CI gates all five jobs on every push and pull request, so a tree you were handed is green — that is what makes the baseline green, not what makes your change green. Run each command once, on the finished state. A full pass is minutes — `verify` 70–130s, `e2e` 100–240s, `e2e:ladle` ~75s — so a baseline run plus a final run doubles the largest cost in your session to learn nothing. Any failure you see is yours until you have evidence otherwise, and `git stash` or `git log` on the file is that evidence in seconds where a second suite run is minutes.
- **Only run what can observe the change.** The scoping above cuts both ways. A change reaching no application or test code — `.github/**`, `.scratch/**`, `docs/**`, a README — cannot be observed by a browser, and `pnpm e2e` on it is pure cost. Match the command to what you touched, and report which commands you ran *and* which you judged inapplicable and why. A skipped command you name is honest; a skipped command you leave unmentioned reads as a passed one.
- **The shards are the suite.** `pnpm e2e --shard=i/3` across all three `i` is the same 159 tests as `pnpm e2e`. Run one or the other, never both.
- CI (`.github/workflows/ci.yml`) runs all five jobs on every push and PR, with `--frozen-lockfile`. It is a backstop, not a substitute — a red CI after the fact is slower than a green run before the commit.
