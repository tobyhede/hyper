# AGENTS.md

Instructions for AI coding agents working in this repo.

A local prototype for **graph-native technical presentations**: Markdown Resources on spatial Maps, connected into curated directed Graphs and presented by traversal. PostgreSQL is the live write model of the database hosts and the browser reaches the store over HTTP; memory repositories serve isolated development and E2E runs, and `pnpm hyper run <dir>`, which Imports its Aggregate directory into a fresh memory store and Exports edits back to it, making the directory the durable copy (ADR 0117). Placement is **authored, not computed**: a **Map** owns an explicitly positioned subset of a Space's Resources and the Graphs drawn across them, and a layout strategy only arranges. The Map and Graph rules are in [`docs/agents/maps-and-graphs.md`](docs/agents/maps-and-graphs.md). A Map overview draws every Graph it owns at once, each as a coloured line of React Flow Edges, with the Active Graph emphasised. What draws the canvas is one authored Map, selected in the **Command Dock** — the Space's one command surface, floating over the canvas and taking no layout space from it (ADR 0079, ADR 0082). Resources in the graph show their title; **opening** a Resource reads it in place, and **presenting** traverses the Active Graph (ADR 0064, ADR 0024).

**Production UI work starts with `$shadcn-first-ui`, before any code.** Any change to a component, control, form, dialog, menu, popover, combobox, pane, resource or application surface goes through that skill: search `@project/ui` first, then the shadcn registry, and hand-roll interactive behaviour only as the last option with the deviation recorded before it is written (ADR 0047, ADR 0050). A new production component or a new hand-rolled block in `packages/app/src/styles.css` — by class, or, where a rule names no class, by its leading attribute, id or element — fails `pnpm ui:catalog:check` until it is either built from `@project/ui` or recorded with its reason in `packages/app/stories/design-system-inventory.ts`, and every stable story owes both a Ladle and an application proof (ADR 0052). See `docs/agents/ui.md`.

**The repo is the only source of state.** Development and CI are the only environments — no production, no release, no users, and no document or byte that outlives a reset. Every database and generated artifact is **derived**: the codebase mints it from tracked seeds, fixtures, migrations and scripts. So a format change rolls schema, fixtures and tests forward in one change, and generated state that disagrees with the code generating it is a bug fixed at the source rather than a shape intake keeps reading (ADR 0054, ADR 0056). The one exception is an Image Resource's picture (ADR 0106, ADR 0118): an external image URL's bytes are not the repository's, and a stored image is outside the aggregate, so Export carries its bytes in the Aggregate directory's `images/` only while a Resource references it.

## Decided — read these before the code

Accepted ADRs run ahead of the code, and standing workarounds constrain it. Read them before touching the areas they govern, and do not read the current code as the design.

**Where a topic has a current contract, read it first** (ADR 0115). A contract states the topic's accepted rules in current words, with their reasons and source ADRs. How contracts relate to ADRs, and how to keep them current, is [`docs/agents/workflow.md`](docs/agents/workflow.md#current-contracts), which also lists every topic that has one.

- **Maps and Graphs — [`docs/agents/maps-and-graphs.md`](docs/agents/maps-and-graphs.md).** Read it before you add, delete, select or default a Map or touch `defaultMap`; add, delete, order or activate a Graph or touch `activeGraph`; change Map membership, Open, Close, Resize, a Resource's size or displacement; change how a new Space is created or a mapless Space is first opened; or change the layout strategy contract or propose Auto-arrange. Its own "Read this before" section lists the paths it covers.

**A topic without a contract** is read through the entries below, the scoped guides under "Agent skills" and [`docs/adr/README.md`](docs/adr/README.md). Each entry states what is built and what is not; most of this section is now built, so the build status to trust is the one written in the entry.

- **Space Resource selection is durable (ADR 0079, Ticket 04) — built.** ADR 0079's Map rules (the Map as the only canvas context, `defaultMap`, Add Map, the last Map, first working load) are in [`maps-and-graphs.md`](docs/agents/maps-and-graphs.md). A Space Resource's selection is durable: `spaceResourceFrontmatterSchema` requires `map` and `graph`, so there is no valid Space Resource with nothing chosen and no surface that draws one. The lifecycle supplies the pair rather than taking it — `create` keeps what `initializeSpace` mints for its new target, and `link` makes the target working first, which durably initializes a stored mapless Space, then records the Map it opens on with that Map's `activeGraph ?? graphs[0]`. So `LinkSpaceResourceInput` declares no selection: the pane holds a `SpaceSummary` and shows no selector, and choosing differently is a later Edit on the Resource. A target that cannot be read, initialized or found refuses as `space-resource-target-unavailable`, on the pane's Target field beside `aggregate-refused`. Two consequences worth knowing before reading the aggregate: intake no longer falls back to the target's `defaultMap`, so `space-resource-map-missing` and its two siblings now mean a **dangling** reference rather than an unmade choice; and a mapless ordinary Space can only be referenced by the very Edit that initializes it, which the adapters' shared `baselineUnreferenced` carve-out is what permits. **Enter is built** — `space-cards/11` is the Enter command in the Space Resource’s entity menu, `entity-url-addressability/08` is independent open at the target's canonical address, and `App` spends `OpenSpaces.enter` as `spaces.enter(spaceId, map, graph)`. A new Open Spaces entry seeds from that pair; an already-open entry keeps its live selection. The aggregate round trip is **built** (`.scratch/v1-release/issues/08`): the CLI imports and exports one complete Meta-rooted aggregate as a directory holding a versioned `hyper.json` plus one `<space-uuid>/` child per Space, and a Space Resource's selection survives that round trip intact. One consequence to know before writing an aggregate fixture: a mapless *ordinary* Space cannot appear in a valid aggregate at all, because a Space Resource's `map` and `graph` must resolve in its target and an unreferenced ordinary Space is `ordinary-space-unreferenced` — only a mapless **Meta** Space is valid, which is what the mapless round trip is asserted against.

- **ADR 0061 — TypeScript 7 is the compiler and TypeScript 6 is a bridge — built.** `tsc` is TypeScript 7 and authoritative; the package name `typescript` deliberately resolves to the TypeScript 6 compatibility API that `typescript-eslint` and `prisma-next` consume, exposing `tsc6`. TypeScript 6 diagnostics are **not normative** — do not change source to satisfy it, do not add a TypeScript 6 typecheck, and do not "fix" the names so `typescript` means 7, which breaks typed linting. `pnpm typecheck:toolchain` asserts the arrangement and runs first in `verify`. The bridge's **removal condition is written in the ADR** — a stable release exposing the replacement compiler API, `typescript-eslint` and the other programmatic consumers supporting it, and `verify` green with `typescript` pointing at 7 — and the one known casualty is a `pnpm` patch on `@ladle/react` (`patches/`), whose bundled `.tsx` carries a `//@ts-ignore` that TypeScript 7's relocated diagnostic no longer sits under.

- **ADR 0062 — The narrowing assertions we have are the most we will have — built.** `@typescript-eslint/no-unsafe-type-assertion` is an error; the sites still in the tree are recorded in the generated `eslint-suppressions.json`, which is the one place their number lives, and **nothing new joins it**. It is a ratchet, not a backlog: `--prune-suppressions` runs in `verify`, the file only shrinks, and it is never hand-edited. `anti-slop/require-safety-comment-for-type-assertion` is unchanged and still applies to every surviving assertion — one rule demands a reason, the other caps the count. `tools/typing-fixtures/` is the executable evidence that both bite.

- **ADR 0064 — Opening and editing a Resource are separate — built.** Opening and closing author the Map-owned Open/Closed state and nothing else: no size changes and nothing moves (ADR 0122, [`maps-and-graphs.md`](docs/agents/maps-and-graphs.md) §6). A closed Resource offers Edit and Open, an open Resource offers Edit and Close, and Edit on a closed Resource opens it before placing the caret. While Markdown editing is live, Save and Cancel replace Edit, Close stays visible but disabled, and blur ends nothing. The open Resource renders Markdown through the shared sanitised renderer; editing swaps that body for `MarkdownSourceEditor`. No `nowheel`, 16:9 constraint or camera follow is added to an Open Resource.

- **ADR 0122 — A Resource's size is independent of Open — built, bar the control (ticket 02).** A Map entry is `{ x, y, open?, size?, shape? }`; `resourceSize` and `resourceOpen` in `@project/core` resolve the defaults (Closed Size, Closed). Resize changes `size`, Open or Closed, and is the only Edit that displaces; Open and Close change `open` alone; the Closed Size is every kind's floor; an Ur Resource is never Open (`open-requires-content`). ADR 0066's Open Size and magnetic Close are superseded. The resize control's canvas draft previews the resizing Resource's own rect and nothing else; it is still offered only on an Open Resource until `.scratch/size-independent-of-open/issues/02` offers it on the selected one. General grid snapping is out of scope.

- **ADR 0084 and ADR 0093 — Displacement is applied by the Edit that causes it — built.** The rules and their reasons are [`maps-and-graphs.md`](docs/agents/maps-and-graphs.md) §6, including the one-axis rule measured from the size before the Resize, and why a Resize never records whom it pushed. Two code facts to know before touching `graph/src/placement.ts`: `Placement.drawn` and `Placement.authoredPoint` are deleted, not reduced — `Placement.displace` replaces them and `Placement.next` merges what the canvas reports directly, so **a canvas coordinate is an authored one** and no drop site converts it; and `displace` is not an involution for a shrink applied first, which is tested rather than clamped (R42). Undo is not built; one Edit moving many Resources is the unit a future undo will reverse.

- **ADR 0070 — An Open Reference Resource shows its immutable Target content read-only — built.** A Reference Resource chooses its Target once at creation and remains ordinarily authorable as a Resource and through its Maps and Graphs: Title, placement, Edges, Open/Closed state and size all change as for any other Resource. Opening a Reference Resource is the normal Map-owned Open operation — pointer, Enter and Space all use the one `opened-resource` completion — and the projection resolves the immutable Target's Markdown into the same `CanvasResource` content a Markdown Resource draws, minus every content-authoring control: an Open Reference Resource offers Close and inline Title editing and no Edit, Save, Cancel or Target picker. **Target immutability is Space Authoring's, not the surface's**: `edited-resource` refuses a changed Target with `reference-target-immutable` while still accepting a rename. The existing-Reference metadata pane, its Target picker, its retarget completion and `presentReferenceResourceRefusal` are gone; **ADR 0089 took the creation picker with them** — a Reference Resource is created *from* its Target, as a `Create Reference` row on that Resource's own command menu, so the gesture supplies the Target and the new Reference Resource is named after it, copied once, with the caret in its Title. The row is drawn **unavailable** rather than absent on a Reference Resource, which is where the product says that referencing terminates. A Space Resource can also be a Reference Resource Target: the Reference Resource draws its Target’s selected Map and Graph read-only through the shared embedding. So can an Image Resource: the Reference Resource draws its Target’s picture, with no Replace on the rail or in the failed-image state; it Opens at the size it has, as every Resource does (ADR 0122). `resolveResourceContent` in `graph` owns that single-hop resolution for every kind: it answers one `ResourceContent` value (`markdown`, `image`, `space`, or `unresolved` for the states intake refuses), and its `via: 'self' | 'reference'` is the whole of read-only-by-reference. The projection puts it on the node's `display` (`closed | open`, then `editing | replacing`, which `beginEditing` and `beginReplacing` make only for Open own content), and `CanvasResource` and the embedded Map draw from that alone; presenting draws `PresentedResource` on the Stage from the same `ResourceContent` (ADR 0123). A Closed display carries no content. The Space Resource’s entity menu groups Rename/Create Reference, Enter/Open in New Tab, its three concise copy links, and Remove from Map. **`openResource` admits every Resource kind with content** — an Ur Resource has none (ADR 0122) — the `space` kind having gained a content arm with `entity-url-addressability/07`: an Open Space Resource draws the Map and Graph it selects, and in Edit authors the Space it points at. **ADR 0112 is built, bar Undo and Redo** (deferred until the application has history, ticket 07): root and embedded Maps use `createMapSurface` and `useMapSurface` over their own Space composition, explicit Map/Graph, occurrence and policy. Drawing holds keep an unlisted target composed; selection and continuation stay with their occurrence. The root canvas reads its surface as a drawn Map does: `SpaceCanvas` takes the surface, its reading, placement and the Space-level collaborators no surface holds, and draws under the surface's policy alone. Read `docs/agents/rendering.md` before changing these boundaries; delivery evidence is tracked under `.scratch/a-map-is-a-map/`. **A drawn Resource names nothing outside itself (ADR 0083)**: neither a Reference Resource's Target nor a Space Resource's target Space is drawn by name on it, so the kind glyph and the Reference Resource's dotted border are what tell those Resources apart from the ones they point at. Jump to Target and a possible Edit Target shortcut follow durable Resource URL implementation under `.scratch/alias-cards/issues/05-jump-to-alias-target.md`.

- **ADR 0069 / ADR 0079 — Entities have durable web addresses — built; ADR 0079's Map URL shape with them, Ticket 04 built.** Every Space, Resource, Graph and Map has a product URL built from its Id, encoded as an unpadded 22-character base64url value; the domain, stored documents and HTTP resources keep canonical UUID spelling. What draws the canvas is a Map, identified by its own UUID, and `/spaces/:spaceId/maps/:mapId` remains the durable Map URL shape. Accepted ADR bodies retain the earlier refinement history (`docs/agents/workflow.md`), so read their status blocks before their bodies.

- **ADR 0095 — SQL databases share one Space repository — built, tickets 25, 26 and 29 included.** `SqlSpaceRepository<Handle, Order>` (`src/persistence/sql-space-repository.ts`) serves `listSpaces`, `loadSpace`, the Meta lifecycle and `commit` for both databases, through each database's own `SqlStore` value — `postgresSqlStore` (`src/prisma/sql-store.ts`) and `sqliteSqlStore` (`src/sqlite/sql-store.ts`), both built over the shared `SqlStore`/`SqlTables` contract in `src/persistence/sql-store.ts`. `PostgresSpaceRepository`, `SqliteSpaceRepository` and `src/persistence/topology-preserving-update.ts` are deleted; the fast path they carried is absorbed into `SqlSpaceRepository` itself, and every HTTP runtime, CLI entry and test builds the one repository over its database's store rather than naming either adapter. A Revision is canonical non-negative decimal TEXT on both databases (`revision`/`exported_revision` are `text` in both `.prisma` contracts), read and written through the one shared codec in `packages/persistence/src/revision-codec.ts` — the `toDatabaseRevision` relabel and its `eslint-suppressions.json` entry are gone with it. `decideCommit` in `@project/persistence` (ticket 20) is still the one place a change set is validated, for the SQL repository, `MemorySpaceRepository` and `MemorySpaceBackend` alike; the SQL repository's private fast path (absorbed from the deleted `topology-preserving-update.ts`) still answers a revision conflict itself before ever reaching it. Ticket 25 moved the behaviour the two databases' integration files restated into the shared `SpaceRepository` contract (`test/support/repository-contract.ts`), and ticket 26 composed one target per database. Ticket 29 is fixed: the fast path reads the Meta identity inside the commit transaction and gives way to the complete-aggregate decision when there is none, so a store holding Space rows with no Meta row is refused on both paths. Ticket 31 named the unreachable arm and ticket 38 moved its recognition into the stores: the repository raises `PersistenceUnavailableError` (beside `AggregateInvariantError` in `packages/persistence/src/repository.ts`) for a failure nothing has named yet that its store's `SqlStore.isUnavailable` recognises, on every operation — reads outside a transaction and the post-conflict reloads included — and for `#lockMetaIdentity` losing the Meta row to concurrent replacements twice. **Classification reads what a failure carries, never how far the operation got**: the by-position rule that named every failure before a transaction callback unavailable is deleted, so a wrong password (`28P01`), a refused authorization (`28000`) or a missing database (`3D000`) is `unclassified`. PostgreSQL's policy lives in `src/prisma/sql-store.ts` — the driver's `SqlConnectionError`, `UNAVAILABLE_SQLSTATES` on a normalised `SqlQueryError` or on an un-normalised `pg` error's `code`, and an allowlist of Node socket codes, because `@prisma-next/driver-postgres` normalises nothing `pool.connect()` raises. SQLite's in `src/sqlite/sql-store.ts` is `SqlConnectionError` (BUSY and LOCKED) plus the one recognised-by-message compatibility check in the repository, the pinned runtime's plain `SQLite client is closed` `Error`. Readers ask `classifyStoredFailure`, whose third answer, `unclassified`, is 500 at HTTP — on every stored-seam route, the collection and single-Space reads included — and counts toward start-up giving up; it is never 503 by default. Ticket 32 removed `#decodeStoredSpaceRow`'s schema pre-parse, so a stored row's documents reach `loadSpaceSnapshot` raw and are parsed once, as `#loadEverySpace`'s already were. What remains open is `.scratch/database-persistence/issues/35`; 36 is resolved, its defect, the by-position rule, having been removed by ticket 38. **Ticket 37 is resolved**: `@prisma-next/sql-runtime` memoises its contract-marker read (`verifyMarkerPromise`) and never resets it on rejection, so a runtime whose first statement met an outage used to answer every later read with that same cached `CliStructuredError` `3006`, unclassified, without touching the network, for the rest of its life — `createPostgresDatabase` (`src/prisma/db.ts`) and the SQLite runtime's options (`src/sqlite/db.ts`) now both construct their runtime with `verifyMarker: false`, which in the installed 0.16.0 only ever logged on drift and never refused a query, so a direct read during an outage now meets the connection itself, which the store classifies unavailable, rather than the cached failure. ADR 0096 is the matching decision **not** to lift the aggregate lifecycle out of the repositories that decide it — now two, SQL and memory, rather than three.

- **ADR 0041 — Graph is the first-public name for Route — built.** The vocabulary rename is complete: schemas, code, tests and fixtures use Graph, Graph navigation and Traversal history; Route and Walk survive only in historical records and qualified HTTP or graph-layout routing prose. Unqualified `Graph` and `GraphEdge` name the domain; strategy and render intermediates use `LayoutStrategyGraph` and `GraphRenderEdge`; the canvas is `SpaceCanvas`. ADR 0040's Map-owned first-public document was a separate structural change, landed after it by `.scratch/first-public-aggregate/`.

Deeper build-status and gotcha detail for the ADRs that see the most churn now lives in the scoped `docs/agents/*.md` files listed under "Agent skills" below — read the one that covers the area before touching it.

## Commands

- Install: `pnpm install` (Node >= 26.8.1, pnpm 9).
- Dev: `pnpm dev` (app at http://localhost:5173) is the normal PostgreSQL-backed HTTP runtime and requires the configured database to be up. `pnpm dev:new` (port 5174) serves an initially empty memory repository; server-side startup creates the normal one-resource **new space** once (ADR 0018). `pnpm dev:fixture` (port 5175) serves the tracked fixture through the same HTTP boundary over an isolated memory repository. `pnpm dev:roadmap` regenerates and serves the V1 dependency-map Space on port 5176 through that memory runtime. `pnpm dev:sqlite` (port 5177) is the opt-in file-backed SQLite host (`SQLITE_PATH`, default `.scratch/sqlite/hyper.db`); PostgreSQL remains the default. `pnpm hyper import --store sqlite` and `pnpm hyper export --store sqlite` reach SQLite, require `SQLITE_PATH` and a migrated file, and must not share a file a running host has open. Edits in any memory runtime survive browser reloads for that server's lifetime. None writes source files except `dev:roadmap`, whose generated files stay under its ignored `.scratch/v1-release/roadmap-space/` directory. **Never start, stop, restart or kill a server you did not start**, and do not free a port (`kill`/`pkill vite`/`lsof -ti:5173 | xargs kill` etc.). `pnpm dev` is not port-strict: a second one (say, in another worktree) takes the next free port and prints it — which is also why an agent must not start one. The scripted `dev:*` hosts stay `--strictPort`, and a second `pnpm dev` usually lands on 5174, `dev:new`'s port. **Whether a server is running is a fact about the machine, and this file cannot tell you.** Look, don't assume: `lsof -nP -iTCP:5173-5299 -sTCP:LISTEN` — wider than the five scripted ports, because a `pnpm dev` that found them taken is listening above them. A running dev server is hot-reloading (Vite HMR + React Fast Refresh), so your edits are already live in it; if none is running, nothing is serving your change and no amount of editing makes it visible. To verify changes, use the tests (Playwright starts its own servers) and CI, as "Before claiming done" sets out — never a dev server.
- Run: `pnpm hyper run <dir>` runs an Aggregate directory (ADR 0117, ADR 0124): it Imports `<dir>` into a fresh memory store, serves the application on port 4173 or the next free one (`--port <port>` fixes it), Exports back to `<dir>` once edits have been quiet for about a second — in place, like every Export (ADR 0119): only the files Import reads, unchanged ones skipped, each changed one renamed over its target, `<dir>` and its Space directories never moved, and git rather than Hyper answering for a write that fails part-way — and flushes on SIGINT, SIGTERM or SIGHUP before exiting zero; a second signal exits at once. A missing or empty `<dir>` (dot-entries such as `.git` do not count) is refused non-zero, naming `pnpm hyper init <dir>`, which writes a new aggregate there and exits without serving; an invalid one, or a single Space directory with no `hyper.json`, is refused non-zero with the intake's errors. It opens the browser unless `--no-open`, and a relative `<dir>` is relative to where `pnpm` was invoked, for every `hyper` verb. **Unlike the dev hosts, an agent may start and stop `pnpm hyper run --no-open` itself**, on a directory of its own (a temp directory, never the human's working directory) — it is how `test/integration/run-command.test.ts` runs it, a database-free file that CI runs in the `postgres` job because `vitest.integration.config.ts` takes every integration file not named `sqlite-*`. Stop it with SIGINT so its last write lands, and stop it before editing the directory's files, or its next write overwrites them. The `hyper` script `exec`s node, so pnpm signals the launcher (`src/cli/run-launcher.ts`) itself rather than a shell that forks it, and the launcher starts the run (`src/cli/run-process.ts`) in a process group of its own and forwards it the signals it receives, once each: under pnpm one Ctrl-C reaches the launcher twice (the terminal's and pnpm's), so it drops a repeat of the same signal within 250ms, and pnpm forwards a second Ctrl-C as SIGTERM, which is never dropped. A failed write is tried again after the quiet period.
- Verify: `pnpm verify` runs `typecheck:toolchain` -> `typecheck` -> `typecheck:packages` -> `ui:catalog:check` -> `lint` -> `lint:anti-slop` -> `format:check` -> `test:coverage` (i.e. the ADR 0061 compiler assertion, then `tsc --noEmit` over the root program, then `pnpm -r typecheck` over each package's own config, `eslint . --max-warnings=0 --prune-suppressions`, `oxlint -c .oxlintrc.json` over the 15 vendored anti-slop rules, `prettier --check .`, `vitest run --coverage`). **`typecheck:toolchain` runs first** because a typecheck against the wrong compiler still passes, so proving which `tsc` ran has to happen before trusting what it said. CI runs that chain as **two jobs**, so a red lint and a red test suite are different check names: `verify:static` is the first seven commands and `test:coverage` is the eighth, and `verify` is defined as those two — the list of eight lives in `package.json` and nowhere else, so a developer's one command and CI's two cannot drift. **Both typechecks are needed**: the root program's `include` has `"*.config.ts"`, and `*` does not cross directory boundaries, so `packages/app/vite.config.ts`, `vite-space-http-plugin.ts` and `http-server-build.config.ts` are covered only by the per-package pass. Warnings fail the lint run; coverage thresholds are per-package and pinned at what already holds — the `thresholds` block in `vitest.config.ts` names the gated packages — with no global threshold on purpose.
- Test: `pnpm test` (Vitest, `vitest` for watch). Unit + property tests (fast-check) live in `packages/*/test`.
- Mutation testing: `pnpm mutate:session` and `pnpm mutate:graph` run StrykerJS (`stryker.conf.mjs`) over one source file against a named oracle. **A deliberate local diagnostic, never a gate** — not in `verify`, not in CI, `thresholds.break` is `null`, and the tickets that introduced it forbid a threshold. `--mutate` and `--testFiles` are chosen as a *pair* per campaign, because the whole suite cannot run inside Stryker's sandbox (the `test/unit` scans that shell out to `git ls-files` — `current-domain-vocabulary`, `conflict-markers`, `docs-agents-citation-accuracy`, and those reading through `test/support/structural-scan.ts` — get `[]`), so a campaign names the tests that are the oracle for the code it mutates — and nothing keeps that pairing honest but the reader. A score is evidence for a conversation about the oracle, not a number to move; the standing limits on what one means, including this runner's `static: true` false survivors, are in `.scratch/mutation-testing/engine.md`. Output goes to the gitignored `/reports/` and `/.stryker-tmp/`.
- E2E: `pnpm e2e` (Playwright, Chromium only) stays database-free and exercises HTTP; `pnpm e2e:fixture` selects only the tracked-fixture project. Every test owns a fresh Vite host, `E2eMemorySpaceRepository` and catalog; reloads and extra pages inside that test share them, while no revision leaks to another test. The `chromium` project imports the tracked fixture and `new-space` starts empty so database startup creates one resource. Hosts use worker-scoped ports beginning at 5300, away from the human's 5173–5175. `pnpm e2e:postgres` is the separate one-test project proving a real PostgreSQL edit survives a fresh Vite host. **CI runs it, as the last step of the `postgres` job** — it sits there rather than in `e2e` because it applies no migration of its own and needs the database `test:integration:postgres` has already migrated. Locally it stays opt-in: run it only with PostgreSQL up and migrated, and always stop PostgreSQL afterward. `pnpm e2e:sqlite` is its SQLite counterpart, proving a real SQLite edit survives a fresh Vite host on the file `SQLITE_PATH` names. **CI runs it too, as the last step of the `sqlite` job**, after that job's `test:integration:sqlite` has migrated the job's temp file — the same placement for the same reason. Locally it stays opt-in: run it only with `SQLITE_PATH` set to a file `pnpm db:migrate:sqlite` has migrated. **Both proofs live in `test/e2e/`, not `packages/app/e2e/`, and both drive the application surface** — each opens a Space and addresses the Space's name, its Resources and `persistence-status` through the same helpers the normal suite uses (`test/support/restart-proof.ts`, shared between the two rather than copied). So a change to the Space's chrome breaks both exactly as it breaks the others, and **nothing in `verify`, `e2e` or `e2e:ladle` will tell you**: the two commands that can observe it each need a database, so a surface change that swept `packages/app/e2e/**` and stopped there reaches CI red. When you change what the chrome draws, grep `test/e2e/` too — it now holds both proofs. One-time first: `pnpm exec playwright install chromium`.
- Ladle E2E: `pnpm e2e:ladle` runs `playwright.ladle.config.ts` over `packages/app/ladle-e2e/`, against a `ladle serve --noWatch` catalogue it starts itself on port 61100. This is the behaviour half of ADR 0052's story evidence and it is **its own CI job**, run by neither `verify` nor `e2e` — so a component change that breaks a story is only caught here. The two Playwright configs share one flake policy (`retries: 2` and `failOnFlakyTests` under CI, `retries: 0` on a laptop); under `failOnFlakyTests` a retry that passes still fails the run, so the retries buy the trace and the reproduce-or-not signal rather than tolerance for a blip.
- Build: `pnpm build` (Vite build of the app).
- PostgreSQL integration: copy `.env.example` to the ignored `.env`, fill its password and matching `DATABASE_URL`, then run `pnpm postgres:up` followed by `pnpm test:integration:postgres`. Always finish with `pnpm postgres:down`; it keeps the named volume. `docker compose down --volumes` is the destructive reset. `pnpm test:integration:sqlite` is the matching file-backed suite (temp file, no Docker). Normal `pnpm verify` and `pnpm e2e` do not require PostgreSQL.

## Package layout & boundaries

Seven `@project/*` workspace packages under `packages/`:

- `core` — domain model. Zod schemas (`schema.ts`, incl. `spaceFileSchema` — the space-file shape) + schema-derived `Resource`/`Graph`/`GraphEdge`/`Map` types (`types.ts`). No React, no framework deps.
- `graph` — pure graph logic over a `Space`: `loadSpace` (the one intake — parse, validate references including duplicate Edges within a Graph, index), the `Space` type and the one `SpaceLookup` it carries, Graph→Edge derivation, traversal, the Graph palette with `nextGraphColor`, the colour rule every Graph creation gesture stores by (`graph-color.ts`, so `newSpace` and persistence's first-load Graph can reach it), and the `LayoutStrategy` contract (`LayoutStrategyGraph`, `buildLayoutStrategyGraph`, `gridStrategy`, `positionedStrategy`). Depends only on `core`. **Its index is curated and there is no `export *`**, and the unit of curation is the **module**: it names every function something outside the package calls, and every type exported by a module those calls reach — whether or not a consumer writes that type down today. `frontmatter` and `validate` are absent as whole modules: the first is how `resource-file` reads a fence, the second runs inside `loadSpace`, which ADR 0010 makes the one intake. `SpaceReferenceError` is off the surface although `loadSpace`'s `SpaceError` union names it, while `ResourceFileError` in that same union is offered — reachability is not the test, and neither is depth. Adding a name is a deliberate act — `test/unit/graph-package-surface.test.ts` holds the index's declarations and the module they produce to one list, so a new export fails until it is listed there. A test of an internal helper imports it from its own module rather than through the index.
- `http` — browser-safe Fetch transport: the Hono `/api/spaces` route tree, request and response policy and the inferred `SpaceHttpApp` client contract. It *consumes* the narrow `StoredSpaceRepository` seam rather than declaring it — that lives in `persistence`, beside the `LoadedSpace` and `SpaceSummary` it is written in terms of. Depends only on `core`, `persistence`, Hono and runtime-neutral media parsing; imports no host, database, app or render implementation.
- `persistence` — browser-safe `SpaceBackend` and `SpaceSession` contracts, optimistic revision handling, commit coalescing, retry/conflict states, and the memory adapter. It also declares the **stored** side of the seam once, for both consumers: `StoredSpaceRepository` and `RepositoryCommitResult` (`src/repository.ts`), which `@project/http` takes and which `src/persistence/space-repository.ts` extends into `SpaceRepository` by adding `initializeAggregate`, `replaceAggregate` and `markExported`. The server seam is a superset, never a second declaration — a `Resource`/`Graph` change cannot leave the two sides disagreeing, and the browser still cannot name the aggregate lifecycle or export because the seam the Fetch application consumes does not declare them. **Two lifecycle doors and no mode parameter on either (ADR 0078)**: the order-sensitive `importSpaces(input, 'insert' | 'truncate')` that used to sit there is gone, because it inferred Meta from array position and hid a destructive choice in an argument. Seeds, fixtures and tests seed through those same two. Depends on `core` and `graph` so every committed snapshot passes the normal domain intake. It also owns **`createObservableState`**, the one observable-state seam behind `SpaceSession`, Navigation and SpaceAuthoring's own `getState`/`subscribe` interfaces: publication installs the next state synchronously, snapshots the subscriber set so a listener added mid-publication begins at the next one rather than part-way through the current, contains synchronous throws and thenable rejections, continues to the observers behind the failure, and reports through a sink `createNonThrowingReporter` has made incapable of interrupting the work it describes. Each collaborator keeps its own state and its own interface — only notification moved. **`app` therefore imports observable state from `persistence` although Navigation has nothing to do with persistence**; `.scratch/authoring-seams/issues/01-one-observable-state-module.md` records why that home was taken and what the alternatives cost.
- `react-flow-adapter` — the React Flow (`@xyflow/react`) projection: projects a Space and its Map-owned Graphs into RF nodes/edges and renders `ResourceNode`. It implements no `LayoutStrategy` — elkjs and the strategy built on it left with ADR 0086, and the two that survive, `gridStrategy` and `positionedStrategy`, are `graph`'s.
- `ui` — reusable, presentation-agnostic React components + shadcn-style primitives (Tailwind v4, CVA, Lucide, and Base UI controls including `Button`, `Select`, `Popover`, `Dialog`, `Menu` and `Combobox`), the `StatusPanel` operational-feedback module, plus the `AppShell` that frames the canvas. **The registry `Sidebar` is gone, and so is everything that stood only beside it**: ADR 0082 retired the gutter and `CommandDock` is a `Toolbar` over the canvas instead, so `.scratch/command-dock/issues/08` deleted `components/sidebar.tsx` with the cookie-backed open state and `Ctrl/Cmd-B` it carried, `components/sheet.tsx` behind it (`components/skeleton.tsx` went too and is back, regenerated from the registry for `ResourceImage`'s loading state), `hooks/use-mobile.ts` behind those, `AddResourceControl` (the Dock's `CreatePeers` offers the Resource kinds as peers rather than as a split control), and `OpenSpaces` with `components/tabs.tsx` (the Dock's Open Spaces menu is the open set's one surface). The words that reported an unwell open Space outlived the strip as `open-space-status.ts`. Regenerate a registry primitive from shadcn if one is wanted again; do not restore `AddResourceControl`, whose recorded design — a split button with a hidden default — contradicts `CreatePeers`'s on purpose: the kind is chosen at creation, so neither is a default. `CreatePeers` replaced the `CreateMenu` that disclosed them, which charged two presses for every creation including `markdown`, the one kind that then completed its Edit on activation; **ADR 0089 made that true of every kind and took `reference` out of the cluster altogether**, so `CreatePeers` draws four glyphs — markdown, space, image, whose one press opens the file picker and completes on the files chosen, and ur (ADR 0113) — and a Reference Resource is created from the Resource it points at. Create stays outside the Resources list. On a side edge the Resources cluster packs onto one row rather than taking a verb track each, giving up the `1fr` name track the three *authored* names need and it does not — "Resources" is a fixed word. Both are ADR 0052 treatment, so the evidence is `parity-claims.ts`'s `command-dock-creates-each-kind-in-one-press` and `command-dock-packs-resources-onto-one-row` rather than an ADR. `Drawer` (`components/drawer.tsx`, a Base UI wrapper rather than a registry copy) and `AppShell`'s `insetEnd` went after `08`, which ran while `ResourcesDrawer` still mounted them: once the Resources list became a Popover nothing overlaid the end edge, and `.scratch/command-dock/issues/22-retire-the-registry-drawer-and-the-yielded-strip.md` deleted both, so the shell no longer yields a strip to anything. **One command surface, drawn wherever the product draws chrome**: `CommandSurface`, `CommandToolbar` and `command-surface.css` carry the neutral translucent panel, and both the Command Dock and a Resource's toolbar (`ResourceRailActions`, floated by `ResourceNode` in React Flow's `NodeToolbar` while the Resource is selected, ADR 0102) mount it — so the Resource rail is neutral and the Active Graph's colour stays on the handles and Edges where it names a Graph (`.scratch/command-dock/issues/12`), and `test/unit/command-surface-sharing.test.ts` holds the ownership a rendering test cannot state. `ChoiceMenu` is how a Map or a Graph is chosen: the Dock's Map and Graph clusters and an Open Space Resource's two choices all draw it, each supplying its own set, selection and operation, because the operation is deliberately not shared — one moves the canvas the author stands on and the other writes which Map a Resource shows. `Select` has **no consumer again**: ADR 0089 retired the Space Resource creation pane whose target-Space field was the last one, which also closes the "one flow asking two ways" seam `docs/agents/ui.md` recorded. It spent a while with none before, after the three renderer selectors were deleted, and it carries an inventory entry meanwhile — as does `Dialog`, whose only consumer was the `ResourcePane` both creation panes were built on. `Textarea` has one again after its own while with none, the Resource body having become a source editor: `InlineTitleEditor` draws it in place of `Input` wherever a Title may be written on more than one line, which ADR 0083 makes the Resource's Title and no other entity's — `CanvasResource` sets `multiline` and the Dock's header does not. Depends on `core` only. **Markdown source is edited through `MarkdownSourceEditor`, the one component allowed to know CodeMirror exists (ADR 0063, refined by ADR 0067).** **`ui` owns the split point that reaches it**, `markdown-source-editor-lazy.ts`, beside the component that needs it — `MarkdownResourceBody` is a second consumer inside this package, and a static import from it would put the whole stack into the barrel and from there into every consumer of `@project/ui`. So `app` no longer names the editor at all and the `@project/ui/*` ESLint zone is a plain bar with no negated entry. Two responsibilities are the wrapper's and not a caller's: which keys it withholds from CodeMirror (`PANE_OWNED_KEYS` — `Escape` and `Mod-Enter`, the two exits the mounting surface spends, both of which `defaultKeymap` would otherwise take), and every `.cm-*` selector. A caller that needs a say over CodeMirror's appearance sets a custom property the component's own theme reads; no stylesheet in the repository may name a `.cm-*` class, and `test/unit/codemirror-encapsulation.test.ts` holds both that and the dynamic-import split, scanning both source trees. **Choosing a Resource is the Resources list, `ResourcesPopover`, in one of two purposes** (`.scratch/edge-toolbar/issues/07`): the Dock places what the selected Map does not, and Connect to Resource, in a Resource's Actions menu, chooses an Edge's other end from what the Map *does* place, bar that Resource — same search and kind filters, no drag and no Spaces source, a refused target kept as an unavailable, still focusable row carrying its reason (asked through `connectChoices`, the pointer gesture's own eligibility), and a last New Resource row that is the keyboard form of the Option/Alt empty drop. A choice draws the Edge in the Active Graph and continues at it, selected and focused. `ResourceSearchCombobox`, the editable combobox Edge endpoints used to choose through, has had **no consumer** since reconnection went (`.scratch/edge-toolbar/issues/05`) and carries a design-system inventory entry meanwhile. Do not add a second picker for choosing a Resource.
- `app` — wiring/composition: **`compose-app.ts` states what an opened Space is composed of, once** — `composeCore` answers the one working-space reader, `currentSpace`, the opening Map and Navigation; `composeApp` adds Space Authoring, the render adapter, the continuation and Edge Authoring, in the order they have to be built in — the continuation before Edge Authoring, which publishes into it. **Where an Edit continues is that one module, `continuation.ts`**: a gesture requests `{ target, select, then }`, one pending continuation is held rather than a queue, and two adapters spend it — `CanvasContinuation` inside `ReactFlowProvider` for the canvas targets and `ChromeContinuation` at the App root for the chrome ones. `ContinuationControl` has one member, `'map-name'`: the two pane return addresses went with the panes, and what replaced them is Add Map continuing in the new Map's name. **There is no creation pane and no reducer behind one**: ADR 0089 deleted `resource-creation.ts` with `NewReference`, `NewSpaceResource` and the `ResourcePane` they were built on, because every Resource creation completes its Edit on activation and takes what it needs from the context the gesture was made in. Every collaborator closes over that one reader, which is what gives them a single `Space` identity to share. **Open Spaces (`open-spaces.ts`) is the one caller of `composeApp`** — it composes each opened Space once, holds the result on the `OpenSpace` entry, and hands it to `createApp`, which builds the component over a composition it is given rather than making a second one. A test that wants collaborators calls `composeCore` or `composeApp` rather than writing the chain out. Also: Navigation and Space Authoring, each keeping its own state behind `createObservableState` and read through one `useSyncExternalStore` (the Active Graph, Traversal history). **Open/Closed is not among them** — it is authored on the Map (ADR 0064), so Navigation carries no opened-Resource field; the Zustand-backed **render adapter**, which owns the published projection, drag bookkeeping and the discriminated `none | resource | edge` canvas selection; **Edge Authoring**, which owns the complete Edge interaction lifecycle over both of them; product-URL navigation, Space loading, the canvas and its camera, the presenting Stage and its chrome, hand-rolled CSS. Zustand is the render adapter's and nothing else's — Traversal history lives in Navigation. **There is no router library, and putting one back is a decision rather than a convenience.** `@tanstack/react-router` went when ADR 0069 gave entities durable web addresses: the destination contract is declared once in `@project/http` (`ProductDestination`, `productDestinationPath`, `resolveProductDestination`) and the Node host resolves the same one the browser does, so a router would have been a second copy of that table, in the browser only, disagreeing with the host the day either moved. **`browser-location.ts` is the one module that knows a browser exists**, and **no call site decides what the browser does** (ADR 0081). It takes the five-member `HistoryApi` — required with no default, the way `newId` is (ADR 0109) — and **`createBrowserHistory` in `browser-history.ts` is the one adapter that implements it**: it takes a `NativeBrowser` (the part of `window` it reads and writes) rather than reaching for `window`, and the application's `window.history` writes — `pushState`, `replaceState` and the return that undoes a held traversal — and its `window.location` reads all go through it, alongside `main.tsx`'s one `window.location.pathname` read. **`browserHistory()` in `space.ts` is where `window` is named**, by handing it to that adapter; `createSpaceStartup` does not reach the browser itself, it selects that adapter as the default of its third argument, which is what makes the composition root the place the ambient browser is named (ADR 0081). The `onPopState` listener answers a `PopStateAnswer`: `undefined` keeps the traversal, `false` holds it — the adapter returns the browser to the entry the traversal left and keeps both entries (by that entry's key through `navigation.traverseTo` where the browser has the Navigation API, so the return lands there wherever the traversals queued ahead of it have taken the browser; otherwise by a relative `history.go`, which such a traversal can push past either end, where the browser drops it and the address stays on another entry until the next traversal), and a Back or Forward the reader queues while it is returning is asked about like any other traversal, the return continuing while the listener holds — and a promise answers either later, which is how a Back refused by an image replacement that began while its destination was opening is still held. A late `false` holds while no later traversal has been kept and no entry written since; a later traversal the listener held does not count, so a refusal that arrives while that one is still returning sends the browser back to the entry the earlier traversal left (`packages/app/test/browser-location.test.ts`, `holds a Back refused by a replacement while a later held Back is still returning`). The adapter numbers the entries it writes (`hyperHistoryIndex` in `history.state`) to know how far to rewind, and numbers a fragment link's entry as it arrives, because the browser writes that entry after the current one and fires `popstate` for it; only a same-document entry written with no `popstate`, such as another script's `pushState`, goes uncounted, and a rewind across it misses by one entry; its index arithmetic is proved against a stand-in browser in `packages/app/test/browser-history.test.ts`, a real browser holding Back and Forward during a replacement in `packages/app/e2e/image-resource.spec.ts`, and a return by key landing on the held entry while the reader jumps on from each arrival in `packages/app/e2e/held-traversal.spec.ts`. Every rule below is proved in the node environment against a recording adapter (`browser-location.test.ts`). `createOpenSpaces` composes it once for the session, because there is one history stack, and calls `follow(app)` with whichever composition is on the canvas; `useAddressedResource` (`addressed-resource.ts`) reads the two fields it publishes, `addressedResourceId` and `destinationNotFound`, through one `useSyncExternalStore`, and `useSpaceAddresses` keeps only the clipboard half of Copy link. Navigation answers a `NavigationAddress` — the selected Map, the Active Graph and the presenting Resource, derived from its state and never stored on it — and that module hands the address, plus the Resource the location addresses, to `destinationSync`, a pure function that compares the position against what the current pathname resolves to and answers `push`, `replace` or `none`. `none` is what lets `popstate` move Navigation without the move pushing an entry over the one the browser just navigated to, and what makes a redundant notification — StrictMode's second invocation included — decide nothing. So a Navigation operation is called for its own sake and never paired with a history write: **do not put a `moves = getState().x !== y` comparison beside a call site**, which is the five-diff shape ADR 0081 removed. The `popstate` listener still reopens whatever `resolveProductDestinationInSnapshot` answers for the current pathname, and a location it cannot resolve is *reported* rather than corrected — but only for the arrival: the first move away from it is written and clears the report. **`canvasProjection` is what the render adapter publishes**: `canvasProjection(space, resolved)` answers a `PendingCanvasProjection` — the `strategyGraph` it builds, the `colors` it derives from the Space, the `visibleGraphs` it reads off the Map's own `graphs`, and a `project(laidOut, interaction)` returning the React Flow nodes and edges. It takes `@project/graph`'s `ResolvedMap`; **`map-resolution.ts` is the one module between a Map id and the Map it names** — `requireDefaultMap`, `resolveMap`, `mapResources` and `MapNotFoundError`, imported rather than injected, and there is no wrapper type around them. None of those is state anything carries. It is a pure module and deliberately not a hook — no store, no React, no DOM — so the whole derivation is tested in the node environment (`canvas-projection.test.ts`, and a property test for the handle-resolution invariant React Flow warns about as #008). The `LayoutStrategyGraph` it takes is **not nullable on purpose**: there is nothing worth projecting before a strategy resolves, and requiring one is what stops a caller publishing a projection whose every Resource sits at the origin. The word *projection* names this bridging construct in `app` and the adapter and is deliberately absent from `CONTEXT.md`, whose render-layer section forbids inventing a domain term between React Flow's vocabulary and ours.

Hard rules — **all four are now enforced, not just documented**. Two layers, because neither catches what the other does: ESLint `no-restricted-imports` zones catch package specifiers and relative escapes (`../../*`), and each package's narrowed tsconfig `paths` makes an illegal alias unresolvable. `rootDir` is set on `core` alone — anywhere else it rejects the legitimate `@project/*` import too, since the referenced file resolves outside the package, which is why the relative-escape half is a lint rule rather than a compiler setting. Before this, `core` could import `@project/ui`, cycle back into `@project/graph`, and reach `../../app/src/store` with typecheck and lint both green.

- Domain logic stays out of React (keep it in `core`/`graph`).
- React Flow stays out of the domain and the reusable UI: **`core`, `graph`, `http`, `persistence` and `ui` must not import `@xyflow/react`**, which `no-restricted-imports` in `eslint.config.js` enforces. `react-flow-adapter` holds the projection into React Flow, and `app`, the composition layer, imports `@xyflow/react` as well. The same zone names elkjs, which no package depends on (ADR 0086). Read that entry as banning a *render-time* engine from the domain, not as siting a returning one: ADR 0086 puts Auto-arrange in `graph`, attached to an Edit, so building it means re-siting the ban rather than obeying the lint message.
- Reusable UI goes in `ui`; app-specific glue goes in `app`.
- A module bundled into a Vite config (`vite.config.ts`, `http-server-build.config.ts`) imports `@project/*` by **relative path only** — a bare specifier is externalized and hands Node the workspace TypeScript, and the dev server then will not start at all.

## Conventions & gotchas

- **Strict TypeScript everywhere**, incl. `noUncheckedIndexedAccess`, `noUnusedLocals/Parameters`, `noImplicitOverride`.
- **`package.json`'s TypeScript entries look wrong and are not (ADR 0061).** `@typescript/typescript7` is TypeScript 7 and owns the `tsc` binary; the package name `typescript` resolves to `@typescript/typescript6`, which owns `tsc6` and the `createProgram` API `typescript-eslint` and `prisma-next` need. `tsc` is the only type-checking truth here — a TypeScript 6 diagnostic is not a defect to fix, and `tsc6` is a migration aid, not a gate. Do not unify the two names. `pnpm typecheck:toolchain` fails the moment either half stops holding, and the ADR states the condition under which the bridge is removed.
- **`eslint-suppressions.json` is a ceiling, not a backlog (ADR 0062).** It records the narrowing assertions that predate the rule, and it is generated — never hand-edited, never added to. `--prune-suppressions` runs in `verify`, so it only shrinks, and it shrinks as files are edited for other reasons rather than as scheduled work. A new assertion fails lint even in a listed file; adding one to a file with suppressed sites reports every assertion in that file, because a count-based baseline cannot tell which is new.
- **`verbatimModuleSyntax` + ESLint `consistent-type-imports` are on** — use `import type` for type-only imports or lint/typecheck fails.
- **Cross-package imports** use the `@project/*` path aliases: declared in `tsconfig.base.json`, mirrored in `vitest.config.ts` `resolve.alias`, and **narrowed per package** in each `packages/*/tsconfig.json` so a package can only resolve what it may legally depend on. Vite needs no alias at all — it resolves through the workspace `exports`, and the third copy that used to sit in `packages/app/vite.config.ts` is gone (removing it built an identical bundle). Vitest's *is* load-bearing: the root package declares no `@project/*` deps, so there is no symlink to resolve through. Two lists to keep in sync, plus the package's own narrowed one.
- **Relative imports inside a package are EXTENSIONLESS** (`./foo`, not `./foo.ts`).
- **Use a functional core and imperative shell for cross-module coordination.** Compute and validate the complete next state in a private pure core before producing side effects; a thin imperative shell then updates collaborators in an order that preserves valid intermediate states. Expose the coordination as one operation rather than returning a plan for callers to execute. Keep framework and store events outside the seam, depend on existing module interfaces, and do not manufacture single-adapter ports for deterministic private helpers. An edit event is a notification, not state transfer: each editor first installs its authoritative completed state and only then emits the notification; the coordinator derives the next Space from the current state owned by its collaborators rather than from state carried by the event.
- **Inject nondeterminism once when composing a module, not through each domain operation, and never by mocking the ambient generator (ADR 0109).** A module that mints identities, reads time or otherwise depends on a nondeterministic in-process function receives that function at composition so tests can supply a deterministic one; its operational interface then stays in domain language and does not repeat the dependency on every call. `createSpaceAuthoring` takes `newId` exactly as it takes `reportObserverError` — **required, with no default** — and mints the Resource, Map and Graph ids of a completed Edit from it. **`packages/app/src/compose-app.ts` supplies it explicitly**, so every authored identity has one visible source, and **`createOpenSpaces` takes the same `newId` — required, with no default — and supplies it to every `composeApp` call it makes**, alongside its `reportObserverError`; omitting either lets `composeApp`'s own defaults reinstate the ambient generator and `console.error` behind the one owner's back. **Don't answer a test's need for a known id with `vi.spyOn(crypto, 'randomUUID')`** — ADR 0109 rejects it, on the grounds ADR 0016 first gave when `loadSpace` faced it: a constant collides across a property test's cases so it needs a counter, at which point a generator exists anyway; `randomUUID` is an unseedable CSPRNG, so controlling it means owning it; and the mock stops working in silence the day the implementation moves to v7 and reads the clock as well as the entropy pool. The seventeen spies this replaced also hid a real defect — one of them named two ids for an Edit that mints three, so a Map quietly took an id from the real generator. Tests name the ids they assert on through `packages/app/test/minting.ts`. Do not hide nondeterminism behind global mocking, and do not manufacture a port or adapter seam when the dependency has one in-process implementation. Deterministic rules stay uninjected — `titles.ts` mints `Resource N`, `Map N` and `Graph N` through three named operations with the `<Prefix> N` arithmetic private, because there is nothing there a test would want to replace.
- **`path` means a file path only.** The document and the implementation agree on `graphs`/`activeGraph` — the sentence here used to contrast a planned spelling with a built one, and the rename closed that gap. Remaining `path` identifiers are filesystem paths, the HTTP and product URL paths `@project/http` builds and matches (`productDestinationPath`, `SPACE_COLLECTION_PATH`, Hono's `context.req.path`), or React Flow's own SVG `edge-path` class — don't “fix” those.
- **`CONTEXT.md` reserves “arrangement” for ordinary prose rather than a domain entity, and the code honours that.** The one deliberate survivor is `packages/graph/src/layout.ts`, which quotes the avoid-list in its own doc comment. `AuthoringRefusal` uses `placement-pending`, and `CanvasContent`'s third kind is `'resources'`, produced by `canvasContent`'s `hasResourcesOnCanvas`. **`'resources'` is not a synonym for Placement** — it means “Resources are mounted on the canvas”, which stays true while replacement placement is still pending.
- **A comment may only assert what its writer has checked (`docs/agents/workflow.md`).** Four rules, each from ticket 14, where each was broken by a claim that opening the named file would have settled. **A negative result belongs in a ticket, never in source** — "X was tried and reverted because it broke Y" forecloses the work, reads as settled because it is in the source, and is never re-run; `App.tsx`'s `entityActions` carried six embedded-Map failures that did not reproduce. **No measurement in source**: commit the instrumentation, or put the number in the ticket with its method. **A claim about another module names the test that holds it** — that family already exists (`command-surface-sharing`, `codemirror-encapsulation`, `graph-package-surface`, `current-domain-vocabulary`), and a subagent's summary is a report, not a fact. **A decision called load-bearing needs something that fails when it is reversed**; this ticket's reconciliation order was documented that way and swapping it broke nothing. None is lintable; they hold in review.
- **A comment carries what the code does, why, and the invariant it keeps, and not its lineage (`docs/agents/workflow.md`, "What a comment may carry").** Remove what the code replaced, retired or "used to" do, and any alternative it rejected. That history belongs in the commit message, the ADR or the ticket. If the history was guarding an invariant, keep the invariant as a present-tense constraint. Keep an ADR or `.scratch/` citation only where it names a constraint the code cannot show. A `SAFETY:` comment, the comment in an intentionally empty block, and the few comments a scanning test asserts are still present are all read by a gate, so shorten them without deleting what the gate reads.

- **"workspace" is guarded, not merely avoided (issue 11).** `CONTEXT.md` retires it for two readings — the loaded Space, and the app chrome around it — and issue 08 brought the code into line; `test/unit/current-domain-vocabulary.test.ts` is what stops it drifting back. It reads the bare word over the source the repo authors (`packages/**`, `src/**`, `test/**`, `scripts/**` and the root `.ts` configs). **Prose Markdown documents are not scanned by any arm of that test**, so a retired word in `AGENTS.md`, `CONTEXT.md`, `docs/**` or a skill is a review finding rather than a build failure. Root tool configuration — `eslint.config.js`, `.oxlintrc.json`, `.coderabbit.yaml`, `ci.yml`, the two `pnpm-*.yaml` — is out by construction, each being written in some tool's vocabulary. Say Space for the loaded Space, and Dock or canvas for the chrome. **pnpm's sense is untouched, and where it is allowed is the exemption list**: five modules (`packages/app/workspace-aliases.ts`, the shared `packages/app/database-vite-config.ts` that spends it for both Vite targets, `packages/app/http-server-build.config.ts`, `scripts/check-typescript-toolchain.ts` and its test), each asserted to still contain a hit so an exemption cannot outlive its reason. The dependency protocol is forgiven **by the line, not the file** — a manifest is read like anything else, so a script name, an `imports` entry or a renamed package is still reported.
- **The word `CONTEXT.md` retires for a Space is guarded too, and the guard reads shapes rather than the word.** ADR 0010 retired the shipping-ledger name for the top-level value, `CONTEXT.md:9` says "retired from the code, not merely avoided", and nothing in `verify` noticed until now. The same test holds it, in two scopes. **Every scannable file** is held to the shapes a domain name is written in — the PascalCase compound in either direction, the camelCase one, the screaming constant, the kebab-case refusal code or test id, and the word capitalised as a noun. **Implementation source** (`src/`, and each package's own `src/`) is held to the bare word as well, because there is no package file to read there and the only surviving sense is ours. So npm's and pnpm's sense stays writable where it is genuinely meant: bare and lowercase, in a comment or a script. Three identifiers naming a parsed package file are masked by spelling, and the retirement notice on `core`'s space-file schema is masked as a quotation; each mask is asserted to still be earning itself. Capitalise it, compound it, hyphenate it or scream it and the scan reports it, anywhere it scans.
- **Two blind spots in that test were closed with it, and both are worth knowing before adding an arm.** A retired word carrying an **English suffix** offers no capital, no word boundary and no hyphen, so every compound arm reads straight past it: the retired spelling of `mapless` went green through `verify` on the aggregate round-trip branch and was caught by a human reviewer. The Map block now has a suffix arm, with the plural ruled out by name so the compound arms keep owning it. And a **cited foreign path** is forgiven by `CITED_PATH` rather than by a shape — React Flow's docs name a section after the retired gerund — so a new arm that reports a URL is working correctly and the mask is what settles it.

## Before claiming done

**The full bar runs in CI, on a draft PR.** `pnpm verify`, `pnpm e2e` and `pnpm e2e:ladle` overload the local machine, so the laptop runs targeted checks and CI runs the suite.

1. **Check locally, aimed at the change**: `pnpm typecheck` and `pnpm typecheck:packages`, `pnpm exec eslint <files>`, `pnpm exec vitest run <files>`, and `pnpm exec playwright test <spec>` when iterating on one UI behaviour (`-c playwright.ladle.config.ts` for a story spec under `packages/app/ladle-e2e/`). `pnpm verify:local` is the whole-repo static bar plus coverage at two workers.
2. **Open a draft PR at the first commit.** Branch off `main`, push, `gh pr create --draft`. CI runs on pull requests and pushes to `main` only, so a pushed branch with no PR is never checked. Asking for the work authorises pushing its branch and opening its draft PR; marking it ready, merging and pushing to `main` wait for the user.
3. **Done is `CI passed` green** — the gate job over every required job. Watch with `gh pr checks --watch`; when the gate is red, find the red job in that list and read it with `gh run view <run-id> --log-failed`. `main` is gated, so the baseline is green and a red job is yours until `git stash` or `git log` on the file shows otherwise.
4. **Report the evidence**: the local commands you ran and those you skipped, the `CI passed` result with each job behind it, and which CI job read what changed, or that none did. Claim success only for a result you watched arrive.
