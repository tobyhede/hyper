# AGENTS.md

Instructions for AI coding agents working in this repo.

A local prototype for **graph-native technical presentations**: Markdown Cards on spatial Layouts, connected into curated directed Graphs and presented by traversal. PostgreSQL is the live write model and the browser reaches it over HTTP; memory repositories are confined to isolated development and E2E runs. Placement is **authored, not computed** — a **Layout** owns an explicitly positioned subset of Space Cards and the Graphs authored across them, while the thing that arranges Cards is a **LayoutStrategy** (ADR 0014, ADR 0040, ADR 0041). A Space need not carry a Layout: an automatic strategy the app supplies renders it, and editing converts that into a Layout (ADR 0025). **No strategy is privileged** — elkjs is one member of a growing set (grid, sorts, tree, cluster), never the thing "layout" means. A Layout overview draws every Graph it owns at once, each as a coloured line of React Flow Edges, with the Active Graph emphasised. What draws the canvas is **one choice** over the computed Views and the authored Layouts, made in the Space Sidebar (ADR 0053). Cards in the graph show their title; **opening** a Card reads it in place, and **presenting** traverses the Active Graph (ADR 0006, ADR 0011, ADR 0024).

**Production UI work starts with `$shadcn-first-ui`, before any code.** Any change to a component, control, form, dialog, menu, popover, combobox, pane, card or application surface goes through that skill: search `@project/ui` first, then the shadcn registry, and hand-roll interactive behaviour only as the last option with the deviation recorded before it is written (ADR 0047, ADR 0050). A new production component or a new hand-rolled block in `packages/app/src/styles.css` — by class, or, where a rule names no class, by its leading attribute, id or element — fails `pnpm ui:catalog:check` until it is either built from `@project/ui` or recorded with its reason in `packages/app/stories/design-system-inventory.ts`, and every stable story owes both a Ladle and an application proof (ADR 0052). See `docs/agents/ui.md`.

**The repo is the only source of state.** Development and CI are the only environments — no production, no release, no users, and no document or byte that outlives a reset. Every database and generated artifact is **derived**: the codebase mints it from tracked seeds, fixtures, migrations and scripts. So a format change rolls schema, fixtures and tests forward in one change, and generated state that disagrees with the code generating it is a bug fixed at the source rather than a shape intake keeps reading (ADR 0054, ADR 0056).

## Decided — read these before the code

Accepted ADRs run ahead of the code, and standing workarounds constrain it. Read them before touching the areas they govern, and do not read the current code as the design. Each entry states what is built and what is not; most of this section is now built, so the build status to trust is the one written in the entry.

- **ADR 0061 — TypeScript 7 is the compiler and TypeScript 6 is a bridge — built.** `tsc` is TypeScript 7 and authoritative; the package name `typescript` deliberately resolves to the TypeScript 6 compatibility API that `typescript-eslint` and `prisma-next` consume, exposing `tsc6`. TypeScript 6 diagnostics are **not normative** — do not change source to satisfy it, do not add a TypeScript 6 typecheck, and do not "fix" the names so `typescript` means 7, which breaks typed linting. `pnpm typecheck:toolchain` asserts the arrangement and runs first in `verify`. The bridge's **removal condition is written in the ADR** — a stable release exposing the replacement compiler API, `typescript-eslint` and the other programmatic consumers supporting it, and `verify` green with `typescript` pointing at 7 — and the one known casualty is a `pnpm` patch on `@ladle/react` (`patches/`), whose bundled `.tsx` carries a `//@ts-ignore` that TypeScript 7's relocated diagnostic no longer sits under.

- **ADR 0062 — The narrowing assertions we have are the most we will have — built.** `@typescript-eslint/no-unsafe-type-assertion` is an error; the 79 sites already in the tree are recorded in the generated `eslint-suppressions.json` and **nothing new joins it**. It is a ratchet, not a backlog: `--prune-suppressions` runs in `verify`, the file only shrinks, and it is never hand-edited. `anti-slop/require-safety-comment-for-type-assertion` is unchanged and still applies to every surviving assertion — one rule demands a reason, the other caps the count. `tools/typing-fixtures/` is the executable evidence that both bite.

- **ADR 0041 — Graph is the first-public name for Route — built.** The vocabulary rename is complete: schemas, code, tests and fixtures use Graph, Graph navigation and Traversal history; Route and Walk survive only in historical records and qualified HTTP or graph-layout routing prose. Unqualified `Graph` and `GraphEdge` name the domain; strategy and render intermediates use `LayoutStrategyGraph` and `GraphRenderEdge`; the canvas is `SpaceCanvas`; and the former Graph-labelled Algorithmic View is Flow. ADR 0040's Layout-owned first-public document was a separate structural change, landed after it by `.scratch/first-public-aggregate/`.

Deeper build-status and gotcha detail for the ADRs that see the most churn now lives in the scoped `docs/agents/*.md` files listed under "Agent skills" below — read the one that covers the area before touching it.

## Commands

- Install: `pnpm install` (Node >= 24, pnpm 9).
- Dev: `pnpm dev` (app at http://localhost:5173) is the normal PostgreSQL-backed HTTP runtime and requires the configured database to be up. `pnpm dev:new` (port 5174) serves an initially empty memory repository; server-side startup creates the normal one-card **new space** once (ADR 0018). `pnpm dev:fixture` (port 5175) serves the tracked fixture through the same HTTP boundary over an isolated memory repository. Edits in either memory runtime survive browser reloads for that server's lifetime. None writes source files. **A dev server is usually already running on :5173, owned by the human in their own terminal — leave it alone.** Do NOT start, stop, restart, or kill it, and do not free the port (`kill`/`pkill vite`/`lsof -ti:5173 | xargs kill` etc.). Assume it's up and hot-reloading (Vite HMR + React Fast Refresh); your edits are already live in it. `strictPort: true`, so a second `pnpm dev` will fail rather than pick another port — don't run one. To verify changes, use `pnpm test`/`pnpm e2e` (Playwright starts its own servers) — never the human's dev server.
- Verify: `pnpm verify` runs `typecheck:toolchain` -> `typecheck` -> `typecheck:packages` -> `ui:catalog:check` -> `lint` -> `lint:anti-slop` -> `format:check` -> `test:coverage` (i.e. the ADR 0061 compiler assertion, then `tsc --noEmit` over the root program, then `pnpm -r typecheck` over each package's own config, `eslint . --max-warnings=0 --prune-suppressions`, `oxlint -c .oxlintrc.json` over the 15 vendored anti-slop rules, `prettier --check .`, `vitest run --coverage`). **`typecheck:toolchain` runs first** because a typecheck against the wrong compiler still passes, so proving which `tsc` ran has to happen before trusting what it said. **Both typechecks are needed**: the root program's `include` has `"*.config.ts"`, and `*` does not cross directory boundaries, so `packages/app/vite.config.ts`, `vite-space-http-plugin.ts` and `http-server-build.config.ts` are covered only by the per-package pass. Warnings fail the lint run; coverage thresholds are per-package and pinned at what already holds (`core`, `graph`, `persistence`), with no global threshold on purpose.
- Test: `pnpm test` (Vitest, `vitest` for watch). Unit + property tests (fast-check) live in `packages/*/test`.
- Mutation testing: `pnpm mutate:session` and `pnpm mutate:graph` run StrykerJS (`stryker.conf.mjs`) over one source file against a named oracle. **A deliberate local diagnostic, never a gate** — not in `verify`, not in CI, `thresholds.break` is `null`, and the tickets that introduced it forbid a threshold. `--mutate` and `--testFiles` are chosen as a *pair* per campaign, because the whole suite cannot run inside Stryker's sandbox (`test/unit`'s repo-meta test shells out to `git ls-files` and gets `[]`), so a campaign names the tests that are the oracle for the code it mutates — and nothing keeps that pairing honest but the reader. A score is evidence for a conversation about the oracle, not a number to move; the standing limits on what one means, including this runner's `static: true` false survivors, are in `.scratch/mutation-testing/engine.md`. Output goes to the gitignored `/reports/` and `/.stryker-tmp/`.
- E2E: `pnpm e2e` (Playwright, Chromium only) stays database-free and exercises HTTP; `pnpm e2e:fixture` selects only the tracked-fixture project. Every test owns a fresh Vite host, `E2eMemorySpaceRepository` and catalog; reloads and extra pages inside that test share them, while no revision leaks to another test. The `chromium` project imports the tracked fixture and `new-space` starts empty so database startup creates one card. Hosts use worker-scoped ports beginning at 5300, away from the human's 5173–5175. `pnpm e2e:postgres` is the separate opt-in one-test project proving a real PostgreSQL edit survives a fresh Vite host; run it only with PostgreSQL up and always stop PostgreSQL afterward. One-time first: `pnpm exec playwright install chromium`.
- Ladle E2E: `pnpm e2e:ladle` runs `playwright.ladle.config.ts` over `packages/app/ladle-e2e/`, against a `ladle serve --noWatch` catalogue it starts itself on port 61100. This is the behaviour half of ADR 0052's story evidence and it is **its own CI job**, run by neither `verify` nor `e2e` — so a component change that breaks a story is only caught here. The two Playwright configs share one flake policy (`retries: 2` and `failOnFlakyTests` under CI, `retries: 0` on a laptop); under `failOnFlakyTests` a retry that passes still fails the run, so the retries buy the trace and the reproduce-or-not signal rather than tolerance for a blip.
- Build: `pnpm build` (Vite build of the app).
- PostgreSQL integration: copy `.env.example` to the ignored `.env`, fill its password and matching `DATABASE_URL`, then run `pnpm postgres:up` followed by `pnpm test:integration:postgres`. Always finish with `pnpm postgres:down`; it keeps the named volume. `docker compose down --volumes` is the destructive reset. Normal `pnpm verify` and `pnpm e2e` do not require PostgreSQL.

## Package layout & boundaries

Seven `@project/*` workspace packages under `packages/`:

- `core` — domain model. Zod schemas (`schema.ts`, incl. `spaceFileSchema` — the space-file shape) + schema-derived `Card`/`Graph`/`GraphEdge`/`Layout` types (`types.ts`). No React, no framework deps.
- `graph` — pure graph logic over a `Space`: `loadSpace` (the one intake — parse, validate references including duplicate Edges within a Graph, index), the `Space` type and the one `SpaceLookup` it carries, Graph→render-handle/Edge derivation, traversal, and the `LayoutStrategy` contract (`LayoutStrategyGraph`, `buildLayoutStrategyGraph`, `gridStrategy`, `positionedStrategy`). Depends only on `core`. **Its index is curated and there is no `export *`**, and the unit of curation is the **module**: it names every function something outside the package calls, and every type exported by a module those calls reach — whether or not a consumer writes that type down today. `frontmatter` and `validate` are absent as whole modules: the first is how `card-file` reads a fence, the second runs inside `loadSpace`, which ADR 0010 makes the one intake. `SpaceReferenceError` is off the surface although `loadSpace`'s `SpaceError` union names it, while `CardFileError` in that same union is offered — reachability is not the test, and neither is depth. Adding a name is a deliberate act — `test/unit/graph-package-surface.test.ts` holds the index's declarations and the module they produce to one list, so a new export fails until it is listed there. A test of an internal helper imports it from its own module rather than through the index.
- `http` — browser-safe Fetch transport: the Hono `/api/spaces` route tree, request and response policy and the inferred `SpaceHttpApp` client contract. It *consumes* the narrow `SpaceResourceRepository` seam rather than declaring it — that lives in `persistence`, beside the `LoadedSpace` and `SpaceSummary` it is written in terms of. Depends only on `core`, `persistence`, Hono and runtime-neutral media parsing; imports no host, database, app or render implementation.
- `persistence` — browser-safe `SpaceBackend` and `SpaceSession` contracts, optimistic revision handling, commit coalescing, retry/conflict states, and the memory adapter. It also declares the **stored** side of the seam once, for both consumers: `SpaceResourceRepository` and `RepositoryCommitResult` (`src/repository.ts`), which `@project/http` takes and which `src/persistence/space-repository.ts` extends into `SpaceRepository` by adding `importSpaces` and `markExported`. The server seam is a superset, never a second declaration — a `Card`/`Graph` change cannot leave the two sides disagreeing, and the browser still cannot name import or export because the seam the Fetch application consumes does not declare them. Depends on `core` and `graph` so every committed snapshot passes the normal domain intake. It also owns **`createObservableState`**, the one observable-state seam behind `SpaceSession`, Navigation and SpaceAuthoring's own `getState`/`subscribe` interfaces: publication installs the next state synchronously, snapshots the subscriber set so a listener added mid-publication begins at the next one rather than part-way through the current, contains synchronous throws and thenable rejections, continues to the observers behind the failure, and reports through a sink `createNonThrowingReporter` has made incapable of interrupting the work it describes. Each collaborator keeps its own state and its own interface — only notification moved. **`app` therefore imports observable state from `persistence` although Navigation has nothing to do with persistence**; `.scratch/authoring-seams/issues/01-one-observable-state-module.md` records why that home was taken and what the alternatives cost.
- `react-flow-adapter` — the ONLY place React-Flow (`@xyflow/react`) and elkjs specifics live: projects a Space and its Layout-owned Graphs into RF nodes/edges, implements `LayoutStrategy` as `elkStrategy`, renders `CardNode`.
- `ui` — reusable, presentation-agnostic React components + shadcn-style primitives (Tailwind v4, CVA, Lucide, and Base UI controls including `Button`, `Select`, `Popover`, `Dialog`, `Menu` and `Combobox`), the `StatusPanel` operational-feedback module, plus the registry `Sidebar` the Space's command surface composes and the `AppShell` that frames it (ADR 0053). `Select` currently has no consumer: the three renderer selectors it drew were deleted with the horizontal toolbar. Depends on `core` only. **Choosing a Card has one component and one interaction model**: `CardSearchCombobox` is the shadcn/Base UI editable combobox used by Edge endpoints, keyboard Connect, new Alias Target and opened Alias Target. Its visible input displays the selected Card and becomes the search field in place; filtering, active item, keyboard selection, dismissal, empty state and the `combobox`/`listbox` pairing belong to the primitive. A refused choice stays visible as a disabled row carrying its reason. Do not add a second inline or trigger-and-popup picker implementation.
- `app` — wiring/composition: **`compose-app.ts` states what an opened Space is composed of, once** — `composeCore` answers the one working-space reader, `currentSpace`, the one renderer resolver and Navigation; `composeApp` adds Space Authoring, the render adapter and Edge Authoring, in the order they have to be built in. Every collaborator closes over that one reader, which is what gives them a single `Space` identity to share, and `createApp` is that call plus the component it builds. A test that wants collaborators calls one of the two rather than writing the chain out. Also: Navigation and Space Authoring, each keeping its own state behind `createObservableState` and read through one `useSyncExternalStore` (the Active Graph, Traversal history, the opened Card); the Zustand-backed **render adapter**, which owns the published projection, drag bookkeeping and the discriminated `none | card | edge` canvas selection; **Edge Authoring**, which owns the complete Edge interaction lifecycle over both of them; TanStack Router, Space loading, the canvas and its cameras, presenting chrome, hand-rolled CSS. Zustand is the render adapter's and nothing else's — Traversal history lives in Navigation. **`canvasProjection` is what the render adapter publishes**: `canvasProjection(space, renderer)` answers a `PendingCanvasProjection` — the `strategyGraph` it builds, the `colors` it derives from the Space, the `visibleGraphs` it reads off `renderer.subject.graphs`, and a `project(laidOut, interaction)` returning the React Flow nodes and edges. **A `ResolvedRenderer` supplies only a subject and a strategy**; none of those three is state it carries, and nothing should look for them on it. It is a pure module and deliberately not a hook — no store, no React, no DOM — so the whole derivation is tested in the node environment (`canvas-projection.test.ts`, and a property test for the handle-resolution invariant React Flow warns about as #008). The `LayoutStrategyGraph` it takes is **not nullable on purpose**: there is nothing worth projecting before a strategy resolves, and requiring one is what stops a caller publishing a projection whose every Card sits at the origin. The word *projection* names this bridging construct in `app` and the adapter and is deliberately absent from `CONTEXT.md`, whose render-layer section forbids inventing a domain term between React Flow's vocabulary and ours.

Hard rules — **all four are now enforced, not just documented**. Two layers, because neither catches what the other does: ESLint `no-restricted-imports` zones catch package specifiers and relative escapes (`../../*`), and each package's narrowed tsconfig `paths` makes an illegal alias unresolvable. `rootDir` is set on `core` alone — anywhere else it rejects the legitimate `@project/*` import too, since the aliased file resolves outside the package, which is why the relative-escape half is a lint rule rather than a compiler setting. Before this, `core` could import `@project/ui`, cycle back into `@project/graph`, and reach `../../app/src/store` with typecheck and lint both green.

- Domain logic stays out of React (keep it in `core`/`graph`).
- React-Flow / elkjs specifics stay in `react-flow-adapter`. Precisely: **`core`, `graph`, `persistence` and `ui` must not import them**, which is what `no-restricted-imports` enforces. `app` does import `@xyflow/react` and legitimately so, being the composition layer — the older "nothing else imports them" was already false.
- Reusable UI goes in `ui`; app-specific glue goes in `app`.
- A module bundled into a Vite config (`vite.config.ts`, `http-server-build.config.ts`) imports `@project/*` by **relative path only** — a bare specifier is externalized and hands Node the workspace TypeScript, and the dev server then will not start at all.

## Conventions & gotchas

- **Strict TypeScript everywhere**, incl. `noUncheckedIndexedAccess`, `noUnusedLocals/Parameters`, `noImplicitOverride`.
- **`package.json`'s TypeScript entries look wrong and are not (ADR 0061).** `@typescript/typescript7` is TypeScript 7 and owns the `tsc` binary; the package name `typescript` resolves to `@typescript/typescript6`, which owns `tsc6` and the `createProgram` API `typescript-eslint` and `prisma-next` need. `tsc` is the only type-checking truth here — a TypeScript 6 diagnostic is not a defect to fix, and `tsc6` is a migration aid, not a gate. Do not unify the two names. `pnpm typecheck:toolchain` fails the moment either half stops holding, and the ADR states the condition under which the bridge is removed.
- **`eslint-suppressions.json` is a ceiling, not a backlog (ADR 0062).** It records the narrowing assertions that predate the rule, and it is generated — never hand-edited, never added to. `--prune-suppressions` runs in `verify`, so it only shrinks, and it shrinks as files are edited for other reasons rather than as scheduled work. A new assertion fails lint even in a listed file; adding one to a file with suppressed sites reports every assertion in that file, because a count-based baseline cannot tell which is new.
- **`verbatimModuleSyntax` + ESLint `consistent-type-imports` are on** — use `import type` for type-only imports or lint/typecheck fails.
- **Cross-package imports** use the `@project/*` path aliases: declared in `tsconfig.base.json`, mirrored in `vitest.config.ts` `resolve.alias`, and **narrowed per package** in each `packages/*/tsconfig.json` so a package can only resolve what it may legally depend on. Vite needs no alias at all — it resolves through the workspace `exports`, and the third copy that used to sit in `packages/app/vite.config.ts` is gone (removing it built an identical bundle). Vitest's *is* load-bearing: the root package declares no `@project/*` deps, so there is no symlink to resolve through. Two lists to keep in sync, plus the package's own narrowed one.
- **Relative imports inside a package are EXTENSIONLESS** (`./foo`, not `./foo.ts`).
- **Use a functional core and imperative shell for cross-module coordination.** Compute and validate the complete next state in a private pure core before producing side effects; a thin imperative shell then updates collaborators in an order that preserves valid intermediate states. Expose the coordination as one operation rather than returning a plan for callers to execute. Keep framework and store events outside the seam, depend on existing module interfaces, and do not manufacture single-adapter ports for deterministic private helpers. An edit event is a notification, not state transfer: each editor first installs its authoritative completed state and only then emits the notification; the coordinator derives the next Space from the current state owned by its collaborators rather than from state carried by the event.
- **Inject nondeterminism once when composing a module, not through each domain operation, and never by mocking the ambient generator (ADR 0016).** A module that mints identities, reads time or otherwise depends on a nondeterministic in-process function receives that function at composition so tests can supply a deterministic one; its operational interface then stays in domain language and does not repeat the dependency on every call. There are **two such seams in the authoring path, and that is not a duplication**: `createSpaceAuthoring` takes `newId` exactly as it takes `reportObserverError` — **required, with no default**, so no collaborator can quietly fall back to `newUuid` behind the composition's back — and mints the Card and Layout ids of a completed Edit from it; a converted Graph's identity is minted inside ADR 0045's conversion boundary, which the *resolver* closes over, so `createRendererResolver({ newGraphId })` takes that one. **`packages/app/src/compose-app.ts` is where both are supplied**: `composeCore` composes the one resolver and hands it to App rendering, Navigation and Space Authoring, and `composeApp` passes `newId` on explicitly, so each identity has one visible source. `createApp` is that call plus the component it builds. (The earlier note that a minter must not go on renderer resolution was written when `resolveView` was a free function seven call sites reached; a composed resolver is where the argument said the dependency belongs.) **Don't answer a test's need for a known id with `vi.spyOn(crypto, 'randomUUID')`** — ADR 0016 rejected that when `loadSpace` faced it and the grounds are general: a constant collides across a property test's cases so it needs a counter, at which point a generator exists anyway; `randomUUID` is an unseedable CSPRNG, so controlling it means owning it; and the mock stops working in silence the day the implementation moves to v7 and reads the clock as well as the entropy pool. The seventeen spies this replaced also hid a real defect — one of them named two ids for an Edit that mints three, so a Layout quietly took an id from the real generator. Tests name the ids they assert on through `packages/app/test/minting.ts`, and compose a deterministic resolver for the Graph. Do not hide nondeterminism behind global mocking, and do not manufacture a port or adapter seam when the dependency has one in-process implementation. Deterministic rules stay uninjected — `titles.ts` mints `Card N`, `Layout N` and `Graph N` through three named operations with the `<Prefix> N` arithmetic private, because there is nothing there a test would want to replace.
- **`path` means a file path only.** The document and the implementation agree on `graphs`/`activeGraph` — the sentence here used to contrast a planned spelling with a built one, and the rename closed that gap. Remaining `path` identifiers are filesystem paths, TanStack Router URL paths, or React Flow's own SVG `edge-path` class — don't “fix” those.
- **`CONTEXT.md` avoids "arrangement" three times over (Placement, Layout strategy, Algorithmic View), and the code now honours that.** The one deliberate survivor is `packages/graph/src/layout.ts`, which quotes the avoid-list in its own doc comment. The word was load-bearing twice and is gone from both: the `AuthoringRefusal` code is `placement-pending` (ADR 0057 makes a refusal code a stable domain identity), and `CanvasContent`'s third kind is `'cards'`, produced by `canvasContent`'s `hasCardsOnCanvas`. **`'cards'` is not a synonym for Placement** — it means "Cards are mounted on the canvas", which stays true while a *replacement* placement is still `'pending'`, because the editor keeps drawing the previous one rather than blanking mid-recompute. Don't "fix" it to a placement-flavoured name. The verb still reads normally — a strategy *arranges* Cards, as `CONTEXT.md` itself says; it is the noun that names nothing.

## Before claiming done

- Run `pnpm verify` and report the real output.
- For any UI/graph change, also run `pnpm e2e` and report it.
- For any change to a component with a story, also run `pnpm e2e:ladle` and report it. It is not part of `verify` and not part of `e2e`, so nothing else runs it for you, and it is a CI job — a story left behind by a component change fails there.
- Do not assert success without having run the commands.
- CI (`.github/workflows/ci.yml`) runs all four jobs on every push and PR, with `--frozen-lockfile`. It is a backstop, not a substitute — a red CI after the fact is slower than a green run before the commit.

## Agent skills

### Workflow

How work moves from a question to committed code: the grilling loop, when a decision earns an ADR, the rename rule, the verification bar. See `docs/agents/workflow.md`. The skills themselves are **tracked**: the files under `.agents/skills/` (where Codex looks), symlinked from `.claude/skills/` (where Claude Code looks), pinned by `skills-lock.json`. Both harnesses' paths are tracked deliberately — tracking one fixes only one. `workflow.md` remains the prose copy of the process, because a vendored third-party skill set can be updated out from under the repo and the loop is ours either way.

### Editing & persistence

`SpaceBackend`, `SpaceSession`, Space Authoring's completed-edit lifecycle (`completed`/`unchanged`/`refused`), and the Layout/Graph/View aggregate model. Read before touching `packages/persistence`, `packages/graph`, `space-authoring.ts`, `migrations/**`, or `src/prisma/**`. See `docs/agents/editing-and-persistence.md`.

### Canvas & rendering

React Flow, ELK, handle geometry, the camera, and Edge Authoring. Read before touching `packages/react-flow-adapter`, canvas/camera modules, or `edge-authoring.ts`. See `docs/agents/rendering.md`.

Wire-level request/response rules and the Node host requirements for the Fetch-native `@project/http` package. Read before touching `packages/http`. See `docs/agents/http.md`.

### UI foundation

UI components, operational feedback, shadcn, Base UI, Lucide, and the Escape/commit and focus conventions that follow from them. Read before touching `packages/ui` or a pane/menu/combobox/feedback surface. See `docs/agents/ui.md`.
